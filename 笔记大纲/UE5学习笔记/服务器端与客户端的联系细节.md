# 服务器端与客户端的联系细节

> 基于 UE5.3 学习视频第3章第5节字幕整理

---

## 一、多人游戏基本架构

### 1.1 服务器（Server）
- 游戏中**独立运行**的实例
- 是游戏的**权威版本**（Authoritative Version）
- 所有重要事务都在服务器上处理

### 1.2 客户端（Client）
- 每个玩家各自运行的游戏版本
- 客户端之间通过服务器通信

---

## 二、两种服务器模型

| 模型 | 特点 |
|------|------|
| **专用服务器（Dedicated Server）** | 无人类玩家，不向屏幕渲染，只运行游戏模拟 |
| **监听服务器（Listen Server）** | 一个人类玩家同时作为主机和服务器，主机无延迟（无需网络传输给自己） |

---

## 三、各类在服务器与客户端上的分布

```
                    服务器        客户端0       客户端1       客户端2
──────────────────────────────────────────────────────────────────
GameMode             ✅            ❌            ❌            ❌
PlayerController     ✅ (全部)     ✅ (仅自己)   ✅ (仅自己)   ✅ (仅自己)
PlayerState          ✅ (全部)     ✅ (全部)     ✅ (全部)     ✅ (全部)
Pawn                 ✅ (全部)     ✅ (全部)     ✅ (全部)     ✅ (全部)
HUD                  ❌*           ✅ (仅自己)   ✅ (仅自己)   ✅ (仅自己)
```

> *专用服务器无 HUD；监听服务器只有主机玩家的 HUD

### 3.1 GameMode（游戏模式）
- **仅存在于服务器**
- 客户端访问会得到**空指针**
- 负责：游戏规则、玩家生成、游戏重启等**重要事务**

### 3.2 PlayerController（玩家控制器）
- 服务器有**所有玩家**的 PlayerController
- 每个客户端**只有自己**的 PlayerController
- 客户端0看不到客户端1的 PlayerController

### 3.3 PlayerState（玩家状态）
- 服务器有所有玩家的 PlayerState
- **每个客户端也有所有玩家**的 PlayerState
- 与 Pawn 类似：所有机器都有所有 Pawn 的副本（否则你看不到其他玩家移动）

### 3.4 HUD
- **仅存在于各自客户端**
- 客户端0无法访问客户端1的 HUD

## 四、网络复制（Replication）

### 4.1 什么是复制
- 服务器上的数据变化通过网络更新发送给所有客户端
- 客户端据此更新本地的变量值

### 4.2 网络更新频率（Net Update Frequency）
- 例如 PlayerState 设为 **100次/秒**
- 意味着服务器每秒最多向客户端发送 100 次更新

### 4.3 复制变量（Replicated Variable）
- 标记为复制的变量，服务器值变化时会同步到所有客户端
- ⚠️ **复制是单向的：只能从服务器 → 客户端**
- 客户端**不应**直接修改复制变量，否则：
  - 服务器不知道变化
  - 其他客户端不知道变化
  - 该客户端变量与服务器**不同步**，被视为错误

### 4.4 客户端如何向服务器发送数据？
- 通过 **RPC（远程过程调用，Remote Procedure Call）**
- 使用复制函数（Replicated Functions）实现
- 例如：键盘/鼠标/手柄输入需要通过 RPC 传递给服务器

## 五、GAS 与多人游戏

- GAS 会**在后台处理大量多人游戏的工作**
- 本课程中实现的所有游戏机制**都能在多人游戏中运行**，也支持单人模式
- 不需要深入学习多人游戏的所有细节，GAS 已经帮我们封装好了

---

## 六、关键要点总结

| 要点 | 说明 |
|------|------|
| 服务器是权威 | 重要事务只在服务器执行 |
| 复制单向 | 服务器 → 客户端，不能反向 |
| 客户端通信 | 通过 RPC 向服务器发送数据 |
| GameMode | 仅服务器端 |
| PlayerState | 服务器+所有客户端都有 |
| PlayerController | 服务器有全部，客户端仅有自己的 |
| GAS 的优势 | 自动处理大量多人游戏底层逻辑 |
