## 一、整体目标：让 UI 响应真实数据

上一阶段我们搭建了 HUD → WidgetController → Widget 的骨架，但 WidgetController 只是持有四个关键变量，还没有真正从 AttributeSet 读取数据并广播给 Widget。

**本次提交的核心目标**：

```
AttributeSet (Model) ──属性变化──▶ WidgetController (Controller) ──委托广播──▶ Widget (View)
                                       │                                      │
                                       ├─ BroadcastInitialValues()            ├─ OnHealthChange 绑定
                                       ├─ BindCallbacksToDependencies()       ├─ OnMaxHealthChange 绑定
                                       ├─ HealthChanged() 回调                └─ SetProgressBarPercent()
                                       └─ MaxHealthChanged() 回调
```

**三个关键问题**：

| 问题                                   | 解决方案                                                  |
| ------------------------------------ | ----------------------------------------------------- |
| ① 如何获取真实的属性值（而非硬编码 100）？             | `CastChecked<UAuraAttributeSet>` → `GetHealth()`      |
| ② 如何让 Widget 在属性变化时自动更新？             | GAS 委托 `GetGameplayAttributeValueChangeDelegate` + 回调 |
| ③ 如何让 WidgetController 广播数据给 Widget？ | Dynamic Multicast Delegate + `BlueprintAssignable`    |

## 二、BroadcastInitialValues — 广播初始值（5.7 核心）

<a id="section-5"></a>
### 2.1 为什么需要虚函数

不同的 WidgetController 子类需要广播不同的初始值：

| WidgetController                     | 需要广播的初始值                      |
| ------------------------------------ | ----------------------------- |
| `UOverlayWidgetController`           | Health、MaxHealth、Mana、MaxMana |
| `UAttributeMenuWidgetController`（未来） | 所有属性值                         |
| `USpellMenuWidgetController`（未来）     | 技能相关信息                        |

**设计模式**：基类定义虚函数接口，子类各自实现。

<a id="section-6"></a>
### 2.2 基类声明 + 子类覆写

```cpp
// ========== 基类：AuraWidgetController.h ==========
public:
    virtual void BroadcastInitialValues();   // ★ 虚函数，基类为空实现
    virtual void BindCallbacksToDependencies();

// ========== 基类：AuraWidgetController.cpp ==========
void UAuraWidgetController::BroadcastInitialValues()
{
    // 空实现，由子类覆写
}

// ========== 子类：OverlayWidgetController.h ==========
public:
    virtual void BroadcastInitialValues() override;  // ★ 覆写
    virtual void BindCallbacksToDependencies() override;
```

<a id="section-7"></a>
### 2.3 CastChecked 安全转换

```cpp
// 文件：OverlayWidgetController.cpp

void UOverlayWidgetController::BroadcastInitialValues()
{
    // ★ 将基类 UAttributeSet* 转换为子类 UAuraAttributeSet*
    const UAuraAttributeSet* AuraAttributeSet =
        CastChecked<UAuraAttributeSet>(AttributeSet);

    // ★ 广播真实的属性值（而非硬编码）
    OnHealthChange.Broadcast(AuraAttributeSet->GetHealth());
    OnMaxHealthChange.Broadcast(AuraAttributeSet->GetMaxHealth());
}
```

**为什么用 `CastChecked` 而不是 `Cast`？**

| 方式               | 行为                | 适用场景        |
| ---------------- | ----------------- | ----------- |
| `Cast<T>`        | 转换失败返回 `nullptr`  | 类型不确定时      |
| `CastChecked<T>` | 转换失败触发 `check` 崩溃 | 类型**确定正确**时 |

> 这里 `AttributeSet` 一定是 `UAuraAttributeSet`（由 GameMode 配置保证），所以用 `CastChecked` 更合适——如果失败说明配置错误，应该立即暴露问题。

<a id="section-8"></a>
### 2.4 InitOverlay 中的调用时机

```cpp
// 文件：AuraHUD.cpp — InitOverlay()

// ① 创建 Widget
// ② 创建 WidgetController
OverlayWidget->SetWidgetController(WidgetController);  // ③ 绑定 Controller 到 Widget
//                                                      ↑ 此时 Widget 蓝图中的
//                                                        "Event WidgetController Set" 已触发
//                                                        Widget 已完成委托绑定

WidgetController->BroadcastInitialValues();  // ④ ★ 在 Widget 绑定完成后才广播
//                                               否则 Widget 还没绑定委托，收不到广播

Widget->AddToViewport();                     // ⑤ 添加到视口
```

> 🔑 **关键时序**：`BroadcastInitialValues` 必须在 `SetWidgetController` **之后**调用。因为 `SetWidgetController` 会触发 Widget 蓝图中的 `Event WidgetController Set`，Widget 在该事件中绑定委托。如果先广播再绑定，Widget 收不到初始值。

## 三、动态多播委托 — 数据广播通道（5.7 核心）

<a id="section-10"></a>
### 3.1 为什么选择 Dynamic Multicast

| 委托类型                                     | 蓝图支持 | 多播  | 适用场景                |
| ---------------------------------------- | ---- | --- | ------------------- |
| `DECLARE_DELEGATE`                       | ❌    | 单播  | C++ 内部回调            |
| `DECLARE_MULTICAST_DELEGATE`             | ❌    | 多播  | C++ 内部广播            |
| `DECLARE_DYNAMIC_DELEGATE`               | ✅    | 单播  | 蓝图单个回调              |
| **`DECLARE_DYNAMIC_MULTICAST_DELEGATE`** | ✅    | 多播  | ★ **蓝图多 Widget 绑定** |

选择 Dynamic Multicast 的原因：

- **Dynamic**：可以在蓝图中绑定事件（`BlueprintAssignable`）
- **Multicast**：多个 Widget 可以同时绑定同一个委托（如 HealthGlobe 和 ManaGlobe 都绑定到同一个 WidgetController）

<a id="section-11"></a>
### 3.2 委托声明语法详解

```cpp
// 文件：OverlayWidgetController.h

#include <GameplayEffect.h>  // ★ 需要此头文件才能使用 FOnAttributeChangeData

// ★ 声明委托类型（末尾加 Signature 表示这是类型，不是实例）
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(
    FOnHealthChangeSignature,   // 委托类型名
    float,                      // 参数类型
    NewHealth);                 // 参数名

DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(
    FOnMaxHealthChangeSignature,
    float,
    NewMaxHealth);
```

**命名约定**：

| 名称                         | 含义                     |
| -------------------------- | ---------------------- |
| `FOnHealthChangeSignature` | 委托**类型**（末尾 Signature） |
| `OnHealthChange`           | 委托**实例**（成员变量）         |

<a id="section-12"></a>
### 3.3 BlueprintAssignable 的意义

```cpp
UPROPERTY(BlueprintAssignable, Category="GAS|Attributes")
FOnHealthChangeSignature OnHealthChange;

UPROPERTY(BlueprintAssignable, Category="GAS|Attributes")
FOnMaxHealthChangeSignature OnMaxHealthChange;
```

`BlueprintAssignable` 使得在 Widget 蓝图中可以这样操作：

```
WidgetController → Cast to BP_OverlayWidgetController
    → OnHealthChange ← 拖出 → Bind Event to OnHealthChanged
        → 当 C++ 调用 OnHealthChange.Broadcast(75.f) 时
            → 蓝图中的 OnHealthChanged 事件被触发
```

## 四、BindCallbacksToDependencies — 属性变化监听（5.8 核心）

<a id="section-14"></a>
### 4.1 GAS 的属性变化委托机制

GAS（Gameplay Ability System）提供了监听属性变化的机制：

```cpp
// ASC 提供的方法
FOnGameplayAttributeValueChange& GetGameplayAttributeValueChangeDelegate(
    FGameplayAttribute Attribute);
```

- 传入一个 `FGameplayAttribute`（如 `GetHealthAttribute()`）
- 返回一个委托引用
- 当该属性值发生变化时，委托会自动广播

<a id="section-15"></a>
### 4.2 AddUObject vs AddDynamic

```cpp
// 文件：OverlayWidgetController.cpp — BindCallbacksToDependencies()

void UOverlayWidgetController::BindCallbacksToDependencies()
{
    const UAuraAttributeSet* AuraAttributeSet =
        CastChecked<UAuraAttributeSet>(AttributeSet);

    // ★ 绑定 Health 属性变化回调
    AbilitySystemComponent
        ->GetGameplayAttributeValueChangeDelegate(
            AuraAttributeSet->GetHealthAttribute())   // 指定监听哪个属性
        .AddUObject(this,                              // ★ 使用 AddUObject
            &UOverlayWidgetController::HealthChanged); // 回调函数指针

    // ★ 绑定 MaxHealth 属性变化回调
    AbilitySystemComponent
        ->GetGameplayAttributeValueChangeDelegate(
            AuraAttributeSet->GetMaxHealthAttribute())
        .AddUObject(this,
            &UOverlayWidgetController::MaxHealthChanged);
}
```

**为什么用 `AddUObject` 而不是 `AddDynamic`？**

| 方法           | 适用委托类型                | 说明                                              |
| ------------ | --------------------- | ----------------------------------------------- |
| `AddDynamic` | Dynamic Delegate      | 用于我们自己声明的 `DECLARE_DYNAMIC_MULTICAST_DELEGATE`  |
| `AddUObject` | Non-Dynamic Multicast | GAS 的 `FOnGameplayAttributeValueChange` 是普通多播委托 |

> GAS 的 `GetGameplayAttributeValueChangeDelegate` 返回的是 `FOnGameplayAttributeValueChange&`，这是一个**非动态**多播委托，所以必须用 `AddUObject` 绑定。

<a id="section-16"></a>
### 4.3 回调函数签名要求

```cpp
// 文件：OverlayWidgetController.h

protected:
    // ★ 签名必须与 FOnGameplayAttributeValueChange 匹配
    void HealthChanged(const FOnAttributeChangeData& Data) const;
    void MaxHealthChanged(const FOnAttributeChangeData& Data) const;
```

```cpp
// 文件：OverlayWidgetController.cpp

void UOverlayWidgetController::HealthChanged(const FOnAttributeChangeData& Data) const
{
    // ★ Data.NewValue 是属性变化后的新值
    OnHealthChange.Broadcast(Data.NewValue);
}

void UOverlayWidgetController::MaxHealthChanged(const FOnAttributeChangeData& Data) const
{
    OnMaxHealthChange.Broadcast(Data.NewValue);
}
```

**`FOnAttributeChangeData` 结构体包含**：

| 字段          | 类型                                | 说明         |
| ----------- | --------------------------------- | ---------- |
| `NewValue`  | `float`                           | 属性变化后的新值   |
| `OldValue`  | `float`                           | 属性变化前的旧值   |
| `GEModData` | `FGameplayEffectModCallbackData*` | GE 修改的详细数据 |

> 💡 函数标记为 `const`，因为这些回调只读取数据并广播，不修改 WidgetController 自身的状态。

<a id="section-17"></a>
### 4.4 完整绑定流程

```
GetOverlayWidgetController(WCParams)
    │
    ├─ NewObject<UOverlayWidgetController>
    │
    ├─ SetWidgetControllerParams(WCParams)   // 设置 PC/PS/ASC/AS
    │
    └─ BindCallbacksToDependencies()         // ★ 绑定 ASC 属性变化回调
        │
        ├─ ASC->GetGameplayAttributeValueChangeDelegate(HealthAttribute)
        │       .AddUObject(this, &HealthChanged)
        │   → 此后每当 Health 属性变化，自动调用 HealthChanged()
        │
        └─ ASC->GetGameplayAttributeValueChangeDelegate(MaxHealthAttribute)
                .AddUObject(this, &MaxHealthChanged)
            → 此后每当 MaxHealth 属性变化，自动调用 MaxHealthChanged()
```

## 五、调用链路全景图

<a id="section-19"></a>
### 5.1 初始化阶段

```
游戏启动
  └─ AAuraCharacter::InitAbilityActorInfo()
      └─ AuraHUD->InitOverlay(PC, PS, ASC, AS)
          │
          ├─ ① CreateWidget → OverlayWidget
          │
          ├─ ② GetOverlayWidgetController(WCParams)
          │       ├─ NewObject<UOverlayWidgetController>
          │       ├─ SetWidgetControllerParams  // 设置四个关键变量
          │       └─ BindCallbacksToDependencies()  // ★ 绑定 ASC 监听
          │           ├─ ASC 监听 Health 变化 → HealthChanged()
          │           └─ ASC 监听 MaxHealth 变化 → MaxHealthChanged()
          │
          ├─ ③ OverlayWidget->SetWidgetController(WidgetController)
          │       └─ 触发 Widget 蓝图 "Event WidgetController Set"
          │           ├─ 传播 Controller 给 HealthGlobe、ManaGlobe
          │           └─ 绑定 OnHealthChange、OnMaxHealthChange 委托
          │
          ├─ ④ WidgetController->BroadcastInitialValues()

          │
          └─ ⑤ Widget->AddToViewport()
```

## 六、蓝图侧配置（5.7 实操）

<a id="section-22"></a>
### 6.1 创建 BP_OverlayWidgetController

1. 在 `Content/BluePrint/UI/WidgetController/` 下创建蓝图
2. 父类选择 `OverlayWidgetController`
3. 命名为 `BP_OverlayWidgetController`
4. 在 `BP_AuraHUD` 中将 `OverlayWidgetControllerClass` 设为 `BP_OverlayWidgetController`

> 💡 使用蓝图子类而非直接使用 C++ 类的好处：未来可在蓝图中为 WidgetController 添加配置数据。

**为什么需要 `BlueprintType` + `Blueprintable`？**

```cpp
// OverlayWidgetController.h
UCLASS(BlueprintType, Blueprintable)  // ★ 必须加这两个
class AURA_API UOverlayWidgetController : public UAuraWidgetController
```

| 说明符             | 作用                           |
| --------------- | ---------------------------- |
| `BlueprintType` | 可在蓝图中作为**变量类型**使用（如 Cast To） |
| `Blueprintable` | 可基于此类创建**蓝图子类**              |

<a id="section-23"></a>
### 6.2 WBP_Overlay 中传播 WidgetController

在 `WBP_Overlay` 的 `Event WidgetController Set` 中：

```
Event WidgetController Set
  └─ Sequence
      ├─ Then 0: 将 WidgetController 传给 HealthGlobe
      │     └─ HealthGlobe->SetWidgetController(WidgetController)
      │
      └─ Then 1: 将 WidgetController 传给 ManaGlobe
            └─ ManaGlobe->SetWidgetController(WidgetController)
```

> 🔑 **连锁反应**：当 `WBP_Overlay` 的 `SetWidgetController` 被调用时，它内部会触发 `Event WidgetController Set`，该事件再将 Controller 传递给子 Widget。子 Widget 收到后也会触发各自的 `Event WidgetController Set`。

<a id="section-24"></a>
### 6.3 WBP_HealthGlobe 中绑定委托

在 `WBP_HealthGlobe` 的 `Event WidgetController Set` 中：

```
Event WidgetController Set
  └─ Sequence
      ├─ Then 0: 将 WidgetController 提升为变量
      │     └─ Cast To BP_OverlayWidgetController → 存为局部变量
      │
      ├─ Then 1: 绑定 OnHealthChange
      │     └─ BP_OverlayWidgetController->OnHealthChange
      │           └─ Bind Event → 设置 Health 变量
      │               └─ SetProgressBarPercent(Health / MaxHealth)
      │
      └─ Then 2: 绑定 OnMaxHealthChange
            └─ BP_OverlayWidgetController->OnMaxHealthChange
                  └─ Bind Event → 设置 MaxHealth 变量
                      └─ SetProgressBarPercent(Health / MaxHealth)
```

<a id="section-25"></a>
### 6.4 GlobeProgressBar 基类添加 SetProgressBarPercent

在 `WBP_GlobeProgressBar`（父类）中添加函数：

```
Function: SetProgressBarPercent
  Input: float Percent
  └─ ProgressBar_Globe->SetPercent(Percent)
```

这样所有子类（HealthGlobe、ManaGlobe）都可以调用此函数。

> 💡 **安全除法**：在蓝图中使用 `SafeDivide(Health, MaxHealth)` 而非普通除法。当 MaxHealth 为 0 时返回 0，避免除零错误。

## 九、知识点总结

| 序号  | 知识点                               | 说明                                                                          |
| --- | --------------------------------- | --------------------------------------------------------------------------- |
| 1   | **虚函数模式**                         | 基类定义 `virtual void BroadcastInitialValues()`，子类覆写各自广播不同数据                   |
| 2   | **CastChecked**                   | 类型确定正确的转换，失败时触发断言崩溃（比 `Cast` 更严格）                                           |
| 3   | **Dynamic Multicast Delegate**    | `DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam` — 蓝图可绑定 + 多播                  |
| 4   | **BlueprintAssignable**           | UPROPERTY 说明符，使委托可在蓝图中绑定事件                                                  |
| 5   | **BlueprintType + Blueprintable** | 前者让类可作为蓝图变量类型，后者允许创建蓝图子类                                                    |
| 6   | **GAS 属性变化委托**                    | `ASC->GetGameplayAttributeValueChangeDelegate(Attribute)` 返回委托引用            |
| 7   | **AddUObject vs AddDynamic**      | GAS 委托是非动态的，必须用 `AddUObject`；自己声明的 Dynamic 委托用 `AddDynamic`                 |
| 8   | **FOnAttributeChangeData**        | 包含 `NewValue`、`OldValue`、`GEModData`                                        |
| 9   | **广播时序**                          | `SetWidgetController` → 蓝图绑定委托 → `BroadcastInitialValues` → `AddToViewport` |
| 10  | **连锁反应**                          | 父 Widget 设置子 Widget 的 Controller 会触发子 Widget 的 `Event WidgetController Set` |
| 11  | **安全除法**                          | 蓝图中用 `SafeDivide` 避免除零                                                      |
| 12  | **单向依赖**                          | ASC 不知道 WidgetController，WidgetController 不知道 Widget，完全解耦                   |

---

> 📝 **架构小结**：本次提交实现了 MVC 架构的**数据流通**。`BroadcastInitialValues` 负责初始数据同步，`BindCallbacksToDependencies` 负责运行时数据变化监听。GAS 的属性变化委托作为"数据源"，WidgetController 的自定义委托作为"广播通道"，Widget 蓝图的委托绑定作为"数据接收端"。三层之间通过委托实现单向依赖，完全解耦。
