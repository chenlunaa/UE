## 一、整体目标：精细化管理 GameplayEffect 的生命周期

上一阶段我们实现了三种 GameplayEffect 的基本应用（即时、持续、无限），但存在以下问题：

```
❌ 问题：
  1. 无限效果无法移除 → 角色离开火区域后仍然扣血
  2. 属性值没有上下限 → 血量可以超过最大值或变为负数
  3. 效果应用策略硬编码 → 无法灵活选择在 Overlap 还是 EndOverlap 时应用
  4. 效果幅度固定 → 无法根据等级动态调整
```

**本次提交的核心目标**：

```
✅ 解决：
  1. 引入策略枚举，灵活控制效果的"何时应用"和"何时移除"
  2. 使用 TMap 存储 ActiveEffectHandle，实现无限效果的按需移除
  3. 通过 PreAttributeChange 钳制属性值，防止越界
  4. 通过 PostGameplayEffectExecute + FEffectProperties 收集效果执行的完整上下文
  5. 引入曲线表（Curve Table），实现按等级缩放效果幅度
```

## 二、EffectApplicationPolicy 与 EffectRemovalPolicy 枚举（6.8 核心）

<a id="section-5"></a>
### 2.1 为什么需要策略枚举

不同效果有不同的触发时机需求：

| 效果类型  | 触发时机  | 移除时机     |
| ----- | ----- | -------- |
| 火区域伤害 | 进入时开始 | 离开时停止    |
| 治疗泉水  | 进入时开始 | 离开时停止    |
| 陷阱伤害  | 离开时触发 | —        |
| 一次性药水 | 重叠时触发 | 自动（即时效果） |

通过枚举，蓝图设计师可以在不修改 C++ 的情况下自由组合这些策略。

<a id="section-6"></a>
### 2.2 三种应用策略

```cpp
// AuraEffectActor.h
UENUM(BlueprintType)
enum class EEffectApplicationPolicy : uint8
{
    ApplyOnOverlap,      // 重叠时应用
    ApplyOnEndOverlap,   // 结束重叠时应用
    DoNotApply           // 不应用
};
```

<a id="section-7"></a>
### 2.3 三种移除策略

```cpp
UENUM(BlueprintType)
enum class EEffectRemovalPolicy : uint8
{
    RemoveOnOverlap,       // 重叠时移除
    RemoveOnEndOverlap,    // 结束重叠时移除
    DoNotRemove            // 不移除
};
```

<a id="section-8"></a>
### 2.4 OnOverlap / OnEndOverlap 统一入口

```cpp
// AuraEffectActor.h — 每种效果类型都有独立的策略变量
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Applied Effects")
EEffectApplicationPolicy InstantEffectApplicationPolicy = EEffectApplicationPolicy::DoNotApply;

UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Applied Effects")
EEffectApplicationPolicy DurationEffectApplicationPolicy = EEffectApplicationPolicy::DoNotApply;

UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Applied Effects")
EEffectApplicationPolicy InfiniteEffectApplicationPolicy = EEffectApplicationPolicy::DoNotApply;

UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Applied Effects")
EEffectRemovalPolicy InfiniteEffectRemovalPolicy = EEffectRemovalPolicy::RemoveOnEndOverlap;
```

**OnOverlap 的处理逻辑**：

```cpp
void AAuraEffectActor::OnOverlap(AActor* TargetActor)
{
    // 检查即时效果的策略
    if (InstantEffectApplicationPolicy == EEffectApplicationPolicy::ApplyOnOverlap)
        ApplyEffectToTarget(TargetActor, InstantGameplayEffectClass);

    // 检查持续时间效果的策略
    if (DurationEffectApplicationPolicy == EEffectApplicationPolicy::ApplyOnOverlap)
        ApplyEffectToTarget(TargetActor, DurationGameplayEffectClass);

    // 检查无限效果的策略
    if (InfiniteEffectApplicationPolicy == EEffectApplicationPolicy::ApplyOnOverlap)
        ApplyEffectToTarget(TargetActor, InfiniteGameplayEffectClass);
}
```

**OnEndOverlap 的处理逻辑**（多了移除逻辑）：

所有的效果运用都要获得目标的ASC来进行

```cpp
void AAuraEffectActor::OnEndOverlap(AActor* TargetActor)
{
    // ... 与 OnOverlap 类似的 ApplyOnEndOverlap 检查 ...

    // ★ 关键：检查是否需要移除无限效果
    if (InfiniteEffectRemovalPolicy == EEffectRemovalPolicy::RemoveOnEndOverlap)
    {
        UAbilitySystemComponent* TargetASC = 
            UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent(TargetActor);
        if (!IsValid(TargetASC)) return;

        // 遍历存储的 Handle，找到对应的 ASC 后移除
        TArray<FActiveGameplayEffectHandle> HandlesToRemove;
        for (auto HandlePair : ActiveEffectHandles)
        {
            if (TargetASC == HandlePair.Value)
            {
                TargetASC->RemoveActiveGameplayEffect(HandlePair.Key, 1);
                HandlesToRemove.Add(HandlePair.Key);
            }
        }
        // 从 Map 中清理已移除的 Handle
        for (auto& Handle : HandlesToRemove)
        {
            ActiveEffectHandles.FindAndRemoveChecked(Handle);
        }
    }
}
```

> ⚠️ 注意：蓝图侧需要将 `OnComponentBeginOverlap` 和 `OnComponentEndOverlap` 事件绑定到 `OnOverlap` 和 `OnEndOverlap` 函数，而不再直接调用 `ApplyEffectToTarget`。

## 三、无限效果的存储与移除（6.8-6.9 核心）

<a id="section-10"></a>
### 3.1 为什么无限效果最复杂

三种效果类型的生命周期管理难度：

| 效果类型                | 管理难度 | 原因          |
| ------------------- | ---- | ----------- |
| Instant（即时）         | ⭐    | 一次性生效，无需追踪  |
| Has Duration（有持续时间） | ⭐⭐   | 自动过期，无需手动移除 |
| Infinite（无限）        | ⭐⭐⭐  | 永久存在，必须手动移除 |

<a id="section-11"></a>
### 3.2 运行时判断效果是否为无限

在 `ApplyEffectToTarget` 中，通过访问 GE 的类默认对象来判断持续时间策略：

SpecHandle是用来在不同代码中进行通信的，相当于一个包装盒，里面包装了Spec，而Spec中储存的是这个GE具体的运行时的数据，可以访问以下数据。Def就是定义这个GE时内部的配置。即固定不变的，要想获取**DurationPolicy**自然要到Def层。

| 数据                           | 类型                                             | 说明                                        |
|:---------------------------- |:---------------------------------------------- |:----------------------------------------- |
| `Def`                        | `TObjectPtr<UGameplayEffect>`                  | **指向 Def 的指针**（回查配置用）                     |
| `Level`                      | `float`                                        | **运行时等级**（可能 ≠ Def 默认值，如技能升级后）            |
| `EffectContext`              | `FGameplayEffectContextHandle`                 | **施法上下文**（谁施放的、目标是谁、命中结果等）                |
| `CapturedRelevantAttributes` | `FGameplayEffectAttributeCaptureSpecContainer` | **捕获的属性快照**（如"基于目标最大生命值的 10%"，这里存的是快照值）   |
| `SetByCallerMagnitudes`      | `TMap<FGameplayTag, float>`                    | **外部传入的动态数值**（如技能伤害 = 基础值 × 等级系数）         |
| `Duration`                   | `float`                                        | **实际计算后的持续时间**（Def 可能有公式，这里存结果）           |
| `Period`                     | `float`                                        | **实际周期**（同样可能被运行时修改）                      |
| `Modifiers`                  | `TArray<FModifierSpec>`                        | **运行时修饰符实例**（每个对应 Def 的一个 Modifier，但值已计算） |
| `StackCount`                 | `int32`                                        | **当前叠加层数**                                |
| `DynamicGrantedTags`         | `FGameplayTagContainer`                        | **运行时动态添加的标签**                            |
| `DynamicAssetTags`           | `FGameplayTagContainer`                        | **运行时动态添加的资产标签**                          |

```cpp
// 从 SpecHandle → Spec → Def → DurationPolicy 的访问链
const bool bIsInfinite = EffectSpecHandle.Data.Get()->Def.Get()->DurationPolicy 
                         == EGameplayEffectDurationType::Infinite;
```

**访问链路详解**：

```
FGameplayEffectSpecHandle (Handle)
    └── .Data (TSharedPtr<FGameplayEffectSpec>)
         └── .Get() → FGameplayEffectSpec* (原始指针)
              └── .Def (TSubclassOf<UGameplayEffect>)
                   └── .Get() → UGameplayEffect* (类默认对象 CDO)
                        └── .DurationPolicy (EGameplayEffectDurationType)
```

> 💡 这里访问的是**类默认对象（CDO）**，不是运行时实例。我们只是读取策略配置，不修改它。

<a id="section-12"></a>
### 3.3 TMap<FActiveGameplayEffectHandle, UAbilitySystemComponent*> 设计

**为什么需要 Map？**

场景：多个角色同时站在火区域中，每个都需要独立追踪其效果 Handle。

```
❌ 错误做法：单个变量存储 Handle
    FActiveGameplayEffectHandle ActiveEffect;
    → 第二个角色进入时会覆盖第一个的 Handle，导致第一个角色的效果无法移除

✅ 正确做法：Map 将 Handle 与 ASC 关联
    TMap<FActiveGameplayEffectHandle, UAbilitySystemComponent*> ActiveEffectHandles;
    → 每个角色的 ASC 对应自己的 Handle，互不干扰
```

**存储时机**：

```cpp
// ApplyEffectToTarget 中
const FActiveGameplayEffectHandle ActiveEffectHandle = 
    TargetASC->ApplyGameplayEffectSpecToSelf(*(EffectSpecHandle.Data.Get()));

const bool bIsInfinite = /* 判断是否为无限 */;
if (bIsInfinite && InfiniteEffectRemovalPolicy == EEffectRemovalPolicy::RemoveOnEndOverlap)
{
    ActiveEffectHandles.Add(ActiveEffectHandle, TargetASC);
}
```

> 💡 只有在"需要移除"时才存储 Handle。如果移除策略是 `DoNotRemove`，就不需要存储。

<a id="section-13"></a>
### 3.4 遍历移除时的安全策略：先收集再删除

**问题**：在遍历 Map 的过程中不能直接移除元素，否则会导致迭代器失效（崩溃）。

**解决方案**：先收集要移除的 Handle，遍历结束后再统一删除。

```cpp
// 第一步：遍历收集
TArray<FActiveGameplayEffectHandle> HandlesToRemove;
for (auto HandlePair : ActiveEffectHandles)
{
    if (TargetASC == HandlePair.Value)
    {
        TargetASC->RemoveActiveGameplayEffect(HandlePair.Key, 1);
        HandlesToRemove.Add(HandlePair.Key);
    }
}

// 第二步：安全删除
for (auto& Handle : HandlesToRemove)
{
    ActiveEffectHandles.FindAndRemoveChecked(Handle);
}
```

<a id="section-14"></a>
### 3.5 堆栈移除数量控制

```cpp
// RemoveActiveGameplayEffect 的第二个参数是移除的堆栈数
TargetASC->RemoveActiveGameplayEffect(HandlePair.Key, 1);  // 只移除 1 个堆栈
// TargetASC->RemoveActiveGameplayEffect(HandlePair.Key, -1); // -1 = 移除所有堆栈
```

当多个火区域重叠时，每个区域独立管理自己的一个堆栈，离开一个区域只移除一个堆栈，不会影响其他区域的堆栈。

## 四、PreAttributeChange — 属性修改前的钳制（6.10 核心）

<a id="section-16"></a>
### 4.1 为什么需要 PreAttributeChange

在没有钳制之前：

```
❌ 问题：
  - 健康值可以降到负数（-10, -20...）
  - 法力值可以超过最大法力值（60/50）
  - UI 显示异常
```

<a id="section-17"></a>
### 4.2 NewValue 是通过引用传递的

```cpp
virtual void PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue) override;
//                                                                          ^^^^^^
//                                                              非 const 引用！可以修改！
```

这个设计意味着：**在属性值真正改变之前，我们可以拦截并修改 NewValue**。

<a id="section-18"></a>
### 4.3 FMath::Clamp 钳制实现

```cpp
void UAuraAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue)
{
    Super::PreAttributeChange(Attribute, NewValue);

    if (Attribute == GetHealthAttribute())
    {
        NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth());
    }
    if (Attribute == GetManaAttribute())
    {
        NewValue = FMath::Clamp(NewValue, 0.f, GetMaxMana());
    }
}
```

**FMath::Clamp 语义**：

```cpp
NewValue = FMath::Clamp(NewValue, Min, Max);
// 等价于：
// if (NewValue < Min) NewValue = Min;
// if (NewValue > Max) NewValue = Max;
```

<a id="section-19"></a>
### 4.4 与 PostGameplayEffectExecute 的区别

| 特性          | PreAttributeChange | PostGameplayEffectExecute |
| ----------- | ------------------ | ------------------------- |
| **调用时机**    | 属性修改**之前**         | GE 执行**之后**               |
| **主要用途**    | 钳制（Clamp）          | 响应逻辑（UI、死亡、升级等）           |
| **Epic 建议** | **仅用于钳制**          | 用于触发游戏逻辑                  |
| **能否修改属性值** | ✅ 可以（通过引用）         | ❌ 不应直接修改                  |
| **触发范围**    | 任何属性变化（含直接 Set）    | 仅 GE 导致的属性变化              |

> ⚠️ **重要限制**：PreAttributeChange 只是临时修改了"此次变化的值"，并不永久改变修饰符。在属性变化之后，GAS 会重新计算所有修饰符的当前值。这意味着 PreAttributeChange 的钳制可能不是最终结果——真正的"最终钳制"需要在 PostGameplayEffectExecute 中再做一次。

## 五、PostGameplayEffectExecute — 效果执行后的数据收集（6.11 核心）

<a id="section-21"></a>
### 5.1 FGameplayEffectModCallbackData 数据结构

```cpp
void UAuraAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data)
```

`Data` 包含三个关键成员：

| 成员                   | 类型                                        | 说明                              |
| -------------------- | ----------------------------------------- | ------------------------------- |
| `Data.EffectSpec`    | `FGameplayEffectSpec`                     | 效果规格（含上下文、幅度等）                  |
| `Data.EvaluatedData` | `FGameplayEffectModCallbackEvaluatedData` | 被修改的属性、幅度、操作类型                  |
| `Data.Target`        | `UAbilitySystemComponent`                 | 目标 ASC（即此 AttributeSet 所属的 ASC） |

<a id="section-22"></a>
### 5.2 从 Data 中获取 Source 信息

Source = 效果的**施加者**（谁造成了这个效果）：

```cpp
// 步骤 1：从 EffectSpec 获取上下文
FGameplayEffectContextHandle EffectContextHandle = Data.EffectSpec.GetContext();

// 步骤 2：从上下文获取 Source 的 ASC
UAbilitySystemComponent* SourceASC = 
    EffectContextHandle.GetOriginalInstigatorAbilitySystemComponent();

// 步骤 3：从 SourceASC 获取 AvatarActor、Controller、Character
if (IsValid(SourceASC) && SourceASC->AbilityActorInfo.IsValid())
{
    AActor* SourceAvatarActor = SourceASC->AbilityActorInfo->AvatarActor.Get();
    AController* SourceController = SourceASC->AbilityActorInfo->PlayerController.Get();

    // 如果 PlayerController 为空，尝试从 Pawn 获取
    if (SourceAvatarActor && !SourceController)
    {
        // 用Pawn保证AI也可以获得到Controller
        if (const APawn* Pawn = Cast<APawn>(SourceAvatarActor))
        {
            SourceController = Pawn->GetController();
        }
    }

    // 从 Controller 获取 Character
    if (SourceController)
    {
        ACharacter* SourceCharacter = Cast<ACharacter>(SourceController->GetPawn());
    }
}
```

<a id="section-23"></a>
### 5.3 从 Data 中获取 Target 信息

Target = 效果的**承受者**（此 AttributeSet 的所有者）：

```cpp
// 直接从 Data.Target 获取（这已经是目标 ASC）
if (Data.Target.AbilityActorInfo.IsValid() && Data.Target.AbilityActorInfo->AvatarActor.IsValid())
{
    AActor* TargetAvatarActor = Data.Target.AbilityActorInfo->AvatarActor.Get();
    AController* TargetController = Data.Target.AbilityActorInfo->PlayerController.Get();
    ACharacter* TargetCharacter = Cast<ACharacter>(TargetAvatarActor);
    UAbilitySystemComponent* TargetASC = 
        UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent(TargetAvatarActor);
}
```

#### 这几种变量的不同以及获取方式的差异

| 变量                   | Source（攻击者）                                       | Target（受击者）                                       | 获取方式差异                                 | 用途                          |
|:-------------------- |:------------------------------------------------- |:------------------------------------------------- |:-------------------------------------- |:--------------------------- |
| **ASC**              | `Data.Source`                                     | `Data.Target`                                     | 直接取，不查询                                | 应用 GE、查询属性                  |
| **AvatarActor**      | `Data.Source.AbilityActorInfo->AvatarActor.Get()` | `Data.Target.AbilityActorInfo->AvatarActor.Get()` | 相同                                     | 物理实体引用                      |
| **Character**        | `Cast<ACharacter>(SourceAvatarActor)`             | `Cast<ACharacter>(TargetAvatarActor)`             | 相同                                     | 播放动画、位移                     |
| **Pawn**             | `Cast<APawn>(SourceAvatarActor)`                  | `Cast<APawn>(TargetAvatarActor)`                  | 相同                                     | 通用接口                        |
| **Controller**       | **必须获取**（玩家/AI 判断）                                | **通常不需要**（除非反馈）                                   | Source 需兜底，Target 省略                   | Source：归属判定；Target：镜头/UI 反馈 |
| **PlayerController** | `Cast<APlayerController>(SourceController)`       | `Cast<APlayerController>(TargetController)`       | 仅当需要时                                  | Source：加分；Target：屏幕震动       |
| **PlayerState**      | `SourcePC->GetPlayerState()`                      | `TargetCharacter->GetPlayerState()`               | Source 从 Controller，Target 从 Character | 持久数据（等级、分数）                 |



<a id="section-25"></a>
### 5.4 FEffectProperties 结构体设计

为了不在 PostGameplayEffectExecute 中堆积大量代码，我们创建一个结构体来统一存储效果执行的所有上下文：

```cpp
// AuraAttributeSet.h
USTRUCT()
struct FEffectProperties
{
    GENERATED_BODY()

    FEffectProperties() {}

    FGameplayEffectContextHandle EffectContextHandle;

    UPROPERTY()
    UAbilitySystemComponent* SourceASC = nullptr;

    UPROPERTY()
    AActor* SourceAvatarActor = nullptr;

    UPROPERTY()
    AController* SourceController = nullptr;

    UPROPERTY()
    ACharacter* SourceCharacter = nullptr;

    UPROPERTY()
    UAbilitySystemComponent* TargetASC = nullptr;

    UPROPERTY()
    AActor* TargetAvatarActor = nullptr;

    UPROPERTY()
    AController* TargetController = nullptr;

    UPROPERTY()
    ACharacter* TargetCharacter = nullptr;
};
```

> 💡 所有指针都用 `UPROPERTY()` 标记，防止被垃圾回收（GC）误清除。

<a id="section-26"></a>
### 5.5 SetEffectProperties 辅助函数

```cpp
// AuraAttributeSet.h — 私有辅助函数
private:
    void SetEffectProperties(const FGameplayEffectModCallbackData& Data, 
                             FEffectProperties& Props) const;
```

**在 PostGameplayEffectExecute 中的使用**：

```cpp
void UAuraAttributeSet::PostGameplayEffectExecute(const FGameplayEffectModCallbackData& Data)
{
    Super::PostGameplayEffectExecute(Data);

    FEffectProperties Props;
    SetEffectProperties(Data, Props);

    // 现在可以通过 Props.SourceCharacter、Props.TargetASC 等访问所有信息
    // 后续课程中会在这里添加伤害计算、死亡判定等逻辑
}
```

**完整的 Source/Target 关系图**：

```
┌─────────────────────────────────────────────────────────┐
│  Source (施加者)                  Target (承受者)         │
```

<a id="section-27"></a>
## 六、曲线表（Curve Table）与可缩放浮点（6.12 核心）

<a id="section-28"></a>
### 6.1 Scalable Float 的真正含义

之前我们只是把 Scalable Float 当作"硬编码一个数值"使用。现在揭示其真正威力：

```
Scalable Float = 基础值 × 曲线表中对应等级的值
```

例如：基础值 = 1.0，曲线表中等级 1 = 5 → 实际效果 = 5

<a id="section-29"></a>
### 6.2 曲线表的创建与配置

**创建步骤**：

1. 在 Content Browser 中右键 → Miscellaneous → **Curve Table**
2. 选择插值类型（Linear / Constant / Cubic）
3. 命名（如 `CT_Potions`）

**配置示例**（治疗曲线）：

| 等级  | 治疗量 |
| --- | --- |
| 1   | 5   |
| 2   | 7.5 |
| 3   | 10  |
| 4   | 15  |
| 5   | 20  |
| 6   | 30  |
| 7   | 45  |
| 8   | 60  |
| 9   | 85  |
| 10  | 100 |

> 💡 曲线表支持两种视图：**电子表格视图**（类似 Excel）和**图表视图**（可视化曲线）。在图表视图中可以拖拽调整点，使曲线更平滑。

<a id="section-30"></a>
### 6.3 在 GE 中使用曲线表

在 GE 蓝图的 Modifier 中：

1. 将 Magnitude Calculation Type 设为 **Scalable Float**
2. 将基础值设为 **1.0**（让曲线表完全控制数值）
3. 在 Curve Table 下拉中选择 `CT_Potions`
4. 在 Curve 下拉中选择具体曲线（如 `HealingCurve`）

```
实际效果值 = 基础值(1.0) × 曲线表中对应等级的值
等级 1: 1.0 × 5 = 5
等级 2: 1.0 × 7.5 = 7.5
等级 4.75: 1.0 × ~18.5 = ~18.5  ← 自动线性插值！
```

<a id="section-31"></a>
### 6.4 ActorLevel 变量的引入

为了让 EffectActor 能够以不同等级应用效果：

```cpp
// AuraEffectActor.h
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Applied Effects")
float ActorLevel = 1.f;
```

在 `ApplyEffectToTarget` 中使用：

```cpp
// 之前硬编码等级
const FGameplayEffectSpecHandle EffectSpecHandle = 
    TargetASC->MakeOutgoingSpec(GameplayEffectClass, 1.f, EffectContextHandle);

// 现在使用 ActorLevel
const FGameplayEffectSpecHandle EffectSpecHandle = 
    TargetASC->MakeOutgoingSpec(GameplayEffectClass, ActorLevel, EffectContextHandle);
```

**蓝图中的效果**：设计师可以放置多个同类型的药水，每个设置不同的 `ActorLevel`，实现不同强度的效果。

<a id="section-32"></a>
### 6.5 一条曲线表管理多条曲线

一个 Curve Table 可以包含多条曲线，每条曲线对应不同的效果：

```
CT_Potions (曲线表)
    ├── HealingCurve   → GE_PotionHeal 使用
    └── ManaCurve      → GE_PotionMana 使用
```

这样所有药水相关的数值集中管理，方便设计师统一调整平衡性。

## 八、知识点总结

| 知识点                           | 要点                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| **策略枚举模式**                    | 用枚举替代硬编码的 if-else，让蓝图设计师自由组合"何时应用"和"何时移除"                                             |
| **TMap 存储 Handle**            | `TMap<FActiveGameplayEffectHandle, UAbilitySystemComponent*>` 将效果与目标 ASC 关联，支持多角色独立追踪 |
| **遍历安全**                      | 遍历容器时不能直接删除元素 → 先收集到 TArray，遍历结束后统一删除                                                 |
| **PreAttributeChange**        | 仅用于钳制（Clamp），NewValue 通过引用传递可修改，但不永久改变修饰符                                             |
| **PostGameplayEffectExecute** | GE 执行后触发，适合响应游戏逻辑；通过 Data 参数可获取 Source 和 Target 的完整信息                                 |
| **FEffectProperties**         | 封装效果执行上下文的 USTRUCT，集中管理 Source/Target 的 ASC、Actor、Controller、Character                |
| **曲线表**                       | 数据驱动的数值管理工具，支持按等级缩放、多曲线共存、线性插值                                                        |
| **ActorLevel**                | 让 EffectActor 拥有等级概念，同一个 GE 蓝图可根据等级产生不同强度的效果                                          |
| **Scalable Float**            | 基础值 × 曲线表等级值 = 实际效果，是实现数据驱动平衡的核心机制                                                    |
