## 一、本次提交的整体目标

上一阶段已经把增强输入转换为 `InputTag`，但 PlayerController 只会打印标签。本次提交把这条链路继续向后接通，并加入第一种可见的技能实体——投射物。

本次实现可以分为四条主线：

1. **能力输入激活**：把能力的初始输入标签写入 `FGameplayAbilitySpec::DynamicAbilityTags`，ASC 根据输入 Tag 查找并激活技能。
2. **左键意图分流**：鼠标指向敌人时视为技能输入，指向地面时视为移动输入。
3. **多人自动寻路**：短按左键生成导航路径和样条，随后每帧通过 `AddMovementInput` 自动行走。
4. **投射物法术骨架**：服务器从武器插槽位置延迟生成可复制的投射物 Actor。

此外还修复了 GameplayEffect 的消息标签只在服务器广播，拥有客户端 HUD 收不到提示的问题。

```text
输入层
  InputAction → InputTag
        ↓
AAuraPlayerController
  ├── 指向敌人 → 传给 ASC 激活技能
  └── 指向地面 → 长按直线移动 / 短按自动寻路

技能层
  ASC 根据 DynamicAbilityTags 找 AbilitySpec
        ↓ TryActivateAbility
  UAuraProjectileSpell::ActivateAbility
        ↓ 仅服务器
  从武器插槽生成 AAuraProjectile
        ↓ Actor 复制
  客户端看到投射物
```

## 二、InputTag 驱动 GameplayAbility 激活（10.7）

### 2.1 在能力基类配置初始输入标签

`UAuraGameplayAbility` 新增：

```cpp
UPROPERTY(EditDefaultsOnly, Category="Input")
FGameplayTag StartupInputTag;
```

该字段配置在能力蓝图的 Class Defaults 中，例如：

```text
GA_FireBolt
    └── StartupInputTag = InputTag.LMB

GA_ArcaneShards
    └── StartupInputTag = InputTag.Num1
```

名称中特意使用 `Startup`，因为它只表示能力初次授予时默认占用的输入槽。运行时换技能栏后，真正使用的输入标签可以改变。

### 2.2 为什么不直接用能力 CDO 上的标签激活

`StartupInputTag` 位于 GameplayAbility 类默认对象上，适合提供初始配置；但角色实际持有的是 `FGameplayAbilitySpec`。

`FGameplayAbilitySpec` 提供了专门的运行时标签容器：

```cpp
FGameplayTagContainer DynamicAbilityTags;
```

它适合保存当前输入绑定，原因是：

- 它属于角色实际持有的 AbilitySpec。
- 可在运行时添加和移除。
- 同一种 Ability 类在不同角色身上可以绑定不同按键。
- 换技能槽时无需修改能力类本身。

```text
StartupInputTag
    └── 能力类上的“初始建议值”

DynamicAbilityTags
    └── AbilitySpec 上的“当前运行时绑定”
```

### 2.3 授予能力时复制 InputTag

`UAuraAbilitySystemComponent::AddCharacterAbilities()`：

```cpp
void UAuraAbilitySystemComponent::AddCharacterAbilities(
    const TArray<TSubclassOf<UGameplayAbility>>& StartupAbilities)
{
    for (const TSubclassOf<UGameplayAbility> AbilityClass : StartupAbilities)
    {
        FGameplayAbilitySpec AbilitySpec(AbilityClass, 1);

        if (const UAuraGameplayAbility* AuraAbility =
            Cast<UAuraGameplayAbility>(AbilitySpec.Ability))
        {
            AbilitySpec.DynamicAbilityTags.AddTag(
                AuraAbility->StartupInputTag);

            GiveAbility(AbilitySpec);
        }
    }
}
```

与上一提交相比，这里从 `GiveAbilityAndActivateOnce` 改为 `GiveAbility`：

- 能力被授予但不会立即执行。
- AbilitySpec 会保留在 ASC 中。
- 后续可由输入重复请求激活。

### 2.4 ASC 处理 Held 输入

```cpp
void UAuraAbilitySystemComponent::AbilityInputTagHeld(
    const FGameplayTag& InputTag)
{
    if (!InputTag.IsValid()) return;

    for (FGameplayAbilitySpec& AbilitySpec : GetActivatableAbilities())
    {
        if (AbilitySpec.DynamicAbilityTags.HasTagExact(InputTag))
        {
            AbilitySpecInputPressed(AbilitySpec);

            if (!AbilitySpec.IsActive())
            {
                TryActivateAbility(AbilitySpec.Handle);
            }
        }
    }
}
```

处理过程：

```text
收到 InputTag
    ↓ 检查有效性
遍历 GetActivatableAbilities()
    ↓
DynamicAbilityTags.HasTagExact(InputTag)
    ↓ 匹配成功
AbilitySpecInputPressed
    ↓
AbilitySpec 尚未激活？
    └── TryActivateAbility(AbilitySpec.Handle)
```

使用 `TryActivateAbility` 而不是直接强制激活，是因为 GAS 还要检查：

- Cost 是否足够。
- Cooldown 是否结束。
- Required/Blocked Tags 是否满足。
- 网络执行策略是否允许。
- 能力自身的 `CanActivateAbility` 是否通过。

### 2.5 Held 为什么不会每帧重复激活

`Held` 会在按键保持期间持续触发。ASC 先检查：

```cpp
if (!AbilitySpec.IsActive())
{
    TryActivateAbility(AbilitySpec.Handle);
}
```

能力处于 Active 状态时只更新“输入仍按下”，不会每帧再次激活。能力何时结束由自身生命周期决定。

### 2.6 Released 只通知，不强制结束

```cpp
void UAuraAbilitySystemComponent::AbilityInputTagReleased(
    const FGameplayTag& InputTag)
{
    if (!InputTag.IsValid()) return;

    for (FGameplayAbilitySpec& AbilitySpec : GetActivatableAbilities())
    {
        if (AbilitySpec.DynamicAbilityTags.HasTagExact(InputTag))
        {
            AbilitySpecInputReleased(AbilitySpec);
        }
    }
}
```

松开按键不等于结束能力：

- 火球术可能按下后立即施放，松开不应取消。
- 蓄力技能可能在松开时释放。
- 引导技能可能在松开时自行结束。
- 被动技能通常完全不关心松开事件。

ASC 只更新 AbilitySpec 输入状态并通知能力实例，具体反应由每个 Ability 决定。

### 2.7 PlayerController 缓存 ASC

```cpp
UAuraAbilitySystemComponent* AAuraPlayerController::GetASC()
{
    if (AuraAbilitySystemComponent == nullptr)
    {
        AuraAbilitySystemComponent =
            Cast<UAuraAbilitySystemComponent>(
                UAbilitySystemBlueprintLibrary::
                    GetAbilitySystemComponent(GetPawn()));
    }

    return AuraAbilitySystemComponent;
}
```

使用延迟获取和缓存，避免每次输入都重新查找 ASC。

## 三、鼠标左键的技能与移动分流（10.9）

### 3.1 同一个左键有两种含义

俯视角 RPG 中，鼠标左键既可能是移动，也可能是攻击：

```text
InputTag.LMB
    ├── 光标下是敌人 → Targeting → 技能输入
    └── 光标下是地面 → 非 Targeting → 移动输入
```

PlayerController 使用 `bTargeting` 保存左键按下瞬间的意图。

### 3.2 Pressed：锁定本次输入意图

```cpp
void AAuraPlayerController::AbilityInputTagPressed(FGameplayTag InputTag)
{
    if (InputTag.MatchesTagExact(
        FAuraGameplayTags::Get().InputTag_LMB))
    {
        bTargeting = ThisActor ? true : false;
        bAutoRunning = false;
    }
}
```

按下左键时：

- `ThisActor` 有效：光标指向实现 `IEnemyInterface` 的敌人，进入技能目标模式。
- `ThisActor` 为空：本次左键用于移动。
- 无论哪种情况，都先停止旧的自动行走。

把意图记录在 Pressed 阶段很重要。如果玩家按下时指向敌人，按住期间敌人移动出光标，也不应突然从攻击切换成移动。

### 3.3 非左键直接交给 ASC

```cpp
if (!InputTag.MatchesTagExact(InputTag_LMB))
{
    if (GetASC())
    {
        GetASC()->AbilityInputTagHeld(InputTag);
    }
    return;
}
```

数字键和鼠标右键没有移动歧义，因此 Held/Released 直接转发给 ASC。

### 3.4 左键指向敌人时交给 ASC

```cpp
if (bTargeting)
{
    GetASC()->AbilityInputTagHeld(InputTag);
}
```

这允许绑定 `InputTag.LMB` 的攻击能力通过同一套 AbilitySpec Tag 机制激活。

### 3.5 左键指向地面时持续移动

```cpp
FollowTime += GetWorld()->GetDeltaSeconds();

if (CursorHit.bBlockingHit)
{
    CachedDestination = CursorHit.ImpactPoint;
}

if (APawn* ControllerPawn = GetPawn())
{
    const FVector WorldDirection =
        (CachedDestination - ControllerPawn->GetActorLocation())
        .GetSafeNormal();

    ControllerPawn->AddMovementInput(WorldDirection);
}
```

`FollowTime` 用于区分长按和短按：

| 条件 | 行为 |
|---|---|
| 持续按住 | 每帧更新目标并向光标方向移动 |
| 松开时 `FollowTime <= ShortPressThreshold` | 生成路径并开启 AutoRun |
| 松开时超过阈值 | 结束手动跟随，不生成自动路径 |

当前短按阈值为 `0.5s`。

## 四、短按寻路与 Spline 路径构建（10.10）

### 4.1 松开左键时生成路径

只有满足以下条件才进入自动寻路：

- 输入是鼠标左键。
- 按下时没有锁定敌人。
- `FollowTime <= ShortPressThreshold`。
- 当前 Controller 拥有有效 Pawn。

```cpp
UNavigationPath* NavPath =
    UNavigationSystemV1::FindPathToLocationSynchronously(
        this,
        ControllerPawn->GetActorLocation(),
        CachedDestination);
```

同步路径查询输入：

```text
WorldContextObject = PlayerController
PathStart          = 当前 Pawn 位置
PathEnd            = 鼠标命中的 CachedDestination
```

输出 `UNavigationPath` 中的 `PathPoints` 是从起点到可达终点的一系列导航节点。

### 4.2 将路径点写入 Spline

PlayerController 构造时创建样条组件：

```cpp
Spline = CreateDefaultSubobject<USplineComponent>("Spline");
```

每次生成新路径时，先清除旧点，再写入导航路径：

```cpp
Spline->ClearSplinePoints();

for (const FVector& PointLocation : NavPath->PathPoints)
{
    Spline->AddSplinePoint(
        PointLocation,
        ESplineCoordinateSpace::World);
}
```

职责分工：

```text
NavigationSystem
    └── 计算绕开障碍物的可行路径点

SplineComponent
    └── 根据路径点提供连续的路径位置和方向

CharacterMovement
    └── 消费 AddMovementInput，完成预测和网络同步
```

### 4.3 开启自动行走

路径构建完成后：

```cpp
CachedDestination =
    NavPath->PathPoints[NavPath->PathPoints.Num() - 1];

bAutoRunning = true;
FollowTime = 0.f;
```

这里把目标改成导航路径的最后一点，而不是原始鼠标命中点。

原因是鼠标可能点到 NavMesh 外部。导航系统返回的最后一点是实际可达位置，如果仍用原始不可达点做停止判断，角色会永远无法进入接受半径。

## 五、AutoRun 自动行走与客户端导航（10.11）

### 5.1 每帧执行 AutoRun

```cpp
void AAuraPlayerController::PlayerTick(float DeltaTime)
{
    Super::PlayerTick(DeltaTime);
    CursorTrace();
    AutoRun();
}
```

`AutoRun()` 首先检查状态：

```cpp
if (!bAutoRunning) return;
```

只有短按成功生成路径后，才进入自动行走逻辑。

### 5.2 获取样条上的最近位置和方向

```cpp
const FVector LocationOnSpline =
    Spline->FindLocationClosestToWorldLocation(
        ControllerPawn->GetActorLocation(),
        ESplineCoordinateSpace::World);

const FVector Direction =
    Spline->FindDirectionClosestToWorldLocation(
        LocationOnSpline,
        ESplineCoordinateSpace::World);
```

角色可能因碰撞或网络修正稍微偏离样条，因此不能假设角色精确位于曲线上。每帧先找最近的样条位置，再取得该处的前进方向。

### 5.3 使用 AddMovementInput 驱动

```cpp
ControllerPawn->AddMovementInput(Direction);
```

样条只提供方向，实际位移仍通过 CharacterMovement 完成，因此可以使用：

- 客户端预测。
- 服务器移动校验。
- 网络位置复制。
- 碰撞和地面移动。
- 服务器修正后的平滑处理。

### 5.4 到达目标后停止

```cpp
const float DistanceToDestination =
    (LocationOnSpline - CachedDestination).Length();

if (DistanceToDestination <= AutoRunAcceptanceRadius)
{
    bAutoRunning = false;
}
```

当前接受半径为 `50.f`。使用范围判断而不是要求坐标完全相等，避免浮点误差和移动制动造成无法停止。

### 5.5 允许客户端生成导航路径

`DefaultEngine.ini` 新增：

```ini
[/Script/NavigationSystem.NavigationSystemV1]
bAllowClientSideNavigation=True
```

如果不启用，远程客户端无法在本地生成 `UNavigationPath`，表现为主机能自动寻路、客户端点击松开无反应。

### 5.6 添加 NavigationSystem 模块

`Aura.Build.cs`：

```csharp
PrivateDependencyModuleNames.AddRange(new string[]
{
    "GameplayTags",
    "GameplayTasks",
    "NavigationSystem"
});
```

使用 `UNavigationSystemV1` 和 `UNavigationPath` 前，模块必须加入构建依赖。

### 5.7 场景碰撞对点击目标的影响

光标检测使用 `ECC_Visibility`。如果大型装饰物阻挡 Visibility，鼠标会命中装饰物表面，而不是其后方地面，可能产生不可达目标。

本节通过调整装饰物碰撞响应，让不希望被选中的物体忽略 Visibility Trace。

```text
鼠标射线
    ├── 可选中敌人：阻挡 Visibility
    ├── 可点击地面：阻挡 Visibility
    └── 纯装饰障碍：按设计决定是否忽略 Visibility
```

碰撞通道不仅影响物理碰撞，也决定鼠标“看见”的对象。

## 六、PlayerController 重构与 GE 消息客户端 RPC（10.12）

### 6.1 CursorHit 改为成员变量

之前 `CursorTrace()` 和 Held 移动逻辑会各做一次鼠标射线检测。本节将结果缓存为 PlayerController 成员：

```cpp
FHitResult CursorHit;
```

每帧由 `CursorTrace()` 更新一次：

```cpp
GetHitResultUnderCursor(ECC_Visibility, false, CursorHit);
```

随后高亮、移动目标和其他光标功能共享同一份 HitResult，避免重复 Trace，也保证同一帧内各系统看到一致的命中结果。

### 6.2 问题：GE 消息只在服务器触发

原先 ASC 绑定：

```cpp
OnGameplayEffectAppliedDelegateToSelf
    .AddUObject(this, &UAuraAbilitySystemComponent::EffectApplied);
```

`OnGameplayEffectAppliedDelegateToSelf` 在服务器权威应用 GameplayEffect 时触发。远程拥有客户端不会自动执行相同回调，导致：

- 服务器 HUD 能显示药水/效果消息。
- 远程客户端 HUD 收不到 `EffectAssetTags` 广播。

### 6.3 改成 Client Reliable RPC

```cpp
UFUNCTION(Client, Reliable)
void ClientEffectApplied(
    UAbilitySystemComponent* AbilitySystemComponent,
    const FGameplayEffectSpec& EffectSpec,
    FActiveGameplayEffectHandle ActiveEffectHandle);
```

实现函数按 UE RPC 约定添加 `_Implementation`：

```cpp
void UAuraAbilitySystemComponent::ClientEffectApplied_Implementation(
    UAbilitySystemComponent* AbilitySystemComponent,
    const FGameplayEffectSpec& EffectSpec,
    FActiveGameplayEffectHandle ActiveEffectHandle)
{
    FGameplayTagContainer TagContainer;
    EffectSpec.GetAllAssetTags(TagContainer);
    EffectAssetTags.Broadcast(TagContainer);
}
```

调用链：

```text
服务器向 ASC 应用 GameplayEffect
    ↓ OnGameplayEffectAppliedDelegateToSelf
服务器调用 ClientEffectApplied RPC
    ↓
拥有该 ASC 的客户端执行 _Implementation
    ↓
提取 EffectSpec AssetTags
    ↓
EffectAssetTags.Broadcast
    ↓
OverlayWidgetController 接收并更新消息 UI
```

`Client` RPC 只发送给拥有该 Actor/Component 的客户端，不会广播给所有玩家，正好符合个人 HUD 消息的需求。

## 七、投射物 Actor 基础结构（10.13）

### 7.1 AAuraProjectile

新增投射物 Actor：

```cpp
UCLASS()
class AURA_API AAuraProjectile : public AActor
{
    GENERATED_BODY()

public:
    AAuraProjectile();

    UPROPERTY(VisibleAnywhere)
    TObjectPtr<UProjectileMovementComponent> ProjectileMovement;

private:
    UPROPERTY(VisibleAnywhere)
    TObjectPtr<USphereComponent> Sphere;
};
```

基础职责：

- `USphereComponent`：重叠检测和根组件。
- `UProjectileMovementComponent`：速度、方向和弹道运动。
- 蓝图子类：配置 Mesh、Niagara、材质等表现资源。

### 7.2 投射物复制

```cpp
bReplicates = true;
```

本项目采用服务器生成投射物的权威模式。服务器生成后，Actor 复制到客户端；客户端不自行生成另一份权威投射物。

### 7.3 Sphere 碰撞配置

```cpp
Sphere->SetCollisionEnabled(ECollisionEnabled::QueryOnly);
Sphere->SetCollisionResponseToAllChannels(ECR_Ignore);
Sphere->SetCollisionResponseToChannel(ECC_WorldDynamic, ECR_Overlap);
Sphere->SetCollisionResponseToChannel(ECC_WorldStatic, ECR_Overlap);
Sphere->SetCollisionResponseToChannel(ECC_Pawn, ECR_Overlap);
```

含义：

- 只参与查询，不产生物理阻挡。
- 默认忽略所有通道。
- 对动态世界、静态世界和 Pawn 产生 Overlap。

这种配置适合技能投射物：命中后执行伤害和特效逻辑，而不是把角色或场景刚体撞开。

### 7.4 绑定 Overlap 委托

```cpp
void AAuraProjectile::BeginPlay()
{
    Super::BeginPlay();

    Sphere->OnComponentBeginOverlap.AddDynamic(
        this,
        &AAuraProjectile::OnSphereOverride);
}
```

当前 `OnSphereOverride()` 还是空函数，后续会补充：

- 忽略投射者自己。
- 对目标应用伤害 GameplayEffectSpec。
- 播放命中特效和声音。
- 销毁投射物。

### 7.5 ProjectileMovement 参数

```cpp
ProjectileMovement->InitialSpeed = 550.f;
ProjectileMovement->MaxSpeed = 550.f;
ProjectileMovement->ProjectileGravityScale = 0.f;
```

重力比例为 0，表示当前投射物沿初始方向直线飞行，不受下坠影响。

## 八、投射物技能类（10.14）

### 8.1 UAuraProjectileSpell

```cpp
UCLASS()
class AURA_API UAuraProjectileSpell : public UAuraGameplayAbility
{
    GENERATED_BODY()

protected:
    virtual void ActivateAbility(
        const FGameplayAbilitySpecHandle Handle,
        const FGameplayAbilityActorInfo* ActorInfo,
        const FGameplayAbilityActivationInfo ActivationInfo,
        const FGameplayEventData* TriggerEventData) override;

    UPROPERTY(EditAnywhere, BlueprintReadOnly)
    TSubclassOf<AAuraProjectile> ProjectileClass;
};
```

继承关系：

```text
UGameplayAbility
    └── UAuraGameplayAbility
          └── UAuraProjectileSpell
                └── GA_FireBolt（蓝图）
```

`ProjectileClass` 使用 `TSubclassOf`，让技能蓝图选择具体投射物蓝图类，同时 C++ 保证所选类一定继承 `AAuraProjectile`。

### 8.2 重写 ActivateAbility

```cpp
void UAuraProjectileSpell::ActivateAbility(
    const FGameplayAbilitySpecHandle Handle,

{
    Super::ActivateAbility(

```

参数职责：

| 参数 | 作用 |
|---|---|

## 九、服务器延迟生成投射物（10.15）

### 9.1 只在服务器生成

```cpp
if (!HasAuthority(&ActivationInfo)) return;
```

投射物会影响碰撞和伤害，必须由服务器权威生成：

```text
拥有客户端请求激活能力
    ↓ GAS 网络策略
服务器执行 ActivateAbility
    ↓ HasAuthority == true
生成可复制投射物
    ↓
客户端接收复制版本
```

如果客户端和服务器都生成，会看到重复投射物，并可能发生重复伤害。

### 9.2 使用 CombatInterface 获取生成位置

能力的 Avatar 可能是玩家、敌人或其他战斗单位。技能不应强制转换到某个具体角色类，因此扩展 `ICombatInterface`：

```cpp
virtual FVector GetCombatSocketLocation();
```

角色基类实现：

```cpp
FVector AAuraCharacterBase::GetCombatSocketLocation()
{
    check(Weapon);
    return Weapon->GetSocketLocation(WeaponTipSocketName);
}
```

角色蓝图配置 `WeaponTipSocketName`，技能只依赖接口：

```cpp
ICombatInterface* CombatInterface =
    Cast<ICombatInterface>(GetAvatarActorFromActorInfo());

const FVector SocketLocation =
    CombatInterface->GetCombatSocketLocation();
```

这样玩家和敌人只要实现同一接口，都能复用投射物技能。

### 9.3 为什么使用 SpawnActorDeferred

```cpp
AAuraProjectile* Projectile =
    GetWorld()->SpawnActorDeferred<AAuraProjectile>(
        ProjectileClass,
        SpawnTransform,
        Owner,
        Instigator,
        ESpawnActorCollisionHandlingMethod::AlwaysSpawn);

// 在 FinishSpawning 前设置运行时数据
// Projectile->DamageEffectSpecHandle = ...;

Projectile->FinishSpawning(SpawnTransform);
```

延迟生成分成两步：

1. 创建 Actor，但暂不完成 BeginPlay 等初始化。
2. 给投射物写入伤害 Spec、来源信息等运行时数据。
3. `FinishSpawning` 正式完成生成。

普通 `SpawnActor` 会一次完成创建，无法在 Actor 完成初始化前注入这些数据。

### 9.4 当前 SpawnTransform

```cpp
FTransform SpawnTransform;
SpawnTransform.SetLocation(SocketLocation);
```

本次只设置生成位置，因此投射物能够出现在法杖尖端，但还没有根据鼠标目标设置旋转方向。

### 9.5 伤害 Spec 的预留位置

源码保留：

```cpp
// TODO: Give the Projectile a Gameplay Effect Spec for causing Damage.
```

未来技能会创建伤害 GameplayEffectSpec，并在 `FinishSpawning` 前交给投射物。投射物命中目标时再应用该 Spec，从而保留：

- 技能等级。
- Source ASC。
- EffectContext。
- SetByCaller 伤害数值。
- 来源和目标标签捕获。

## 十二、源码校验与当前边界

### 12.1 NavPath 必须检查有效性

当前源码取得 `NavPath` 后直接访问：

```cpp
for (const FVector& PointLoc : NavPath->PathPoints)
```

路径查询失败时 `NavPath` 可能为空，或 `PathPoints` 可能没有元素，后面的最后元素索引会越界。

更安全的写法：

```cpp
if (NavPath && NavPath->PathPoints.Num() > 0)
{
    Spline->ClearSplinePoints();

    for (const FVector& Point : NavPath->PathPoints)
    {
        Spline->AddSplinePoint(
            Point,
            ESplineCoordinateSpace::World);
    }

    CachedDestination = NavPath->PathPoints.Last();
    bAutoRunning = true;
}
```

### 12.2 SpawnActorDeferred 的 Instigator 当前可能为空

当前传入：

```cpp
GetOwningActorFromActorInfo(),
Cast<APawn>(GetOwningActorFromActorInfo())
```

本项目玩家 ASC 的 OwnerActor 是 `PlayerState`，AvatarActor 才是 `Character/Pawn`。因此把 OwnerActor 转为 `APawn` 通常会失败，Instigator 变成空指针。

更合理的来源通常是：

```cpp
AActor* AvatarActor = GetAvatarActorFromActorInfo();
APawn* InstigatorPawn = Cast<APawn>(AvatarActor);
```

Owner 具体选 Ability 的 OwnerActor 还是 AvatarActor，取决于项目后续如何追踪伤害来源；Instigator 应优先使用 Avatar Pawn。

### 12.3 投射物尚未朝向目标

`SpawnTransform` 只设置 Location，没有设置 Rotation。当前投射物会沿其默认本地前向移动，不一定飞向鼠标位置或目标敌人。

后续需要：

```text
TargetLocation - SocketLocation
    ↓ Rotation()
SpawnTransform.SetRotation(...)
```

### 12.4 投射物尚未造成伤害

当前状态：

- `OnSphereOverride()` 为空。
- 没有 Damage GameplayEffectSpec。
- 没有排除投射者自己。
- 没有命中特效、声音和销毁逻辑。

本次只完成“生成并移动投射物”的骨架，还没有形成完整攻击闭环。

### 12.5 投射物能力没有结束

`UAuraProjectileSpell::ActivateAbility()` 生成投射物后没有调用 `EndAbility()`。由于 Held 逻辑不会重复激活处于 Active 状态的 Ability，该技能可能一直保持活动，后续无法再次施放。

课程后续通常会通过蒙太奇 AbilityTask、事件或显式 `EndAbility` 完成生命周期。

### 12.6 非 AuraGameplayAbility 会被跳过

`GiveAbility()` 位于转换成功的 `if` 内：

```cpp
if (const UAuraGameplayAbility* AuraAbility = Cast<UAuraGameplayAbility>(...))
{
    // 添加 Tag
    GiveAbility(AbilitySpec);
}
```

因此 `StartupAbilities` 中若配置了原生 `UGameplayAbility` 或其他项目能力基类，将不会被授予。这符合“所有项目能力必须继承 UAuraGameplayAbility”的约束，但应明确该约束。

### 12.7 Reliable RPC 的使用边界

`ClientEffectApplied` 使用 `Reliable`，适合不能丢失的少量 UI 消息。但如果未来出现高频周期效果，每次都发送可靠 RPC 可能堵塞可靠通道。

是否保留 Reliable 应根据消息频率决定：

- 拾取提示、关键状态消息：Reliable 合理。
- 每帧或极高频效果：应聚合、节流或改用其他同步方式。

### 12.8 客户端导航的信任边界

`bAllowClientSideNavigation=True` 允许客户端本地计算路径，但不代表客户端拥有最终位置权威。实际移动仍经 `AddMovementInput` 和 CharacterMovement 交给服务器校验。

如果后续加入动态障碍或严格反作弊，需要考虑客户端与服务器 NavMesh 不一致导致的路径偏差和位置修正。

## 十三、知识点总结

### 核心类职责

| 类 | 本次职责 |
|---|---|
| `UAuraGameplayAbility` | 提供能力初始输入标签 |
| `FGameplayAbilitySpec` | 保存运行时 DynamicAbilityTags 和输入状态 |
| `UAuraAbilitySystemComponent` | 按 InputTag 查找、通知并尝试激活能力 |
| `AAuraPlayerController` | 分流技能/移动意图，生成路径并执行 AutoRun |
| `UNavigationSystemV1` | 计算起点到目标点的导航路径 |
| `USplineComponent` | 根据路径点提供平滑移动方向 |
| `UCharacterMovementComponent` | 执行预测、复制和服务器校验的角色移动 |
| `UAuraProjectileSpell` | 在服务器生成投射物 |
| `AAuraProjectile` | 承载投射物碰撞和移动 |
| `ICombatInterface` | 向技能统一提供战斗插槽位置 |

### 核心设计思想

1. **能力类提供默认值，AbilitySpec 保存运行时状态。**
2. **输入与能力通过 GameplayTag 解耦。**
3. **按下意图被锁定，避免 Held 过程中技能和移动互相跳变。**
4. **Navigation 负责规划，Spline 负责方向，CharacterMovement 负责执行和联网。**
5. **GameplayEffect 的个人 UI 消息通过 Client RPC 送到拥有客户端。**
6. **投射物由服务器生成并复制，避免重复实体和伤害作弊。**
7. **CombatInterface 隔离技能与具体角色类型。**
8. **SpawnActorDeferred 为伤害 Spec 等运行时数据预留注入时机。**

### 一句话总结

> 本次提交把 `InputTag → AbilitySpec → TryActivateAbility` 的技能输入链正式接通，同时用“导航路径 + Spline + AddMovementInput”完成支持客户端预测的多人自动寻路，并建立了“服务器从武器插槽延迟生成可复制投射物”的首个攻击技能骨架。
