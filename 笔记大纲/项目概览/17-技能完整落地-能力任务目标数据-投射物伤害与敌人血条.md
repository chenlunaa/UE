## 一、整体目标与主线

第10章结束时，我们已经能做到：输入 Tag → ASC 激活 `UAuraProjectileSpell` → 服务器从武器插槽生成一颗**只会飞行**的火球。本章把它补成一套真正完整的技能：

1. **能力任务的原理**：用“播放蒙太奇并等待”剖析 AbilityTask 的底层机制。
2. **蒙太奇中的时机**：用自定义动画通知发 `GameplayEvent`，配合 `WaitGameplayEvent` 在动画的指定点才生成火球。
3. **目标数据**：自己写一个 `UTargetDataUnderMouse` 能力任务，把鼠标光标命中位置从客户端可靠地送到服务器（目标数据复制 + 预测密钥）。
4. **方向与朝向**：让火球朝点击位置飞行，让角色用 Motion Warping 转向目标，并通过 `ICombatInterface` 解耦。
5. **命中反馈**：Niagara 爆炸特效、命中音效、循环音效、生命周期与碰撞通道。
6. **伤害**：火球携带 `FGameplayEffectSpecHandle`，命中后把 `GE_Damage` 应用到目标。
7. **UI**：给敌人加头顶血条——WidgetComponent + WidgetController（敌人自己）+ 属性变化委托，再做幽灵条和计时器隐藏。

## 二、总览：从创建 Ability 到命中目标再到 UI 的完整链路

本章的核心是一条从“创建能力”到“能力生效”的完整管线，建议以后回顾时先看这张图：

```text
【一、创建与授予】
  继承 UGameplayAbility 写 C++ 类（UAuraProjectileSpell）
        ↓ 创建蓝图 GA_FireBolt，ClassDefaults 配置
   ProjectileClass = BP_Projectile
   DamageEffectClass = GE_Damage
   （输入 Tag 由能力初始标签提供）
        ↓
   ASC::GiveAbility(FGameplayAbilitySpec)   —— 第10章已完成

【二、输入驱动激活】
  InputAction(Shift/鼠标) → IMC → UAuraInputComponent::BindAbilityActions
        ↓
  AAuraPlayerController::AbilityInputTagHeld/Pressed/Released
        ↓ 左键且 (bTargeting || bShiftKeyDown)
  UAuraAbilitySystemComponent::AbilityInputTagHeld → TryActivateAbility
        ↓
  UAuraProjectileSpell::ActivateAbility —— 真正开始执行技能

【三、目标数据（本章核心）】
  ActivateAbility 中创建 UTargetDataUnderMouse
        ↓
  本地：GetHitResultUnderCursor → 打包成 SingleTargetHit → 广播 ValidData
        ↓ 同时
  ServerSetReplicatedTargetData(SpecHandle, PredictionKey, DataHandle, ...)
        ↓ RPC
  服务器：TargetDataSetDelegate 触发 → 回调中 Consume 缓存 → 广播 ValidData
        ↓
  蓝图拿到 DataHandle → GetHitResultFromTargetData → 命中位置

【四、动画节奏】
  播放蒙太奇 AM_FireBolt（Motion Warping 使角色转向目标）
        ↓
  蒙太奇内自定义通知 AN_MontageEvent
   → SendGameplayEventToActor(Owner, Event.Montage.FireBolt)
        ↓
  WaitGameplayEvent(Event.Montage.FireBolt) 的 EventReceived 触发
        ↓
  调用 SpawnProjectile(ProjectileTargetLocation)   —— 仅服务器

【五、投射物与伤害】
  SpawnActorDeferred(ProjectileClass, 目标方向旋转)
   MakeOutgoingSpec(DamageEffectClass, 等级) → 存入 DamageEffectSpecHandle
   FinishSpawning
        ↓
  飞行 → 球体重叠（WorldStatic/WorldDynamic/Pawn）
        ↓ 服务器
  播放命中特效/音效 → 目标 ASC ApplyGameplayEffectSpecToSelf → 扣血 → Destroy
        ↓ 属性变化
  AttributeSet::PostGameplayEffectExecute 钳制生命值

【六、UI 反馈】
  ASC 属性变化委托 → 敌人广播 OnHealthChanged/OnMaxHealthChanged
        ↓
  WBP_EnemyHealthBar（WidgetController = 敌人自身）
   → 绑定委托 → health / maxHealth → SetPercent
        ↓
  幽灵条插值跟随 + 一段时间不更新后自动隐藏
```

一句话概括本章：**用能力任务解决“何时拿数据、何时执行”，用目标数据复制解决“数据怎么到服务器”，用投射物 Actor 承载表现与伤害，用 WidgetController + 委托解决“属性变化怎么画到 UI”。**

## 三、AbilityTask 能力任务原理（11.1）

### 3.1 能力任务是什么

AbilityTask（能力任务）是 GameplayAbility 雇用的“工作者”，用来执行**异步**步骤：播放蒙太奇、等待事件、等待目标数据等。它可以即时完成，也可以跨越一段时间。

蓝图里看到的一类带“时钟”图标的延迟节点，底层就是能力任务。典型例子：`PlayMontageAndWait`（播放蒙太奇并等待）。

### 3.2 PlayMontageAndWait 的输出执行引脚

它有多个输出执行引脚，对应不同的蒙太奇时机：

| 引脚 | 触发时机 |
|---|---|
| 常规输出（顶部） | 节点一到达就立即执行（不等待） |
| OnCompleted | 蒙太奇播放完成并淡出 |
| OnBlendOut | 蒙太奇开始淡出且未被中断（可能早于 Completed） |
| OnInterrupted | 蒙太奇被中断 |
| OnCancelled | 蒙太奇被取消 |
| OnNotifyBegin / OnNotifyEnd | 播放蒙太奇通知窗口的开始/结束 |

### 3.3 底层机制：能力任务为什么是“异步蓝图节点”

以 `UAbilityTask_PlayMontageAndWait` 为例，剖析其实现套路（这就是**以后写任何自定义能力任务都要模仿的模板**）：

1. 类里声明多个**委托变量**（如 `OnCompleted`、`OnBlendOut`、`OnInterrupted`、`OnCancelled`）——每个 `UPROPERTY(BlueprintAssignable)` 委托都会变成蓝图节点的一个输出执行引脚。
2. 提供一个**静态工厂函数**，例如 `CreatePlayMontageAndWaitProxy`：
   - 返回当前类类型的指针；
   - `meta = (DisplayName="PlayMontageAndWait", HidePin="OwningAbility", DefaultToSelf="OwningAbility", BlueprintInternalUseOnly="true")`——蓝图节点隐藏 OwningAbility 引脚并默认传 self；
   - 函数体内用 `NewAbilityTask<UAbilityTask_PlayMontageAndWait>(OwningAbility)` 创建实例并设置参数后返回。
3. 重写 `Activate()`：任务被激活时立即执行，通常是调用 `AbilitySystemComponent->PlayMontage(...)`，并把类里的委托绑定到各种回调（蒙太奇淡出、中断、完成、取消）。
4. 引擎在对应时机**广播委托**，蓝图里连到这些输出引脚的分支就会执行。

能力任务还天然拥有 `Ability`（所属能力）和 `AbilitySystemComponent`（所属 ASC）两个成员，因此能方便地拿到角色、玩家控制器、蒙太奇等上下文。

> 本章先看透这一个任务，后面自己写 `TargetDataUnderMouse` 时完全复用这套模式。

## 四、蒙太奇事件：动画通知 + WaitGameplayEvent（11.2、11.3）

目标：不再“激活技能瞬间就生成火球”，而是**等蒙太奇播到某个特定帧再生成**。

### 4.1 思路

```text
蒙太奇到达指定帧
    ↓ 自定义动画通知（AnimNotify）
发送游戏事件 SendGameplayEventToActor(Owner, EventTag, Payload)
    ↓
能力中的 WaitGameplayEvent(EventTag) 收到 → 执行对应分支
    ↓
调用 SpawnProjectile()
```

### 4.2 新建事件 Tag

在项目设置 → Gameplay Tags 里新增 `Event.Montage.FireBolt`（提交里同步进了 `Config/DefaultGameplayTags.ini`）。事件用 Tag 标识，便于区分“发射火球”“攻击命中”等不同事件。

### 4.3 自定义动画通知 AN_MontageEvent

新建蓝图类，父类选 `AnimNotify`，重写 `Received Notify`：

1. `GetOwner` 拿到网格体所属 Actor（即施法角色）；
2. 调用能力系统蓝图库的 **Send Gameplay Event To Actor**；
3. 目标传 Owner，Tag 传一个暴露成变量的 `EventTag`（在蒙太奇里可配置成 `Event.Montage.FireBolt`）；
4. Payload 是 `FGameplayEventData` 结构，可以携带施动者、目标、强度、TargetData 等大量附加信息——本阶段只传 Tag。

然后把通知加到蒙太奇 AM_FireBolt 的对应时间点，并把变量设为 `Event.Montage.FireBolt`。

### 4.4 能力里等待事件

能力蓝图 GA_FireBolt 中：

1. 播放蒙太奇并等待（`PlayMontageAndWait`）；
2. 同时挂 `WaitGameplayEvent` 节点，指定 `Event.Montage.FireBolt`；
3. 事件接收引脚触发后执行后续逻辑。

### 4.5 把“生成”从 ActivateAbility 挪到蓝图可调用函数（11.3 任务）

生成时机不应该绑死在 `ActivateAbility` 里，所以把它改成独立的 `BlueprintCallable` 函数：

```cpp
// AuraProjectileSpell.h
UFUNCTION(BlueprintCallable, Category = "Projectile")
void SpawnProjectile(const FVector& ProjectileTargetLocation);
```

第一步先做成无参版，把原来 `ActivateAbility` 里的生成代码剪过来，并把“是否服务器”的判断改成：

```cpp
if (!GetAvatarActorFromActorInfo()->HasAuthority()) return;
```

随后蓝图里把 `WaitGameplayEvent` 的事件接收引脚接到 `SpawnProjectile` 上，即可实现“动画播到通知点 → 事件 → 生成火球”。生成后手动 `EndAbility` 可以重复施法（但要注意：服务器端立即结束会取消能力，11.9 里会再处理）。

## 五、自定义能力任务 TargetDataUnderMouse（11.4）

问题：火球虽然会在事件点生成，但**不知道朝哪飞**——因为没有任何“点击位置”数据进入能力。本节自己写一个能力任务，让能力拿到鼠标光标下的命中结果。

### 5.1 创建类与工厂函数

在 `AbilitySystem/AbilityTasks` 下新建 `UTargetDataUnderMouse : UAbilityTask`，完全复刻 3.3 的模板：

```cpp
// TargetDataUnderMouse.h
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FMouseTargetDataSignature,
                                            const FGameplayAbilityTargetDataHandle&, DataHandle);

UCLASS()
class AURA_API UTargetDataUnderMouse : public UAbilityTask
{
	GENERATED_BODY()
public:
	UFUNCTION(BlueprintCallable, Category = "Ability|Tasks",
		meta = (DisplayName = "TargetDataUnderMouse",
			HidePin = "OwningAbility",
			DefaultToSelf = "OwningAbility",
			BlueprintInternalUseOnly = "true"))
	static UTargetDataUnderMouse* CreateTargetDataUnderMouse(UGameplayAbility* OwningAbility);

	UPROPERTY(BlueprintAssignable)
	FMouseTargetDataSignature ValidData;   // 蓝图里的输出执行引脚

private:
	virtual void Activate() override;
	void SendMouseCursorData();
	void OnTargetDataReplicatedCallback(const FGameplayAbilityTargetDataHandle& DataHandle,
	                                    FGameplayTag ActivationTag);
};
```

```cpp
// TargetDataUnderMouse.cpp
UTargetDataUnderMouse* UTargetDataUnderMouse::CreateTargetDataUnderMouse(UGameplayAbility* OwningAbility)
{
	UTargetDataUnderMouse* MyObj = NewAbilityTask<UTargetDataUnderMouse>(OwningAbility);
	return MyObj;
}
```

### 5.2 第一版 Activate：只取本地数据

```cpp
void UTargetDataUnderMouse::Activate()
{
	APlayerController* PC = Ability->GetCurrentActorInfo()->PlayerController.Get();
	FHitResult CursorHit;
	PC->GetHitResultUnderCursor(ECC_Visibility, false, CursorHit);
	ValidData.Broadcast(CursorHit.ImpactPoint);  // 第一版委托广播 FVector
}
```

能力里挂上这个节点后，从 `ValidData` 拖出绘制调试球体，本地（拥有客户端）位置完全正确。

### 5.3 暴露的问题：服务器拿不到数据

两人联机测试：客户端点击，本地调试球体位置正确，**服务器上的调试球体出现在世界原点（全零）**。原因：

- 鼠标位置只有本地客户端知道；
- 能力有复制，服务器也会调用 `Activate()`，但服务器上 `GetHitResultUnderCursor` 没有有效命中；
- 本地数据不会自动送到服务器。

结论：需要一个可靠的“客户端 → 服务器”目标数据传输机制，这就是下一节的 **目标数据复制**。

## 六、目标数据复制到服务器（11.5~11.7）

### 6.1 为什么不能只用普通 RPC（11.5）

设想客户端激活能力任务后：

```text
能力激活复制到服务器（需要时间 ε）
         vs
客户端 RPC 发送数据到服务器（需要时间 δ）
```

**ε 与 δ 谁大谁小无法保证**：可能服务器的 `Activate()` 先跑（此时数据还没到），也可能数据先到（此时委托还没绑定，广播被错过）。所以 GAS 内置了一套完整的目标数据机制来解决这个竞态。

### 6.2 GAS 内置目标数据结构

- `FGameplayAbilityTargetData`：所有目标数据的父类；
- `FGameplayAbilityTargetData_SingleTargetHit`：封装单次 `FHitResult`，正是本技能需要的；
- `FGameplayAbilityTargetDataHandle`：目标数据的“句柄/容器”，跨网络传输的就是它；
- ASC 内部有 `AbilityTargetDataMap`：以 `AbilitySpecHandle + PredictionKey` 为键缓存到达服务器的目标数据。

### 6.3 客户端一侧：发送数据（11.6）

`Activate()` 里先判断是否本地控制，本地才采集并发送：

```cpp
void UTargetDataUnderMouse::Activate()
{
	const bool bIsLocallyControlled = Ability->GetCurrentActorInfo()->IsLocallyControlled();
	if (bIsLocallyControlled)
	{
		SendMouseCursorData();
	}
	else
	{
		// 服务器侧：绑定委托并等待数据，见 6.4
	}
}

void UTargetDataUnderMouse::SendMouseCursorData()
{
	FScopedPredictionWindow ScopedPrediction(AbilitySystemComponent.Get());

	APlayerController* PC = Ability->GetCurrentActorInfo()->PlayerController.Get();
	FHitResult CursorHit;
	PC->GetHitResultUnderCursor(ECC_Visibility, false, CursorHit);

	FGameplayAbilityTargetDataHandle DataHandle;
	FGameplayAbilityTargetData_SingleTargetHit* Data = new FGameplayAbilityTargetData_SingleTargetHit();
	Data->HitResult = CursorHit;
	DataHandle.Add(Data);

	AbilitySystemComponent->ServerSetReplicatedTargetData(
		GetAbilitySpecHandle(),
		GetActivationPredictionKey(),
		DataHandle,
		FGameplayTag(),
		AbilitySystemComponent->ScopedPredictionKey);

	if (ShouldBroadcastAbilityTaskDelegates())
	{
		ValidData.Broadcast(DataHandle);   // 本地立即广播，客户端马上能画调试球体
	}
}
```

要点：

- **`FScopedPredictionWindow`**：一个作用域预测窗口，窗口内执行的本地操作都被视为“预测”，服务器稍后确认。后续调用 `ServerSetReplicatedTargetData` 时会把窗口内的 `ScopedPredictionKey` 一并带上。
- **`ServerSetReplicatedTargetData`**：客户端 → 服务器的 RPC，参数为 SpecHandle、激活预测密钥、数据句柄、应用标签、当前作用域预测密钥。
- **`ShouldBroadcastAbilityTaskDelegates()`**：广播前检查能力是否仍激活，避免能力已结束时还在广播。
- 委托从广播 `FVector` 改为广播 `const FGameplayAbilityTargetDataHandle&`，蓝图里可再拆出命中结果。

### 6.4 服务器一侧：接收数据（11.7）

```cpp
// Activate() 的 else 分支
const FGameplayAbilitySpecHandle SpecHandle = GetAbilitySpecHandle();
const FPredictionKey ActivationPredictionKey = GetActivationPredictionKey();

AbilitySystemComponent.Get()->AbilityTargetDataSetDelegate(SpecHandle, ActivationPredictionKey)
	.AddUObject(this, &UTargetDataUnderMouse::OnTargetDataReplicatedCallback);

const bool bCalledDelegate =
	AbilitySystemComponent.Get()->CallReplicatedTargetDataDelegatesIfSet(SpecHandle, ActivationPredictionKey);
if (!bCalledDelegate)
{
	SetWaitingOnRemotePlayerData();   // 数据还没到，通知 ASC 我们仍在等待
}
```

三个关键调用：

| 调用 | 作用 |
|---|---|
| `AbilityTargetDataSetDelegate(...)` | 拿到该 Spec + 预测键对应的“数据已到达”委托并绑定回调 |
| `CallReplicatedTargetDataDelegatesIfSet(...)` | 如果数据**已经先到**（委托广播发生在绑定前），立即补调一次回调，解决竞态 |
| `SetWaitingOnRemotePlayerData()` | 数据未到，让 ASC 知道能力任务在等待远程数据 |

数据到达后的回调：

```cpp
void UTargetDataUnderMouse::OnTargetDataReplicatedCallback(
	const FGameplayAbilityTargetDataHandle& DataHandle, FGameplayTag ActivationTag)
{
	AbilitySystemComponent->ConsumeClientReplicatedTargetData(GetAbilitySpecHandle(),
	                                                          GetActivationPredictionKey());
	if (ShouldBroadcastAbilityTaskDelegates())
	{
		ValidData.Broadcast(DataHandle);
	}
}
```

`ConsumeClientReplicatedTargetData` 会从 `AbilityTargetDataMap` 里清掉这条缓存，告诉 ASC“数据已接收，不用再缓存”。

### 6.5 关键一步：InitGlobalData()（11.7 必踩的坑）

不做这一步，一旦使用目标数据，客户端会直接断线，日志报错：

> “找不到 GameplayAbilityTargetData_SingleTargetHit 和脚本结构缓存”（ScriptStructCache 未初始化）

修复：在 AssetManager 的初始化里调用全局数据初始化：

```cpp
void UAuraAssetManager::StartInitialLoading()
{
	Super::StartInitialLoading();
	FAuraGameplayTags::InitializeNativeGameplayTags();
	UAbilitySystemGlobals::Get().InitGlobalData();   // 初始化目标数据脚本结构缓存等
}
```

之后联机测试：客户端点击 → 服务器也能在正确位置画出调试球体。目标数据（仅一个命中结果）成功从客户端送达服务器。

<a id="section-7"></a>
## 七、GAS 预测机制速览（11.8）

本章用了 `FScopedPredictionWindow` 和 `PredictionKey`，视频用一节专门讲清预测原理：

### 7.1 为什么需要预测

- 多人游戏中服务器应拥有权威，但若每次操作都等服务器回包，操作到反馈会有明显延迟；
- **预测** = 客户端先行执行（移动、开火、扣蓝等），同时把变更报告给服务器；
- 服务器校验合法性，合法则接受，不合法则**回滚**客户端已执行的部分。

### 7.2 预测密钥（FPredictionKey）

- 一个唯一标识符，客户端预测性操作时生成，随 RPC 发给服务器；
- 客户端把本地操作的副作用与密钥关联；服务器把自身生成的副作用也关联到同一密钥并回传；
- 服务器只把确认/拒绝结果返回给**最初发起该密钥的那个客户端**，其他客户端拿到的是无效密钥；
- 预测窗口（Prediction Window）：窗口期间客户端无需请求许可即可执行状态变更。

### 7.3 能力激活的预测链路

```text
客户端 TryActivateAbility
    ↓ 生成新 PredictionKey
    ↓ ServerTryActivateAbility(RPC)  ← 客户端不等回包，直接继续
    ↓ 用该密钥调用 ActivateAbility（标记激活信息）
    ↓ 产生副作用（GE、属性修改、Tag 修改、GameplayCue）
服务器：判断激活有效/无效
    ├─ 失败 → ClientActivateAbilityFailed → 客户端结束能力并撤销副作用
    └─ 成功 → ClientActivateAbilitySucceeded → 客户端保留副作用
```

副作用（GameplayEffect）被预测时：本地立即应用效果，服务器确认后通过复制回来的数据比对密钥，若已有相同密钥的相同效果则**跳过重复应用**。

> GAS 预测能力激活、事件触发、GE 应用（含属性修改）；但**不预测** GE 移除和周期效果。本章只要求理解原理，细节可参考引擎的 `GamePrediction.h` 注释。

## 八、投射物方向与角色转向（11.9、11.10）

### 8.1 让火球飞向点击位置（11.9）

`SpawnProjectile` 增加目标位置参数：

```cpp
void UAuraProjectileSpell::SpawnProjectile(const FVector& ProjectileTargetLocation)
{
	if (!GetAvatarActorFromActorInfo()->HasAuthority()) return;
	ICombatInterface* CombatInterface = Cast<ICombatInterface>(GetAvatarActorFromActorInfo());
	if (CombatInterface)
	{
		const FVector SocketLocation = CombatInterface->GetCombatSocketLocation();
		FRotator Rotator = (ProjectileTargetLocation - SocketLocation).Rotation();
		Rotator.Pitch = 0.f;   // 火球平行于地面飞行

		FTransform SpawnTransform;
		SpawnTransform.SetLocation(SocketLocation);
		SpawnTransform.SetRotation(Rotator.Quaternion());

		AAuraProjectile* Projectile = GetWorld()->SpawnActorDeferred<AAuraProjectile>(
			ProjectileClass, SpawnTransform,
			GetOwningActorFromActorInfo(), Cast<APawn>(GetOwningActorFromActorInfo()),
			ESpawnActorCollisionHandlingMethod::AlwaysSpawn);
		// ……设置伤害 SpecHandle（见第十一节）……
		Projectile->FinishSpawning(SpawnTransform);
	}
}
```

旋转 = `(目标位置 - 插槽位置)` 的向量转成 `FRotator`，再把 Pitch 置零（可选：以后想加弹道可以设 25°~35° 配合重力）。

蓝图里：`TargetDataUnderMouse → ValidData → GetHitResultFromTargetData → 位置 → SpawnProjectile(位置)`。

### 8.2 修复：不要一生成就 EndAbility

如果事件接收后立刻 `EndAbility`，服务器端会马上取消能力，导致“客户端看着生成了，服务器却没生成/无法再次激活”。本章的做法是去掉立即结束节点（或加延迟后再结束），保证服务器完整执行。

### 8.3 Shift 键强制施法（11.9）

原来的逻辑只有鼠标**悬停在敌人上**才会放火球。新增“按住 Shift + 左键 = 朝任意点击位置放火球”：

1. 新建一维轴输入动作 `IA_Shift`，在 IMC 里绑定左/右 Shift 键；
2. PlayerController 增加 `ShiftAction`，绑定 Started → `ShiftPressed`、Completed → `ShiftReleased`，维护 `bShiftKeyDown`；
3. `AbilityInputTagHeld` 中左键分支改为：`if (bTargeting || bShiftKeyDown)` 才把输入交给 ASC，否则按移动处理；
4. `AbilityInputTagReleased` 中只有 `!bTargeting && !bShiftKeyDown` 才走短按寻路。

### 8.4 修复摄像机被角色挡住（11.9 顺带）

走近其他角色时镜头拉近，是因为胶囊体和网格默认**阻挡摄像机**。在 `AAuraCharacterBase` 构造函数修复：

```cpp
GetCapsuleComponent()->SetCollisionResponseToChannel(ECC_Camera, ECR_Ignore);
GetMesh()->SetCollisionResponseToChannel(ECC_Camera, ECR_Ignore);
```

### 8.5 Motion Warping 让角色转向（11.10）

#### 启用与配置

1. 编辑器 → 插件 → 启用 **Motion Warping**（测试版，发布项目慎用），重启编辑器；
2. 给角色蓝图（BP_AuraCharacter）添加 **MotionWarping 组件**；
3. 蒙太奇 AM_FireBolt 新建 Motion Warp 通知轨道：
   - 根运动修饰器选 **Aim Offset（倾斜扭曲）**；
   - 扭曲目标命名 `FacingTarget`（名称任意但后面必须一致）；
   - 关闭位置扭曲，保留旋转扭曲；旋转类型选 **面向方向**（Facing Direction）；
   - 窗口从动画开头延伸到发射事件前。

#### CombatInterface 解耦

一开始直接在能力蓝图里 Cast 到 BP_AuraCharacter 调用转向事件，能跑但耦合角色类型。任务要求改成接口：

```cpp
// CombatInterface.h
UINTERFACE(MinimalAPI, BlueprintType)   // 必须 BlueprintType，蓝图才能 Cast
class UCombatInterface : public UInterface { GENERATED_BODY() };

class AURA_API ICombatInterface
{
	GENERATED_BODY()
public:
	virtual int32 GetPlayerLevel();
	virtual FVector GetCombatSocketLocation();

	// 蓝图可实现事件 + 蓝图可调用，不能是虚函数
	UFUNCTION(BlueprintImplementableEvent, BlueprintCallable)
	void UpdateFacingTarget(const FVector& Target);
};
```

踩坑记录（以后照抄）：

- 接口要能被蓝图 Cast，必须 `UINTERFACE(..., BlueprintType)`；
- `BlueprintImplementableEvent` 函数要让蓝图能调用，还要加 `BlueprintCallable`；
- 蓝图实现时连接 `MotionWarpingComponent → AddOrUpdateWarpTargetFromLocation("FacingTarget", Target)`；
- 能力里改为 `Cast<ICombatInterface>(GetAvatarActorFromActorInfo())` 后调用 `UpdateFacingTarget(目标位置)`，不再依赖具体角色类。

结果：服务器端和客户端都能让角色转向目标，且技能与“火球类敌人”等任何实现接口的 Actor 兼容。

### 9.2 BeginPlay

```cpp
	SetLifeSpan(LifeSpan);
	Sphere->OnComponentBeginOverlap.AddDynamic(this, &AAuraProjectile::OnSphereOverride);
	LoopingSoundComponent = UGameplayStatics::SpawnSoundAttached(LoopingSound, GetRootComponent());
}
```

### 9.3 命中逻辑与销毁顺序

关键点是**服务器销毁复制到客户端**和**客户端本地重叠**哪个先发生并不确定，用 `bHit` 标记避免特效丢失或重复：

```cpp
void AAuraProjectile::OnSphereOverride(...)
{
	UGameplayStatics::PlaySoundAtLocation(this, ImpactSound, GetActorLocation(), FRotator::ZeroRotator);
	UNiagaraFunctionLibrary::SpawnSystemAtLocation(this, ImpactEffect, GetActorLocation());
	LoopingSoundComponent->Stop();

	if (HasAuthority())
	{
		// 应用伤害效果（见第十一节）
		Destroy();
	}
	else
	{
		bHit = true;   // 客户端先重叠：标记，等 Destroyed 时不再重复播放
	}
}

void AAuraProjectile::Destroyed()
{
	if (!bHit && !HasAuthority())
	{
		// 服务器销毁先同步过来、客户端还没重叠：在这里补播特效与音效
		UGameplayStatics::PlaySoundAtLocation(this, ImpactSound, GetActorLocation(), FRotator::ZeroRotator);
		UNiagaraFunctionLibrary::SpawnSystemAtLocation(this, ImpactEffect, GetActorLocation());
		LoopingSoundComponent->Stop();
	}
	Super::Destroyed();
}
```

蓝图中把 `BP_Projectile` 的 ImpactEffect 设为火球爆炸 Niagara、ImpactSound 设为火球命中音效、LoopingSound 设为循环嘶嘶声。蒙太奇里再加一条 Play Sound 通知播放发射音效。

> 任务补充：飞行循环音效用 `SpawnSoundAttached` 附加到根组件并保存 `UAudioComponent`，命中/销毁时 `Stop()`；最后给投射物加 15 秒生命周期，防止永不消失。

## 十、投射物碰撞通道（11.12）

### 10.1 遇到的问题

- 火球会**撞上并消耗药水**，还会在药水上爆炸；
- 火球会**直接穿过柱子**等静态物体；
- 需要：穿过拾取物、被世界物体阻挡/重叠、命中敌人爆炸。

### 10.2 自定义碰撞通道 Projectile

项目设置 → 碰撞 → 新建对象通道 `Projectile`，默认响应 **Ignore**（默认忽略，只有显式设置过的类型才响应）。它占用 `ECC_GameTraceChannel1`，在 `Aura.h` 里定义宏：

```cpp
#define ECC_Projectile ECollisionChannel::ECC_GameTraceChannel1
```

`AAuraProjectile` 构造函数配置球体：

```cpp
Sphere->SetCollisionObjectType(ECC_Projectile);
Sphere->SetCollisionEnabled(ECollisionEnabled::QueryOnly);
Sphere->SetCollisionResponseToAllChannels(ECR_Ignore);
Sphere->SetCollisionResponseToChannel(ECC_WorldDynamic, ECR_Overlap);
Sphere->SetCollisionResponseToChannel(ECC_WorldStatic, ECR_Overlap);
Sphere->SetCollisionResponseToChannel(ECC_Pawn, ECR_Overlap);
```

### 10.3 各对象的响应设置

| 对象 | 设置 |
|---|---|
| 药水等拾取物 | 盒体碰撞预设自定义，忽略 Projectile（默认即忽略） |
| 柱子等静态物体 | 勾选“生成重叠事件”，与 Projectile 重叠 |
| 敌人网格 | C++ 中 `GetMesh()->SetCollisionResponseToChannel(ECC_Projectile, ECR_Overlap)` |
| 角色网格 | 同上（以后 PVP 火球互射也能命中） |

`AAuraCharacterBase` 构造函数最终形态：

```cpp
GetCapsuleComponent()->SetCollisionResponseToChannel(ECC_Camera, ECR_Ignore);
GetCapsuleComponent()->SetGenerateOverlapEvents(false);   // 避免与网格重复触发重叠
GetMesh()->SetCollisionResponseToChannel(ECC_Camera, ECR_Ignore);
GetMesh()->SetCollisionResponseToChannel(ECC_Projectile, ECR_Overlap);
GetMesh()->SetGenerateOverlapEvents(true);
```

> 注意：胶囊体关闭生成重叠事件，是为了解决 11.13 里“火区每秒掉两次血”的 bug——角色同时有胶囊和网格两个可重叠组件，效果重叠体积会各触发一次。

## 十一、GameplayEffect 伤害应用（11.13）

### 11.1 占位伤害 GE

创建蓝图 `GE_Damage`（父类 GameplayEffect）：

- 时长策略：**Instant（即时）**；
- 添加一个属性修改器：目标属性 = Health（生命值）、修改方式 = 数值叠加、数值 = -10。

> 这是占位实现，最终伤害会走“元属性（Meta Attribute）→ 计算伤害 → 派生属性”的体系，本章只为跑通链路。

### 11.2 技能类持有伤害 GE 类

```cpp
// AuraProjectileSpell.h
UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)
TSubclassOf<UGameplayEffect> DamageEffectClass;
```

在 GA_FireBolt 的 ClassDefaults 里设置 `DamageEffectClass = GE_Damage`。

### 11.3 生成时创建 Spec 并注入投射物

`SpawnProjectile` 里在 `FinishSpawning` 之前：

```cpp
const UAbilitySystemComponent* SourceASC =
	UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent(GetAvatarActorFromActorInfo());

const FGameplayEffectSpecHandle SpecHandle = SourceASC->MakeOutgoingSpec(
	DamageEffectClass, GetAbilityLevel(), SourceASC->MakeEffectContext());
Projectile->DamageEffectSpecHandle = SpecHandle;

Projectile->FinishSpawning(SpawnTransform);
```

`AAuraProjectile` 提供可生成时注入的句柄：

```cpp
UPROPERTY(BlueprintReadWrite, meta = (ExposeOnSpawn = true))
FGameplayEffectSpecHandle DamageEffectSpecHandle;
```

### 11.4 命中时把效果应用到目标

`OnSphereOverride` 的服务器分支：

```cpp
if (UAbilitySystemComponent* TargetASC =
	UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent(OtherActor))
{
	TargetASC->ApplyGameplayEffectSpecToSelf(*DamageEffectSpecHandle.Data.Get());
}
Destroy();
```

要点：

- `DamageEffectSpecHandle` 是句柄，用 `.Data.Get()` 取出 `FGameplayEffectSpec` 再解引用；
- 只有服务器应用效果，属性变化最终通过复制同步到客户端；
- `ApplyGameplayEffectSpecToSelf`（目标 ASC 视角）等价于“来源 ASC → 目标 ASC”应用，这里用 Self 版即可。

### 11.5 敌人初始化默认属性

火球命中后敌人要能扣血，但此前只有 Aura 角色初始化了属性，敌人没有。临时方案：敌人在 `InitAbilityActorInfo` 里同样调用 `InitializeDefaultAttributes()`（用与 Aura 共享的占位属性 GE：默认主属性、次属性、生命值），并让 `BP_EnemyBase` 设置这些 GE。这样所有敌人出生就有 100 血。

### 11.6 验证

`AuraAttributeSet::PostGameplayEffectExecute` 里健康值变化时打印日志（提交中新增）：

```cpp
UE_LOG(LogTemp, Warning, TEXT("Change Health on %s, Health: %f"),
       *Props.TargetAvatarActor->GetName(), GetHealth());
```

测试结果：击中敌人后生命值 100 → 90 → 80……服务器与客户端日志一致，伤害链路打通。

### 12.1 任务要求


蓝图里把 WidgetComponent 设为屏幕空间、Widget Class 指向血条 Widget，并调整绘制尺寸与垂直偏移。

### 12.3 敌人作为 WidgetController：绑定属性变化

```cpp
void AAuraEnemy::BeginPlay()
{
	Super::BeginPlay();
	InitAbilityActorInfo();

	if (UAuraUserWidget* AuraUserWidget = Cast<UAuraUserWidget>(HealthBar->GetUserWidgetObject()))
	{
		AuraUserWidget->SetWidgetController(this);   // 敌人自己就是控制器
	}

	if (const UAuraAttributeSet* AuraAS = CastChecked<UAuraAttributeSet>(AttributeSet))
	{
		AbilitySystemComponent->GetGameplayAttributeValueChangeDelegate(AuraAS->GetHealthAttribute())
			.AddLambda([this](const FOnAttributeChangeData& Data)
			{
				OnHealthChanged.Broadcast(Data.NewValue);
			});

		AbilitySystemComponent->GetGameplayAttributeValueChangeDelegate(AuraAS->GetMaxHealthAttribute())
			.AddLambda([this](const FOnAttributeChangeData& Data)
			{
				OnMaxHealthChanged.Broadcast(Data.NewValue);
			});

		OnHealthChanged.Broadcast(AuraAS->GetHealth());       // 广播初始值
		OnMaxHealthChanged.Broadcast(AuraAS->GetMaxHealth());
	}
}
```

### 12.4 血条 Widget：WBP_ProgressBar → WBP_EnemyHealthBar

**WBP_ProgressBar（通用父类）**

1. 根节点 SizeBox（`SizeBoxRoot`）：预构造时用参数 `BoxWidth`/`BoxHeight` 调用 `SetWidthOverride/SetHeightOverride`（折叠成 `UpdateBox` 函数），默认 80×6；
2. 内部 Overlay（`OverlayRoot`）叠两个进度条：
   - `ProgressBar_Front`：主血条，红色填充笔刷（`FrontBarFillBrush` 变量，`UpdateFrontFillBrush` 函数设置样式）；
   - `GhostBar`（幽灵条）：半透明去饱和填充笔刷，位于主条之后；
3. 父类函数：
   - `SetBarPercent(Value, MaxValue)`：安全除法 → 设置主条百分比 → 更新幽灵目标 → 显示血条；
   - `UpdateGhostTarget`（自定义事件）：重置隐藏计时器 → 延迟约 1 秒 → 写入 `GhostPercentTarget`；
   - `SetBarVisibility(bool)`：设置可见性并维护 `bBarVisible`；
   - `Event Tick`：`GhostBar->SetPercent(FInterpTo(当前值, GhostPercentTarget, DeltaTime, 速度))`，仅当 `bBarVisible` 时插值；
   - 隐藏计时器：`SetTimerByEvent`（句柄存 `HideTimer`），每次更新先 `ClearAndInvalidateTimer` 再重新设置（约 6 秒），到点隐藏血条。

**WBP_EnemyHealthBar（敌人专用子类）**

`Event Construct` 里：

```text
GetWidgetController
    → Cast<AAuraEnemy>（蓝图中转成 BP_EnemyBase）
    → 序列：
       绑定 OnHealthChanged → 存入 health 变量
       绑定 OnMaxHealthChanged → 存入 maxHealth 变量
    → health / maxHealth（安全除法）→ ProgressBar_Front SetPercent
```

### 12.5 UI 绘制的一般流程（本章总结版）

结合第7~9章 MVC 体系，画任何“由游戏状态驱动的 UI”都遵循这套流程：

1. **准备数据源**：确定要展示的属性（如 Health），确认它在 AttributeSet 里、ASC 会广播变化。
2. **建 Widget 蓝图**：通用控件（如进度条）做父类，具体业务（如敌人血条）做子类；UI 元素全部提升为变量便于设置。
3. **选 WidgetController**：优先复用已有控制器（OverlayWidgetController 管 HUD），场景绑定的控件（敌人头顶血条）可以直接让拥有者（敌人）当控制器——WidgetController 的本质就是“负责广播数据的 UObject”。
4. **C++ 侧广播**：在拥有者上声明 `BlueprintAssignable` 委托，绑定 ASC 的属性变化委托（Lambda/回调），并在初始化时**广播一次初始值**。
5. **Widget 侧绑定**：`Event Construct` 里 `GetWidgetController()` → 类型转换 → 绑定委托 → 用安全除法等计算 → 更新控件（`SetPercent`）。
6. **挂载**：场景型 UI 用 WidgetComponent（屏幕空间 + Draw Size + 偏移）；屏幕型 UI 用 Viewport 添加并绑定到 HUD。
7. **细节优化**：插值/幽灵条、计时器隐藏、可见性分支等表现层逻辑放在 Widget 内部，避免污染游戏逻辑。

## 十五、知识点总结

### 核心类职责

| 类 / 结构 | 本章职责 |
|---|---|
| `UAbilityTask` | 异步工作单元；静态工厂 + 委托输出引脚 + `Activate` 的模板 |
| `UAbilityTask_WaitGameplayEvent` | 等待游戏事件，事件由动画通知发送 |
| `AN_MontageEvent` | 蒙太奇指定帧发送 `Event.Montage.FireBolt` 事件 |
| `UTargetDataUnderMouse` | 自定义能力任务：采集光标命中结果并复制到服务器 |
| `FGameplayAbilityTargetData_SingleTargetHit` / `Handle` | 跨网络传输的目标数据载体 |
| `ServerSetReplicatedTargetData` / `AbilityTargetDataSetDelegate` | 客户端发送 / 服务器接收目标数据的核心 RPC 与委托 |
| `FScopedPredictionWindow` / `FPredictionKey` | 预测窗口与密钥：客户端先行、服务器确认 |
| `AAuraProjectile` | 投射物：碰撞、特效、音效、生命周期、携带伤害 Spec |
| `UAuraProjectileSpell` | 技能类：目标位置旋转、生成投射物、构造伤害 Spec |
| `ICombatInterface` | 解耦技能与角色：武器插槽位置、转向目标 |
| `UWidgetComponent` + `UAuraUserWidget` | 场景挂载 UI 与 WidgetController 容器 |
| `AAuraEnemy` | 敌人：初始化属性、作为血条的 WidgetController 广播委托 |

### 核心设计思想

1. **能力任务三件套**：静态工厂函数、`BlueprintAssignable` 委托引脚、重写 `Activate`——写任何自定义能力任务都照此模式。
2. **动画驱动逻辑**：蒙太奇通知只管“发事件”，能力用 `WaitGameplayEvent` 决定“何时做什么”，解耦动画与逻辑。
3. **目标数据竞态**：`AbilityTargetDataSetDelegate + CallReplicatedTargetDataDelegatesIfSet + SetWaitingOnRemotePlayerData` 三者配合，无论 RPC 先到还是激活先到都不会丢数据。
4. **预测窗口**：预测性操作必须在 `FScopedPredictionWindow` 内进行，服务器端才能通过预测密钥关联并确认。
5. **服务器权威**：生成投射物、应用伤害、销毁投射物都在服务器（`HasAuthority`）；客户端只负责表现与预测。
6. **接口优于具体类**：转向、插槽位置等跨角色能力通过 `ICombatInterface` 提供，技能不依赖任何具体角色蓝图。
7. **Spec 随实体走**：伤害不是“命中瞬间现算”，而是生成时用 `MakeOutgoingSpec` 构造好，随投射物带到目标再应用。
8. **UI 即数据的投影**：属性变化 → 委托广播 → Widget 绑定 → 更新控件；场景 UI 的 WidgetController 可以由拥有者自身承担。

### 一句话总结

> 第11章把火球术补成完整闭环：`AbilityTask（取目标数据）→ 目标数据复制（客户端→服务器）→ 动画事件（定时生成）→ 服务器生成携带 GE Spec 的投射物 → 命中应用伤害 → 属性变化广播 → 敌人头顶血条/幽灵条刷新`，同时把自定义能力任务、目标数据复制、预测密钥、碰撞通道、GE 应用和 WidgetController 六套机制全部串了起来。
