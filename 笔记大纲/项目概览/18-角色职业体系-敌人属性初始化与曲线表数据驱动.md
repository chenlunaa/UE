## 一、整体目标与主线

第11章结束时，敌人只是用与 Aura 相同的“默认属性 GE”占位初始化，伤害 GE 也只是直接减 10 血。本章解决第一个问题：**让不同职业、不同等级的敌人拥有不同的初始属性**。

主线分四步：

1. **定义职业**：`ECharacterClass` 枚举（元素师 Elementalist、战士 Warrior、游侠 Ranger）。
2. **建数据资产**：`UCharacterClassInfo` 保存每个职业的主属性 GE，以及所有职业共享的次级、生命属性 GE。
3. **按等级缩放**：每个职业一张主属性曲线表（Strength / Intelligence / Resilience / Vigor 四条曲线），用修饰符的“可缩放浮点”按等级取值；并学习用 CSV / JSON 批量制作曲线表。
4. **集中应用**：数据资产放在 GameMode 里，`UAuraAbilitySystemLibrary::InitializeDefaultAttributes` 统一读取并应用三个 GE，敌人重写初始化函数完成接入。

## 二、总览：数据驱动的敌人属性初始化链路

```text
【数据准备】
  DA_CharacterClassInfo（UCharacterClassInfo 数据资产）
   ├── CharacterClassInformation: TMap<ECharacterClass, FCharacterClassDefaultInfo>
   │     ├── Elementalist → PrimaryAttributes = GE_PrimaryAttributes_Elementalist
   │     ├── Warrior    → PrimaryAttributes = GE_PrimaryAttributes_Warrior
   │     └── Ranger     → PrimaryAttributes = GE_PrimaryAttributes_Ranger
   ├── SecondaryAttributes = GE_SecondaryAttributes_Enemy（共享）
   └── VitalAttributes     = GE_VitalAttributes（共享）

【曲线表（CT_PrimaryAttributes_<职业>）】
  Strength / Intelligence / Resilience / Vigor 四条曲线
   x 轴 = 等级（1/5/10/15/20/40 稀疏关键帧 + Cubic 平滑）
   ↓ 被主属性 GE 的 4 个修饰符引用（Scalable Float，Magnitude=1）

【运行时】
  AAuraGameModeBase::CharacterClassInfo  ← 蓝图里指向 DA_CharacterClassInfo
        ↓
  AAuraEnemy::InitializeDefaultAttributes()（重写基类虚函数）
   → UAuraAbilitySystemLibrary::InitializeDefaultAttributes(this, CharacterClass, Level, ASC)
        ↓
  GetGameMode → CharacterClassInfo → GetClassDefaultInfo(CharacterClass)
        ↓ 依次应用三个 GE（都带等级、都 AddSourceObject(AvatarActor)）
  PrimaryAttributes → SecondaryAttributes → VitalAttributes
        ↓
  敌人出生即拥有符合职业与等级的属性
```

一句话概括：**职业决定“用哪张曲线表”，等级决定“曲线上的取值”，GameMode 集中存放数据，蓝图库统一负责把数据变成 GE 应用到自己身上。**

## 三、规划：职业、数据资源与效果体系（12.1）

### 3.1 RPG 职业（Class）不是编程类

职业是 RPG 概念：不同职业有各自的优势与弱点。本课程规划三个：

| 职业 | 定位 |
|---|---|
| 战士 Warrior | 近战（挥剑、长矛突刺），力量成长高 |
| 游侠 Ranger | 远程（弹弓等），力量/韧性均衡偏高 |
| 元素师 Elementalist | 魔法法术，智力成长高（Aura 本人就是元素师） |

### 3.2 需要哪些数据与机制

1. 枚举 `ECharacterClass` 区分职业；
2. 数据资源 `CharacterClassInfo` 存储每个职业的默认属性数据；
3. 曲线表：每个主属性一条“等级 → 属性值”曲线，每个职业一张表；
4. GameplayEffect：
   - 主属性 GE（每职业一个）；
   - 次级属性 GE（所有职业共享）；
   - 生命（核心）属性 GE（共享）；
5. 敌人共有的能力数组、共享效果数组、每个敌人独特的技能数组（本章先建结构，暂留空）；
6. 一个初始化函数（放进 `AuraAbilitySystemLibrary`），接收数据资源、ASC、等级，应用所有初始 GE。

## 四、CharacterClassInfo 数据资产（12.2）

### 4.1 枚举与结构体

```cpp
// CharacterClassInfo.h（AbilitySystem/Data 目录）
UENUM(BlueprintType)
enum class ECharacterClass : uint8
{
	Elementalist,   // 元素师
	Warrior,        // 战士
	Ranger          // 游侠
};

USTRUCT(BlueprintType)
struct FCharacterClassDefaultInfo
{
	GENERATED_BODY()

	UPROPERTY(EditDefaultsOnly, Category = "Class Defaults")
	TSubclassOf<UGameplayEffect> PrimaryAttributes;   // 每个职业单独的主属性 GE
};
```

### 4.2 数据资产类

```cpp
UCLASS()
class AURA_API UCharacterClassInfo : public UDataAsset
{
	GENERATED_BODY()
public:
	// 职业 → 该职业默认信息（主属性 GE）
	UPROPERTY(EditDefaultsOnly, Category = "Character Class Defaults")
	TMap<ECharacterClass, FCharacterClassDefaultInfo> CharacterClassInformation;

	// 所有职业共享
	UPROPERTY(EditDefaultsOnly, Category = "Common Class Defaults")
	TSubclassOf<UGameplayEffect> SecondaryAttributes;

	UPROPERTY(EditDefaultsOnly, Category = "Common Class Defaults")
	TSubclassOf<UGameplayEffect> VitalAttributes;

	FCharacterClassDefaultInfo GetClassDefaultInfo(ECharacterClass CharacterClass);
};
```

```cpp
// CharacterClassInfo.cpp
FCharacterClassDefaultInfo UCharacterClassInfo::GetClassDefaultInfo(ECharacterClass CharacterClass)
{
	return CharacterClassInformation.FindChecked(CharacterClass);
}
```

要点：

- 用 `TMap<ECharacterClass, FCharacterClassDefaultInfo>` 做“职业 → 信息”映射，便于蓝图逐键配置；
- `GetClassDefaultInfo` 用 `FindChecked`：找不到会触发断言，尽早暴露配置错误；
- 次级/生命属性放在数据资产顶层（Common Class Defaults），因为所有职业共享。

### 4.3 蓝图创建 DA_CharacterClassInfo

在能力系统/数据目录下创建杂项 → Data Asset，类型选 `CharacterClassInfo`，命名 `DA_CharacterClassInfo`。

填 TMap 时注意一个编辑器细节：**TMap 默认会预置一个默认键（Elementalist），此时再点加号会提示“无法添加新键，因为已存在默认值键”**。正确做法是先把默认键改成 Warrior / Ranger，再逐个添加其余职业，最后得到 Elementalist / Warrior / Ranger 三个条目。

## 五、GameplayEffect 的整理与创建（12.3）

### 5.1 资源目录整理

默认属性 GE 原本是 Aura 专用（AA_ 前缀），本章把目录拆开：

```text
内容/蓝图/能力系统/游戏效果/默认属性/
  ├── Aura/      ← Aura 专用的 GE（AA_SecondaryAttributes 等）
  └── Enemies/   ← 敌人专用的 GE（GE_PrimaryAttributes_* 等）
```

### 5.2 创建各职业主属性 GE

三个 Instant GE：

- `GE_PrimaryAttributes_Elementalist`
- `GE_PrimaryAttributes_Warrior`
- `GE_PrimaryAttributes_Ranger`

本章先建空壳（没有修饰符），下一节再配曲线表修饰符。

### 5.3 共享的次级与生命属性 GE

- 原 `AA_SecondaryAttributes` 重命名为 `GE_SecondaryAttributes`（供 Aura 使用，Infinite）；
- 原 `AA_VitalAttributes` 重命名为 `GE_VitalAttributes`（共享）；
- **敌人专用**：复制一份 `GE_SecondaryAttributes_Enemy`，把时长从 Infinite 改成 **Instant**。

为什么敌人不用 Infinite：Aura 的主属性会在运行时变化，所以次级属性必须用 Infinite GE 持续跟随主属性重算；而本项目敌人主属性初始化后不再改变，用 Instant 一次性算好即可，省去持续效果的负担。

> 如果以后想让敌人也能升级/改主属性，就给它也用 Infinite 版本。

### 5.4 在 DA_CharacterClassInfo 中分配

- 三个职业的 PrimaryAttributes 分别指向对应的 `GE_PrimaryAttributes_*`；
- SecondaryAttributes = `GE_SecondaryAttributes_Enemy`；
- VitalAttributes = `GE_VitalAttributes`。

## 六、曲线表：按等级缩放的主属性（12.4）

### 6.1 为什么用曲线表

主属性 GE 的修饰符强度要“随等级缩放”。曲线表天然适合：x 轴当等级、y 轴当属性值，生成敌人时用指定等级查曲线得到强度。注意：**曲线表 x 轴默认显示为“秒”，但只是单位标签，完全可以当等级用**。

### 6.2 插值类型

| 插值类型 | 行为 |
|---|---|
| Linear 线性 | 关键帧之间直线连接 |
| Cubic 三次 | 关键帧之间平滑曲线（默认偏好，曲线更自然） |
| Constant 常量 | 无插值，阶梯状跳变 |

### 6.3 制作 CT_PrimaryAttributes_Elementalist

1. 新建曲线表（Curve Table，选 Cubic），命名 `CT_PrimaryAttributes_Elementalist`；
2. 添加 4 条曲线，命名与主属性 GameplayTag 一致：
   - `Attributes.Primary.Strength`
   - `Attributes.Primary.Intelligence`
   - `Attributes.Primary.Resilience`
   - `Attributes.Primary.Vigor`
3. 每条曲线只放**稀疏关键帧**（如等级 1 / 5 / 10 / 15 / 20 / 40），选中全部关键帧右键 **自动平滑（Auto）**，即可得到平滑成长曲线；也可拖拽控制手柄微调形状；
4. 示例取值（元素师）：力量低（1级 5 → 40级 25）、智力高（1级 15 → 40级 40）、韧性中等、活力偏低。

### 6.4 给主属性 GE 加修饰符

以 `GE_PrimaryAttributes_Elementalist` 为例，加 4 个修饰符：

| 修饰符 | 属性 | 修改方式 | 强度类型 | 曲线表 |
|---|---|---|---|---|
| 1 | Strength | Override（覆盖） | Scalable Float（可缩放浮点）= 1 | CT_PrimaryAttributes_Elementalist → Strength 曲线 |
| 2 | Intelligence | Override | Scalable Float = 1 | 同上 → Intelligence 曲线 |
| 3 | Resilience | Override | Scalable Float = 1 | 同上 → Resilience 曲线 |
| 4 | Vigor | Override | Scalable Float = 1 | 同上 → Vigor 曲线 |

`Scalable Float` 的曲线表曲线值会按等级查表，生成 GE 时传入的 Level 决定最终强度。

## 七、CSV 与 JSON：批量制作曲线表的两种方式（12.4）

不需要把元素师的曲线表制作过程对战士/游侠重做一遍，可以把曲线表数据导出成文本再改：

### 7.1 方式一：CSV（适合在 Excel / 记事本里改）

1. 资源浏览器中右键曲线表 → **导出为 CSV**（建议存到项目 `Data` 目录）；
2. CSV 结构：第一行是 x 轴值（等级），之后每行以曲线名开头、按列给数值；空值表示该等级无关键帧；
3. 用 Excel 或记事本修改数值后保存；
4. 回到编辑器，打开原曲线表点 **“从源文件重新导入”**（或资源菜单重新导入）→ 曲线表更新；
5. 也可以直接把改好的 CSV **另存为新职业的 CSV**（如 `PrimaryAttributes_Ranger.csv`），新建曲线表后重新导入，快速生成游侠表。

⚠️ **CSV 的坑**：从 CSV 导入后曲线表会**丢失三次插值，强制变成线性**（无法再“自动平滑”）。想省事用 CSV 就得接受线性。

### 7.2 方式二：JSON（能保留 Cubic 平滑）

1. 右键曲线表 → 导出为 JSON（方括号包一组花括号对象，键值对形式）；
2. 用记事本编辑数值，另存为新职业的 JSON（如 `PrimaryAttributes_Warrior.json`）；
3. 在内容浏览器 **Import** 该 JSON，导入选项里选 **Curve Table**，插值类型选 **Cubic** → 新曲线表保留平滑曲线，控制点仍可再调整。

结论：**想保留三次平滑曲线用 JSON，只追求快速改数用 CSV。**

### 7.3 给游侠/战士 GE 配修饰符

参照 6.4，给 `GE_PrimaryAttributes_Ranger` 和 `GE_PrimaryAttributes_Warrior` 各配 4 个修饰符，指向各自的曲线表与曲线（战士力量/韧性更高，游侠均衡，元素师智力最高）。

## 八、GameMode 持有数据资源 + 蓝图库应用属性（12.5）

### 8.1 为什么放 GameMode

每个角色都挂一个数据资源太冗余。GameMode 决定游戏规则，而“敌人属性按职业/等级”就是规则的一部分，所以数据资产集中放在 GameMode，全局只占一份内存。

```cpp
// AuraGameModeBase.h
UCLASS()
class AURA_API AAuraGameModeBase : public AGameModeBase
{
	GENERATED_BODY()
public:
	UPROPERTY(EditDefaultsOnly, Category = "Character Class Default")
	TObjectPtr<UCharacterClassInfo> CharacterClassInfo;
};
```

在 BP_GameMode 里把 `CharacterClassInfo` 指向 `DA_CharacterClassInfo`。

### 8.2 蓝图库函数

```cpp
// AuraAbilitySystemLibrary.h
UFUNCTION(BlueprintCallable, Category = "AuraAbilitySystemLibrary|CharacterClassDefault")
static void InitializeDefaultAttributes(const UObject* WorldContextObject,
	ECharacterClass CharacterClass, float Level, UAbilitySystemComponent* ASC);
```

```cpp
// AuraAbilitySystemLibrary.cpp
void UAuraAbilitySystemLibrary::InitializeDefaultAttributes(
	const UObject* WorldContextObject, ECharacterClass CharacterClass, float Level,
	UAbilitySystemComponent* ASC)
{
	AAuraGameModeBase* AuraGameMode = Cast<AAuraGameModeBase>(UGameplayStatics::GetGameMode(WorldContextObject));
	if (AuraGameMode == nullptr) return;

	AActor* AvatarActor = ASC->GetAvatarActor();

	UCharacterClassInfo* CharacterClassInfo = AuraGameMode->CharacterClassInfo;
	FCharacterClassDefaultInfo ClassDefaultInfo = CharacterClassInfo->GetClassDefaultInfo(CharacterClass);

	// 1) 主属性（按职业查表）
	FGameplayEffectContextHandle PrimaryAttributeContextHandle = ASC->MakeEffectContext();
	PrimaryAttributeContextHandle.AddSourceObject(AvatarActor);
	const FGameplayEffectSpecHandle PrimaryAttributeSpecHandle =
		ASC->MakeOutgoingSpec(ClassDefaultInfo.PrimaryAttributes, Level, PrimaryAttributeContextHandle);
	ASC->ApplyGameplayEffectSpecToSelf(*PrimaryAttributeSpecHandle.Data.Get());

	// 2) 次级属性（共享）
	FGameplayEffectContextHandle SecondaryAttributeContextHandle = ASC->MakeEffectContext();
	SecondaryAttributeContextHandle.AddSourceObject(AvatarActor);
	const FGameplayEffectSpecHandle SecondaryAttributeSpecHandle =
		ASC->MakeOutgoingSpec(CharacterClassInfo->SecondaryAttributes, Level, SecondaryAttributeContextHandle);
	ASC->ApplyGameplayEffectSpecToSelf(*SecondaryAttributeSpecHandle.Data.Get());

	// 3) 生命（核心）属性（共享）
	FGameplayEffectContextHandle VitalAttributeContextHandle = ASC->MakeEffectContext();
	VitalAttributeContextHandle.AddSourceObject(AvatarActor);
	const FGameplayEffectSpecHandle VitalAttributeSpecHandle =
		ASC->MakeOutgoingSpec(CharacterClassInfo->VitalAttributes, Level, VitalAttributeContextHandle);
	ASC->ApplyGameplayEffectSpecToSelf(*VitalAttributeSpecHandle.Data.Get());
}
```

要点：

- 世界上下文对象用来 `GetGameMode`，找不到 GameMode 直接返回，避免空指针；
- 每个 GE 都走“MakeEffectContext → AddSourceObject(AvatarActor) → MakeOutgoingSpec(GE, Level, Context) → ApplyGameplayEffectSpecToSelf(*Spec.Data.Get())”四步；
- **`AddSourceObject` 必须有**：MMC（如最大生命值计算）会从源对象获取 `ICombatInterface`，没设源对象就会在运行时崩溃。

## 十、测试验证与坑位记录

### 10.1 遇到的两个问题

1. **MMC 崩溃（最大生命值异常）**：应用 GE 时没有设置源对象，MMC 拿不到源对象的 CombatInterface。修复：每个效果上下文都 `AddSourceObject(AvatarActor)`。
2. **看不到属性值**：敌人没有 UI 显示当前属性，肉眼无法确认初始化结果。修复：在 Debug 模式打断点，检查生成的 `FGameplayEffectSpec`：
   - 展开 Spec 的定义，确认是 `GE_PrimaryAttributes_Warrior/Ranger`；
   - 查看 4 个修饰符：计算类型 Scalable Float、Magnitude=1、关联正确的曲线表与曲线行名。

### 10.2 验证技巧

- 把 BP_GoblinArcher 的职业临时改成 Ranger，断点确认 `CharacterClass` 枚举值正确、使用的曲线表变为 `CT_PrimaryAttributes_Ranger`；
- 检查 DA_CharacterClassInfo 里三个职业的映射是否齐全（TMap 默认键陷阱见 4.3）。

## 十二、源码校验与当前边界

### 已核对事实

- `ECharacterClass` 三个枚举值顺序为 Elementalist / Warrior / Ranger，int8 底层类型、BlueprintType；
- `FCharacterClassDefaultInfo` 目前只含 `PrimaryAttributes`（次级/生命属性在数据资产顶层共享）；
- `GetClassDefaultInfo` 用 `FindChecked`；
- 蓝图库函数签名与实现一致：WorldContextObject、CharacterClass、Level、ASC 四个参数，依次应用三个 GE 且都 `AddSourceObject(AvatarActor)`；
- 敌人 `CharacterClass` 默认 Warrior，可在蓝图细节面板修改。

### 当前边界 / 后续章节预告

1. **敌人还没有独特技能**：数据资源里计划的能力数组/共享效果数组/独特技能数组尚未落地；
2. **伤害仍是占位**：直接扣血，真正的伤害计算（元属性 + 防御/抗性）还没做，下一章预告就是“对敌人造成伤害”；
3. **敌人主属性初始化后不再变化**：所以次级属性用 Instant GE，若敌人未来要升级需改回 Infinite；
4. **Aura 的属性初始化仍是旧方案**：本章只重构了敌人侧，Aura 的“磁盘存档后按存档初始化”留待后续。

## 十三、知识点总结

### 核心类职责

| 类 / 资源 | 本章职责 |
|---|---|
| `ECharacterClass` | 职业枚举（元素师/战士/游侠），BlueprintType |
| `FCharacterClassDefaultInfo` | 单个职业的默认信息（主属性 GE） |
| `UCharacterClassInfo` | 数据资产：职业→信息映射 + 共享次级/生命 GE + 查找函数 |
| `GE_PrimaryAttributes_<职业>` | 各职业主属性初始化（Instant + 曲线表修饰符） |
| `GE_SecondaryAttributes_Enemy` | 敌人次级属性（Instant，区别于 Aura 的 Infinite） |
| `CT_PrimaryAttributes_<职业>` | 等级→主属性曲线表（Strength/Intelligence/Resilience/Vigor） |
| `AAuraGameModeBase` | 中央持有 CharacterClassInfo 数据资产 |
| `UAuraAbilitySystemLibrary::InitializeDefaultAttributes` | 蓝图库：按职业/等级应用三个 GE |
| `AAuraEnemy` | 提供 CharacterClass 与 Level，重写初始化函数接入数据驱动 |

### 核心设计思想

1. **数据驱动初始化**：属性怎么成长是“数据”（数据资产 + 曲线表），不是代码分支；
2. **职业决定曲线，等级决定取值**：枚举查映射、曲线表按等级插值，新增职业只需加枚举值和数据，不改逻辑；
3. **共享与特例分离**：次级/生命属性放数据资产顶层共享，主属性放职业映射里特例化；
4. **集中存储**：规则类数据放 GameMode，一份内存、全局可查；
5. **上下文即规范**：GE 应用四步曲（MakeEffectContext → AddSourceObject → MakeOutgoingSpec → ApplySpecToSelf），源对象缺失会触发 MMC 崩溃；
6. **外部数据格式**：CSV 改数快但丢平滑曲线，JSON 能保留 Cubic 插值，按需选择。

### 一句话总结

> 第12章用“职业枚举 + 数据资产 + 曲线表 + 蓝图库”把敌人属性从占位共享改成真正的数据驱动：`ECharacterClass` 定位职业 → `DA_CharacterClassInfo` 存 GE → 曲线表按等级出属性值 → GameMode 集中持有 → 蓝图库统一应用，敌人出生即拥有符合职业与等级的正确属性。
