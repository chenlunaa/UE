## 一、远程攻击完整数据流

```text
Behavior Tree 远程分支
  -> EQS 计算可见射击位置
  -> Move To 射击位置
  -> BT_Attack
  -> ASC::TryActivateAbilitiesByTag(Abilities.Attack)
  -> Ranger 的 GA_RangedAttack 激活
  -> 获取 CombatTarget 并更新 Motion Warp Target
  -> 从 AttackMontages 随机取得弹弓攻击 FTaggedMontage
  -> Play Montage and Wait
  -> 角色蒙太奇播放到发射帧
  -> Montage.Attack.Weapon Gameplay Event
  -> Wait Gameplay Event 收到事件
  -> SpawnProjectile(CombatTarget Location)
  -> 服务器从 Weapon TipSocket 生成 BP_SlingshotRock
  -> Projectile 携带 DamageEffectSpecHandle
  -> 与非友方目标重叠
  -> ApplyGameplayEffectSpecToTarget
  -> GE_Damage / ExecCalc_Damage / IncomingDamage
  -> 生命扣除、受击反应与伤害飘字
```

表现层还存在另一条同步链：

```text
角色攻击蒙太奇 Notify
  -> Release Rock
  -> 取得 Weapon 的 AnimInstance
  -> ABP_Slingshot.bHoldingPouch = false
  -> 播放武器自己的 Slingshot Attack Montage
  -> 武器袋向前弹出
  -> Grab Pouch Notify
  -> bHoldingPouch = true
  -> 武器袋重新跟随右手 Socket
```

角色动画负责“哥布林什么时候松手”，武器动画蓝图负责“弹弓袋如何拉伸与回弹”，GameplayAbility 负责“什么时候真正生成投射物”。三者必须共享同一时间点，视觉和伤害才不会错位。

## 二、复用 AuraProjectileSpell 构建远程能力

### 2.1 为什么不重新写一套远程攻击 C++

`UAuraProjectileSpell` 已经封装了投射物生成的核心步骤：

```text
只在 Authority 执行
  -> 从 CombatInterface 获取 Weapon Socket
  -> 计算目标方向 Rotator
  -> SpawnActorDeferred
  -> 创建 EffectContext
  -> 创建 Damage GE Spec
  -> 遍历 DamageTypes 写入 SetByCaller
  -> 把 SpecHandle 保存到 Projectile
  -> FinishSpawning
```

弹弓岩石和 Aura 火球在底层都是“从一个 Socket 朝目标生成携带伤害规格的 Projectile”，因此直接创建 `UAuraProjectileSpell` 的蓝图子类更合适。

### 2.2 创建 GA_RangedAttack

在敌人能力目录中：

1. 创建 `AuraProjectileSpell` 的蓝图子类；
2. 命名 `GA_RangedAttack`；
3. Ability Tags 添加 `Abilities.Attack`；
4. Projectile Class 选择 `BP_SlingshotRock`；
5. Damage Effect Class 选择 `GE_Damage`；
6. Damage Types 添加 `Damage.Physical`；
7. 可缩放值绑定远程伤害曲线。

当前 `SpawnProjectile` 仍固定使用 `Montage.Attack.Weapon` 查询 Socket，适用于弹弓和弓箭等武器型远程攻击。若以后从手掌、法杖或多个枪口生成投射物，函数应接收 MontageTag 或 SocketTag，而不是继续硬编码 Weapon。

<a id="section-3"></a>
## 三、创建岩石 Projectile 蓝图

基于 `AAuraProjectile` 创建 `BP_SlingshotRock`：

1. 在根 Sphere 下添加 `Static Mesh Component`，命名 `RockMesh`；
2. Static Mesh 选择 Slingshot Rock；
3. Projectile Movement 初始速度约 1000；
4. Max Speed 约 1000；
5. 启用重力并调整 Projectile Gravity Scale；
6. Static Mesh Collision 设为 `NoCollision`；
7. 真正的命中检测仍由根 Sphere Overlap 完成。

静态网格只负责显示。若 RockMesh 仍阻挡 Camera 或 Visibility，岩石经过镜头时会造成摄像机碰撞或点击检测异常；因此它不应承担物理碰撞，避免与 Sphere 的重叠逻辑重复。

球体半径不必与模型完全贴合。俯视角下镜头距离较远，可以保留适量命中宽容度，让小型高速投射物更容易产生符合玩家预期的命中。

## 四、伤害曲线与 Ranger 启动能力

### 4.1 远程伤害曲线

在 `CT_Damage` 中新增 `Abilities.Ranged` 或课程使用的远程曲线：

| 等级 | 远程物理伤害示例 |
|---:|---:|
| 1 | 7.5 |
| 40 | 35 |

`GA_RangedAttack.DamageTypes` 配置：

```text
Key   = Damage.Physical
Value = FScalableFloat(CT_Damage.Abilities.Ranged)
```

ProjectileSpell 在生成 Projectile 时使用 `GetAbilityLevel()` 查询曲线，把结果作为 `Damage.Physical` 的 SetByCaller 写入 `GE_Damage`。投射物命中时不需要再次访问能力蓝图，伤害数据已经封装在 `DamageEffectSpecHandle` 中。

### 4.2 Ranger 获得远程能力

在 `CharacterClassInfo` 数据资源：

```text
Warrior.StartUpAbilities -> GA_MeleeAttack
Ranger.StartUpAbilities  -> GA_RangedAttack
```

敌人在服务器 `BeginPlay` 时根据 CharacterClass 授予职业技能。行为树仍统一使用 `Abilities.Attack` 标签：

- Warrior ASC 中匹配到 `GA_MeleeAttack`；
- Ranger ASC 中匹配到 `GA_RangedAttack`；
- 行为树无需知道具体类名。

第一轮验证可以在 `GA_RangedAttack.ActivateAbility` 中画 0.5 秒蓝色 Debug Sphere。只有 Ranger 进入远程攻击范围时出现蓝球，说明“数据资源授予 -> BT 标签激活 -> GA Activate”链路正确，再继续处理蒙太奇和投射物。

## 五、创建弹弓攻击蒙太奇

从 Goblin Slingshot Attack 动画创建 `AM_Attack_GoblinSlingshot`：

1. 确认源动画启用 Root Motion；
2. 新建 `Motion Warping` Notify Track；
3. 新建 `Event` Notify Track；
4. 添加 Motion Warping Notify State；
5. 窗口覆盖攻击开始到即将松开弹弓袋；
6. Warp Target Name = `FacingTarget`；
7. 关闭 Warp Translation，只启用旋转；
8. Rotation Type = `Facing`；
9. 在手释放弹弓袋的帧添加 Montage Event；
10. Event Tag = `Montage.Attack.Weapon`。

在 `BP_GoblinSlingshot.AttackMontages` 添加：

```text
Montage    = AM_Attack_GoblinSlingshot
MontageTag = Montage.Attack.Weapon
```

弹弓武器骨架的 Pouch 骨骼处添加 Socket。可以所有武器统一命名 `TipSocket`，也可以给弹弓单独命名 `PouchSocket` 并在子蓝图覆盖 `WeaponTipSocketName`。课程最终沿用基础敌人的 `TipSocket` 约定。

## 六、GA_RangedAttack 的蓝图执行链

### 6.1 面向战斗目标

```text
Activate Ability
  -> Get Avatar Actor from Actor Info
  -> EnemyInterface::GetCombatTarget
  -> Is Valid
  -> Get Actor Location(Target)
  -> CombatInterface::UpdateFacingTarget(Avatar, Location)
```

`BT_Attack` 已在激活能力前把 Blackboard 的 `TargetToFollow` 写入 CombatTarget，所以远程与近战能力都能复用同一套朝向逻辑。

### 6.2 获取并播放攻击蒙太奇

```text
CombatInterface::GetAttackMontages(Avatar)
  -> GetRandomTaggedMontageFromArray
  -> Promote to Variable: TaggedMontage
  -> Break TaggedMontage
       Montage    -> Play Montage and Wait
       MontageTag -> Wait Gameplay Event(Only Exact Match)
```

取消 `Stop When Ability Ends`，避免事件触发并结束能力后立刻截断剩余攻击动作。Completed、Interrupted 和 Cancelled 仍应连接到 `End Ability`，保证被 HitReact 打断时技能能正确清理。

### 6.3 等待发射事件

当 `Wait Gameplay Event` 收到 `Montage.Attack.Weapon`：

1. 再次取得 CombatTarget；
2. 读取 Target Actor Location；
3. 调用 `Spawn Projectile`；
4. 结束能力或等待蒙太奇完成，取决于蓝图的结束策略。

调试阶段可以先用 `GetCombatSocketLocation(MontageTag)` + 小半径 Debug Sphere，确认球体精准出现在弹弓袋 Socket，再替换为 SpawnProjectile。

<a id="section-7"></a>
## 七、随机 TaggedMontage 的 C++ 工具函数

上一章在蓝图中使用 Length、Random Integer 和 Get 组合随机蒙太奇。本次把它集中到 `UAuraDamageGameplayAbility`：

```cpp
FTaggedMontage
UAuraDamageGameplayAbility::GetRandomTaggedMontageFromArray(
    const TArray<FTaggedMontage>& TaggedMontages) const
{
    if (TaggedMontages.Num() > 0)
    {
        const int32 Selection =
            FMath::RandRange(0, TaggedMontages.Num() - 1);
        return TaggedMontages[Selection];
    }

    return FTaggedMontage();
}
```

函数标记为 `BlueprintPure`：

- 输入使用 `const TArray<FTaggedMontage>&`，避免复制整个数组；
- 先检查 Num，避免空数组访问；
- `RandRange` 的最大值是包含的，因此使用 `Num() - 1`；
- 空数组返回默认结构体，Montage 为 nullptr、Tag 无效。

蓝图仍应把返回结构体提升为变量。Pure 函数若分别连接到 Montage 和 Tag，仍可能被蓝图重复求值两次，得到两个不同随机结果；“封装到 C++”并不会自动消除 Pure 节点的多次执行语义。

## 八、从事件帧生成岩石投射物

在远程能力接收蒙太奇事件时调用：

```text
Get Combat Target
  -> Get Actor Location
  -> Spawn Projectile(Target Location)
```

`SpawnProjectile` 内部只在服务器执行：

```cpp
if (!GetAvatarActorFromActorInfo()->HasAuthority()) return;
```

生成位置来自：

```cpp
ICombatInterface::Execute_GetCombatSocketLocation(
    AvatarActor,
    FAuraGameplayTags::Get().Montage_Attack_Weapon);
```

目标方向为：

```cpp
(ProjectileTargetLocation - SocketLocation).Rotation();
```

这是一条直线瞄准。岩石启用重力后会下坠，因此距离较远时可能提前砸地。本章测试已观察到该现象，但尚未实现抛物线解算。后续可以：

- 在目标位置上增加 Z 偏移；
- 使用 `SuggestProjectileVelocity` 求弹道初速度；
- 关闭重力，使用直线飞行；
- 让不同 Projectile 定义自己的瞄准策略。

## 九、岩石旋转、材质与碰撞配置

### 9.1 随机旋转

在 `BP_SlingshotRock.BeginPlay`：

```text
YawRate   = Random Float in Range(-500, 500)
PitchRate = Random Float in Range(-500, 500)
RollRate  = Random Float in Range(-500, 500)
```

在 Tick：

```text
Delta Rotation = Rotator(
    PitchRate * DeltaSeconds,
    YawRate   * DeltaSeconds,
    RollRate  * DeltaSeconds)

RockMesh -> Add Local Rotation(Delta Rotation)
```

乘以 DeltaSeconds 后，旋转速度才与帧率无关。只旋转可视 Mesh，不旋转碰撞 Sphere，能保持命中形状稳定。

### 9.2 可读性材质

岩石体积小、飞行快，可以用 Fresnel 乘颜色和强度接入 Emissive，让轮廓在暗场景中更容易辨认。注意不要把强度调成“熔岩球”，材质调整应服务于可读性而不是改变武器语义。

### 9.3 碰撞职责

```text
RockMesh Collision = NoCollision
Sphere Collision   = Overlap 目标对象通道
ProjectileMovement = 负责位移和重力
```

这样只有一个组件负责命中事件，避免网格阻挡摄像机、产生刚体碰撞或比 Sphere 更早撞到场景。

## 十、投射物友军过滤

`AAuraProjectile::OnSphereOverride` 新增：

```cpp
if (!UAuraAbilitySystemLibrary::IsNotFriend(
        GetOwner(), OtherActor))
{
    return;
}
```

Projectile 生成时 Owner 设为技能 Avatar，因此：

```text
Enemy Projectile + Enemy -> friend -> 忽略
Enemy Projectile + Player -> not friend -> 命中
Player Projectile + Player -> friend -> 忽略
Player Projectile + Enemy -> not friend -> 命中
```

过滤发生在播放 Impact、设置 `bHit` 和应用 GE 之前，友军重叠不会消耗投射物，也不会播放错误的命中特效。

这套规则同时关闭了玩家互伤。若未来需要 PvP、可破坏中立物或阵营转换，Actor Tag 的二元 Player/Enemy 判断会不够，需要改为 Team ID 或项目阵营组件。

## 十一、为什么弹弓需要独立动画蓝图

弹弓不是 Static Mesh，而是带骨骼和蒙皮权重的 Skeletal Mesh。它至少有两个状态：

1. 待机/瞄准：Pouch 骨骼始终跟随哥布林右手，皮筋被拉住；
2. 发射：停止跟随右手，播放弹弓自己的攻击动画，让 Pouch 向前弹出再回到可抓取位置。

角色的 `ABP_GoblinSlingshot` 控制身体动作，武器的 `ABP_Slingshot` 控制弹弓骨骼。把武器形变硬写进角色 AnimBP 会让武器和角色骨架耦合，也难以复用于弓、弩或其他有独立骨骼动画的装备。

## 十二、ABP_Slingshot 的骨骼跟随流程

### 12.1 创建武器动画蓝图

1. 选择 Slingshot Skeleton 创建 `ABP_Slingshot`；
2. 创建 Main State Machine；
3. 只放一个 Slingshot Idle 状态；
4. State Machine 输出经过默认 Slot；
5. Weapon 组件 Animation Mode 设为 `Use Animation Blueprint`；
6. Anim Class 选择 `ABP_Slingshot`。

### 12.2 获取哥布林手部变换

角色骨架右手创建 `RightHandSocket`。在武器 AnimBP：

```text
Blueprint Initialize Animation
  -> Try Get Pawn Owner
  -> Cast To Character / GoblinSlingshot
  -> Get Mesh
  -> Promote to Variable: OwnerMesh

Blueprint Update Animation
  -> OwnerMesh -> Get Socket Transform(RightHandSocket, World Space)
  -> Promote to Variable: HandSocketTransform
```

Pawn Cast 和 Mesh 引用只需初始化一次；Socket Transform 会随角色动画变化，因此必须每帧更新。

### 12.3 Transform Modify Bone

在 AnimGraph：

```text
Main State Machine Pose
  -> Local To Component
  -> Transform (Modify) Bone
       Bone = Pouch
       Translation Mode = Replace Existing
       Translation Space = World Space
       Rotation Mode = Replace Existing
       Rotation Space = World Space
       Translation/Rotation = HandSocketTransform
  -> Component To Local
  -> Slot
  -> Output Pose
```

`Transform Modify Bone` 在组件空间中工作，所以 AnimGraph 自动或显式加入 Local/Component Space 转换。事件图取得 World Space，节点也必须选择 World Space；空间不一致会造成 Pouch 偏移、翻转或跳到世界原点。

<a id="section-13"></a>
## 十三、释放岩石与重新抓袋的双动画协作

### 13.1 bHoldingPouch

`ABP_Slingshot` 新增 Bool：

```text
bHoldingPouch = true（默认）
```

AnimGraph 使用 `Blend Poses by Bool`：

- true：经过 Transform Modify Bone，Pouch 跟随手；
- false：使用武器默认姿势/Slot，让武器蒙太奇控制 Pouch。

### 13.2 角色蒙太奇的 Skeleton Notify

在 `AM_Attack_GoblinSlingshot` 新增 Rock/Weapon Track：

- 手松开的帧：`ReleaseRock`；
- 手重新抓回袋子的帧：`GrabPouch`。

这些 Notify 是角色骨架事件，不等同于前面用于生成 Projectile 的 Gameplay Event。Gameplay Event 负责技能逻辑；Release/Grab Notify 负责武器 AnimBP 的视觉状态。

### 13.3 角色 AnimBP 控制 Weapon AnimBP

`AAuraCharacterBase::Weapon` 改为 `BlueprintReadOnly`，使角色 AnimBP 能访问武器组件。

在 `ABP_GoblinSlingshot.Initialize Animation`：

```text
Try Get Pawn Owner
  -> Cast BP_GoblinSlingshot
  -> Get Weapon
  -> Get Anim Instance
  -> Cast ABP_Slingshot
  -> Promote to Variable: SlingshotAnimBP
```

响应通知：

```text
AnimNotify_ReleaseRock
  -> IsValid(SlingshotAnimBP)
  -> Set bHoldingPouch(false)
  -> Montage Play(AM_Slingshot_Attack) on Weapon AnimInstance

AnimNotify_GrabPouch
  -> Set bHoldingPouch(true)
```

于是角色手、Pouch 跟随、武器回弹和 Projectile 生成在同一个角色蒙太奇时间轴上对齐。

<a id="section-14"></a>
## 十四、动画蓝图继承与初始化陷阱

`ABP_GoblinSlingshot` 是基础 Enemy AnimBP 的子类。新增 `Blueprint Initialize Animation` 后，如果只写子类逻辑而没有 `Call to Parent Function`，父类负责缓存 Character、Movement Component 等引用的初始化不会执行。

运行现象是：

- 弹弓形变正常；
- 哥布林却不再播放跑步动画，看起来在地面滑行；
- Update Animation 虽然调用父版本，但父版本依赖的初始引用为空。

修复：在子类 Initialize Animation 事件上右键添加 `Call to Parent Function`，再执行取得 Weapon AnimInstance 的子类逻辑。

```text
Child Blueprint Initialize Animation
  -> Parent: Blueprint Initialize Animation
  -> Child: Cache SlingshotAnimBP
```

覆盖任何父类蓝图事件时都要明确决定是否需要 Parent Call。UE 不会因为事件名称相同就自动执行父版本。

不要一次性测试最终效果，应按以下顺序逐层证明：

```text
武器袋形变
  -> 证明角色 Notify 与 Weapon AnimBP 协作正确
```

## 十六、源码审查与当前边界

### 16.1 GetRandomTaggedMontage 的 Pure 随机语义

该函数既是随机函数又标记 `BlueprintPure`。Pure 节点可被多次求值，不适合让多个输出使用点直接依赖同一个随机调用。当前蓝图通过 Promote to Variable 解决。长期可改为 `BlueprintCallable`，用执行引脚明确“随机一次”。

### 16.2 Projectile 友军过滤的空指针

当前代码直接调用：

```cpp
IsNotFriend(GetOwner(), OtherActor)
```

`IsNotFriend` 内部会立即访问两个 Actor 的 Tag。如果 Projectile Owner 配置错误或 OtherActor 无效，存在空指针风险。建议在双方有效后再判断，并明确 Owner 必须设置为技能 Avatar。

### 16.3 Owner 与 EffectCauser

字幕讲解提到可以从 EffectContext 获取 EffectCauser，实际提交使用 `GetOwner()`。当前 `SpawnActorDeferred` 把 Avatar 设为 Owner，因此结果正确；但若未来投射物由武器、陷阱或召唤物代为生成，Owner 和伤害阵营来源可能不再相同。应为阵营判断定义统一的 Source Actor 语义。

### 16.4 低弹道问题

当前方向只瞄准目标当前世界位置，ProjectileMovement 又应用重力，远距离时岩石会提前落地。此问题已在测试中出现，尚未闭环。需要弹道速度解算、目标高度偏移或关闭重力。

### 16.5 目标死亡后继续攻击

17.9 测试中 Aura 死亡后，弹弓哥布林仍继续射击。说明 Blackboard Target、行为树 Decorator 或最近目标 Service 还没有统一处理死亡目标。后续应在目标死亡时：

- 清除 TargetToFollow；
- 或让 Decorator 检查 `IsDead`；
- 或在 Service 中排除死亡角色并重新选敌；
- 同时让当前 GA/BT Task 中止。

### 16.6 武器 AnimBP 的强类型依赖

`ABP_GoblinSlingshot` 直接 Cast 到 `ABP_Slingshot`，适合专用角色资产，但不够通用。若多种武器都有“拉弦/释放”状态，可以建立 Weapon AnimInstance 基类或接口，减少角色动画蓝图依赖具体武器类。

### 16.7 Content 资产与 Git 差异

提交只显示 4 个 C++ 文件、21 行新增；实际功能的大部分位于：

- `GA_RangedAttack`；
- `BP_SlingshotRock`；
- `AM_Attack_GoblinSlingshot`；
- `AM_Slingshot_Attack`；
- `ABP_Slingshot`；
- `ABP_GoblinSlingshot`；
- CharacterClassInfo、伤害曲线、Socket、材质和关卡配置。

当前 Content 资产没有体现在这次源码提交差异中。只同步 C++ 无法复现本章效果。
