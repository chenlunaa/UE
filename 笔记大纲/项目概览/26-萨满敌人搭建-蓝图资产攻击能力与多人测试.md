# 第 18 章：萨满敌人搭建——蓝图资产、攻击能力与多人测试

> 本章目标：在既有的 `BP_EnemyBase`、GAS、行为树和远程投射物框架上，创建一个元素法师类型的哥布林萨满。重点不是新增大量 C++，而是学习如何把角色网格、动画蓝图、Blend Space、攻击蒙太奇、Socket、GameplayAbility、职业数据和材质效果组合成一个完整敌人。

---

## 1. 本章最终完成了什么

萨满是一种新的施法型远程敌人，最终具备：

- 使用萨满 Skeletal Mesh 和法杖武器；
- 正确的胶囊体、模型位置和朝向；
- 自己的 Animation Blueprint；
- Idle/Walk Blend Space；
- 带 Motion Warping 的施法攻击蒙太奇；
- 从法杖尖端 Socket 生成火球；
- 通过角色职业数据自动获得 Elementalist 属性与火球能力；
- 由通用行为树寻找目标、移动和攻击；
- 攻击音效和移动参数调优；
- 死亡后立即停止行为树攻击；
- 在 Listen Server + Client 环境中通过多人测试；
- 身体和法杖均支持溶解效果。

完整依赖链如下：

```text
BP_Shaman
├── 父类：BP_EnemyBase
├── Mesh：SK_Shaman
├── Weapon：Shaman Staff
├── Anim Class：ABP_Shaman
│   ├── BS_IdleWalk
│   └── AM_Attack_Shaman
├── CharacterClass：Elementalist
├── Tagged Montage：Montage.Attack.Weapon
└── Dissolve Materials

CharacterClassInfo.Elementalist
└── Startup Ability：GA_Enemy_FireBolt
    ├── 复用 GA_RangedAttack 流程
    ├── DamageType：Fire
    └── ProjectileClass：FireBolt
```

本章最重要的架构认识是：**创建一种新敌人，不等于复制一整套 C++ 逻辑。只要已有基类提供稳定接口，就可以主要通过蓝图资产和 DataAsset 重新组合能力。**

## 2. 为什么萨满可以主要用蓝图完成

项目此前已经构建了通用敌人框架：

| 已有系统 | 为萨满提供的能力 |
|---|---|
| `BP_EnemyBase` / `AAuraEnemy` | ASC 初始化、属性、血条、死亡、AIController |
| `ICombatInterface` | CombatTarget、Montage、Socket Location、Level |
| Behavior Tree | 索敌、追击、保持距离、攻击 |
| `BTTask_Attack` | 按 `Abilities.Attack` 激活攻击能力 |
| `GA_RangedAttack` | 面向目标、播放蒙太奇、等待事件、生成投射物 |
| Tagged Montage | 用 Tag 连接蒙太奇、事件和 Socket |
| CharacterClassInfo | 按职业提供属性与 Startup Abilities |
| Damage GE / ExecCalc | 火焰伤害、抗性、暴击、护甲等结算 |
| Enemy Base Dissolve | 动态材质、时间线和死亡溶解流程 |

因此萨满蓝图只需要回答：

```text
长什么样？
使用什么动画？
从哪里发射？
属于什么职业？
获得哪一个攻击 Ability？
移动和表现参数是多少？
```

具体的网络、属性和伤害算法仍由 C++ 与 GAS 处理。

## 3. 创建萨满角色蓝图与动画蓝图

### 3.1 创建角色子蓝图

在敌人蓝图目录中：

1. 新建 `Shaman` 文件夹；
2. 右键 `BP_EnemyBase`；
3. 选择 **Create Child Blueprint Class**；
4. 命名为 `BP_Shaman`；
5. 将其移动到萨满文件夹。

必须从 `BP_EnemyBase` 创建子类，而不是直接创建普通 Character。这样萨满才能继承：

- ASC 与属性初始化流程；
- Behavior Tree 和 Blackboard 配置入口；
- Weapon 组件；
- Tagged Montage 数组；
- Hit React 和 Death；
- 血条与高亮；
- 溶解时间线。

### 3.2 创建 AnimBP 子蓝图

1. 找到现有敌人的动画蓝图基类；
2. 创建子蓝图；
3. 为其指定 `SK_Shaman` 使用的 Skeleton；
4. 命名为 `ABP_Shaman`；
5. 移到 Shaman 文件夹。

使用动画蓝图子类的好处是复用通用动画逻辑：

```text
速度计算
是否在空中
移动状态机
受击/死亡等共享结构
```

萨满只需替换它特有的动画资产。

## 4. 配置 Skeletal Mesh、胶囊体和模型变换

打开 `BP_Shaman`：

1. 选择 `Mesh` 组件；
2. 将 Skeletal Mesh 设置为萨满网格；
3. 调整 Capsule Component 的半高和半径；
4. 调整 Mesh 的相对位置，让脚底接近胶囊底部；
5. 调整 Mesh 的相对旋转，使角色正面与 UE Character 的 Forward 方向一致；
6. 编译并在视口中检查。

### 4.1 为什么必须同时检查胶囊和 Mesh

Character 的实际碰撞与移动主要由 Capsule 控制，Mesh 只是视觉表现：

```text
Capsule Component
├── 决定碰撞范围
├── 决定地面接触
└── CharacterMovement 移动的主体

Skeletal Mesh
├── 播放动画
├── 显示角色
└── 提供骨骼和 Socket
```

如果只把 Mesh 调到看起来合适，而胶囊仍然过大或悬空，会出现：

- 角色看似悬浮；
- 攻击距离与视觉距离不一致；
- 导航绕障异常；
- 点击和碰撞范围不自然；
- 死亡后模型与地面关系错误。

建议把角色放到平坦测试地面上再微调，不要只依赖蓝图视口。

## 5. 配置法杖与手部 Socket

Enemy Base 已经拥有 Weapon Skeletal Mesh Component，并会将它附加到约定的手部 Socket。

本项目的约定名称类似：

```text
WeaponHandSocket
```

操作流程：

1. 打开萨满 Skeleton；
2. 在 Skeleton Tree 找到握法杖的手部骨骼；
3. 创建或重命名 Socket 为项目要求的武器手部 Socket 名称；
4. 回到 `BP_Shaman`；
5. 为 Weapon 组件选择萨满法杖 Skeletal Mesh；
6. 检查法杖是否正确附加；
7. 必要时调整 Socket 的位置和旋转，而不是在每个角色蓝图中随意偏移 Weapon。

### 5.1 Socket 为什么适合做武器挂点

Socket 是附着在骨骼上的命名变换点：

```text
手部骨骼动画变换
  -> WeaponHandSocket 跟随骨骼
  -> 法杖组件附着到 Socket
  -> 法杖自然跟随手部动画
```

统一 Socket 名称后，Enemy Base 不需要识别每种 Skeleton，只需调用同一个名字。

### 5.2 Skeleton Socket 与 Mesh Socket

- Skeleton Socket：所有共享该 Skeleton 的 Mesh 都可使用；
- Mesh Socket：只属于某一个 Skeletal Mesh，适合特定网格的局部修正。

选择原则是：若这是整个骨架体系通用的握持点，放在 Skeleton；若只有某个 Mesh 需要特殊位置，考虑 Mesh Socket。

## 6. 创建萨满 Idle/Walk Blend Space

萨满拥有待机和缓慢步行动画，需要创建一维 Blend Space：

1. 在动画目录右键；
2. 选择 **Animation > Blend Space**；
3. 选择萨满 Skeleton；
4. 命名为 `BS_Shaman_IdleWalk`；
5. 将水平轴命名为 `Speed`；
6. 最小值设为 `0`；
7. 最大值先设为萨满目标移动速度，例如 `75`；
8. 将 Idle 动画放在 0；
9. 将 Walk 动画放在最大值；
10. 将 Weight Speed 调为约 4，再根据预览效果微调。

```text
Speed = 0       -> 100% Idle
Speed = 37.5    -> Idle/Walk 混合
Speed = 75      -> 100% Walk
```

### 6.1 Blend Space 最大值要与移动速度对应

如果 `BP_Shaman` 的基础步行速度是 75，而 Blend Space 最大值是 600，那么实际运行时输入只会落在轴线很靠左的位置，Walk 权重不足，可能产生滑步。

推荐保持：

```text
CharacterMovement MaxWalkSpeed
≈ Blend Space Speed Axis Max
```

之后若修改移动速度，应同时检查 Blend Space。

### 6.2 在 AnimBP 中使用

打开 `ABP_Shaman`：

1. 找到 Locomotion 状态或基类提供的 Blend Space Player；
2. 将资产替换为 `BS_Shaman_IdleWalk`；
3. 把计算得到的 Ground Speed 接入 `Speed`；
4. 编译并预览；
5. 回到 `BP_Shaman` 的 Mesh，将 Anim Class 设置为 `ABP_Shaman`。

数据流是：

```text
CharacterMovement Velocity
  -> AnimBP 计算 GroundSpeed
  -> Blend Space 的 Speed
  -> 在 Idle 和 Walk 之间混合
```

## 7. 创建攻击蒙太奇

萨满的施法攻击需要制作 Montage：

1. 找到 Shaman Attack 动画；
2. 确认动画的 Root Motion 设置符合项目要求；
3. 右键动画，选择 **Create AnimMontage**；
4. 命名为 `AM_Attack_Shaman`；
5. 打开 Montage，整理 Notify Tracks。

建议至少建立：

```text
MotionWarping 轨道
Event 轨道
Sound 轨道
```

独立命名轨道不会改变运行逻辑，但能显著提高动画事件的可读性和维护性。

## 8. 配置 Motion Warping

萨满施法时应朝向当前目标，所以在攻击动画前段添加 Motion Warping Notify State：

1. 在 MotionWarping 轨道添加 **Motion Warping Notify State**；
2. 覆盖角色需要调整朝向的动画区间；
3. Warp Target Name 设置为项目能力中使用的目标名；
4. 关闭平移变形（Ignore/Disable Translation Warping）；
5. 保留旋转变形；
6. Rotation Type 设置为 **Facing**。

本章只希望萨满原地转向目标：

```text
Translation Warping：关闭
Rotation Warping：开启
Rotation Type：Facing Target
```

GameplayAbility 在播放蒙太奇前更新 Warp Target：

```text
Behavior Tree 设置 CombatTarget
  -> GA_RangedAttack 读取 CombatTarget
  -> 更新 Motion Warp Target
  -> 播放 AM_Attack_Shaman
  -> Notify State 按目标方向修正根运动旋转
```

如果 Warp Target Name 在 Ability 和 Montage 中不一致，萨满就不会正确朝向目标。

## 9. 添加 Montage Event：确定火球发射帧

在动画中法杖挥到合适位置时添加 Montage Event Notify：

1. 在 Event 轨道添加项目自定义的 Montage Event Notify；
2. 将 Event Tag 设置为武器攻击事件，例如：

```text
Montage.Attack.Weapon
```

3. 把 Notify 放在视觉上应该生成火球的那一帧。

GameplayAbility 中会等待这个 Tag：

```text
Play Montage
  -> Wait Gameplay Event(Montage.Attack.Weapon)
  -> 动画播放到 Notify
  -> 广播 Gameplay Event
  -> Ability 收到事件
  -> 查询 Weapon Combat Socket
  -> Spawn Projectile
```

这比“Ability 激活后立刻生成火球”更好，因为玩法事件与动画动作同步。动画速度、蒙太奇片段发生改变时，只需调整 Notify 位置。

## 10. 配置 Tagged Montage

打开 `BP_Shaman` 的 Class Defaults，在攻击蒙太奇数组中添加元素：

```text
Montage：AM_Attack_Shaman
MontageTag：Montage.Attack.Weapon
SocketTag：项目所用的 Weapon Socket Tag
```

Tagged Montage 把三件事绑定在同一个数据项中：

```text
播放哪段攻击动画
使用哪个 GameplayTag 表示攻击类型
从哪个 Combat Socket 生成攻击
```

通用 `GA_RangedAttack` 因此不需要写：

```text
如果是萨满 -> 播放萨满动画 -> 从法杖生成
如果是投石者 -> 播放投石动画 -> 从弹弓生成
```

它只处理通用数据：

```text
随机/指定取得 TaggedMontage
  -> Play Montage
  -> 等待 MontageTag 对应事件
  -> 用 SocketTag 查询世界位置
```

## 11. 创建法杖尖端 Socket

萨满火球不能从角色中心或手腕生成，应从法杖尖端出现。

操作：

1. 打开法杖 Skeletal Mesh 或 Skeleton；
2. 在合适的末端骨骼上创建 Socket；
3. 名称必须与角色的 Weapon Tip Socket 配置一致，例如：

```text
TipSocket
```

4. 使用移动/旋转工具把 Socket 放到法杖顶端；
5. 在预览场景中显示 Socket 检查位置；
6. 保存资产。

运行时：

```text
Montage Event Tag
  -> GetCombatSocketLocation(SocketTag)
  -> Weapon Component 查 TipSocket
  -> 得到法杖尖端世界坐标
  -> 从该坐标 Spawn FireBolt
```

要区分两个 Tag/Name：

- Montage/Event GameplayTag：说明“攻击事件是什么”；
- Socket FName 或 SocketTag：说明“攻击从哪里产生”。

它们可以在同一个 Tagged Montage 数据中关联，但语义不同。

## 12. 复用远程攻击 Ability 创建火球能力

现有 `GA_RangedAttack` 已经完成通用远程攻击流程：

```text
获取 CombatTarget
  -> 更新 Motion Warp Target
  -> 选择 Tagged Montage
  -> 播放蒙太奇
  -> 等待 Gameplay Event
  -> 查询 Combat Socket Location
  -> 朝目标方向生成 Projectile
```

因此萨满不需要重写 Event Graph，只需创建能力子蓝图：

1. 右键 `GA_RangedAttack`；
2. 创建 Child Blueprint Class；
3. 命名为 `GA_Enemy_FireBolt`；
4. 在 Class Defaults 中设置：
   - Projectile Class：FireBolt 投射物；
   - Damage Effect Class：沿用通用伤害 GE；
   - Damage Type：Fire；
   - Damage Curve/Scalable Float：选择 FireBolt 对应曲线；
   - Ability Tags：保持敌人攻击所需的 `Abilities.Attack` 分类；
5. 编译保存。

### 12.1 为什么创建子能力而不是复制蓝图

子蓝图复用父能力流程，只覆盖数据：

```text
父类：攻击怎么执行
子类：使用什么投射物、伤害类型和数值
```

复制整个蓝图会产生多个独立版本；以后修复远程攻击流程时，容易漏改其中一个。

### 12.2 Fire Damage 如何进入结算

```text
GA_Enemy_FireBolt
  -> DamageType = Damage.Fire
  -> 创建 Damage GE Spec
  -> SetByCaller 写入火焰伤害
  -> Projectile 命中目标
  -> ExecCalc_Damage
  -> 查找对应 Fire Resistance
  -> 输出 IncomingDamage
  -> AttributeSet 扣除 Health
```

蓝图只配置伤害类型与曲线，最终规则仍由统一 ExecCalc 执行。

## 13. 用 CharacterClassInfo 授予萨满能力

在 `BP_Shaman` 中将 Character Class 设置为：

```text
Elementalist
```

然后打开 CharacterClassInfo DataAsset，在 Elementalist 配置中：

1. 确认 Primary Attribute 初始化 GE；
2. 在 Startup Abilities 中添加 `GA_Enemy_FireBolt`；
3. 保存 DataAsset。

启动链：

```text
服务器生成 BP_Shaman
  -> Enemy 初始化 ASC
  -> 读取 CharacterClass = Elementalist
  -> CharacterClassInfo 返回 Elementalist 属性 GE
  -> 按 Level 初始化属性
  -> 授予 Elementalist Startup Abilities
  -> ASC 获得 GA_Enemy_FireBolt
  -> BTTask_Attack 用 Abilities.Attack 激活它
```

萨满蓝图不需要直接调用 `GiveAbility`。职业数据将“敌人种类”和“初始能力集合”连接起来。

## 14. 调整移动速度和旋转

初次测试时萨满移动过快、转身较生硬，因此在 `BP_Shaman` 中调整：

- Base Walk Speed / Max Walk Speed：约 75；
- CharacterMovement Rotation Rate：降低到适合老年萨满的值，例如 Yaw 约 200；
- Blend Space 最大 Speed 同步为 75；
- 检查 Use Controller Rotation Yaw、Orient Rotation to Movement 等继承配置。

需要一起观察：

```text
移动速度
Blend Space 轴范围
动画步频
Rotation Rate
行为树保持距离和 MoveTo
```

单独调其中一个参数可能造成滑步、突然转向或到达攻击距离太快。

## 15. 在攻击蒙太奇中添加音效

本章为萨满火球和弹弓攻击补充了声音：

1. 打开对应 Attack Montage；
2. 添加 `Sound` Notify Track；
3. 添加 **Play Sound** Notify；
4. 选择 FireBolt 或 Slingshot 音效；
5. 将 Notify 移到动作发力或投射物发射帧；
6. 预览并微调音量与时机。

将音效放在 Montage Notify 的优势：

- 与动画帧同步；
- Ability 不需要知道具体音效资产；
- 不同敌人的同一攻击流程可使用不同声音；
- 动画师可以直接调整节奏。

需要注意网络：蒙太奇在哪些端播放，Notify 就可能在哪些端触发。纯表现声音通常在各客户端本地播放；不要让一个 Notify 同时通过多个网络路径重复播放。

## 16. 修复敌人死亡后仍然攻击

测试发现敌人死亡后，Behavior Tree 仍然运行并可能继续触发远程攻击。这不是死亡动画的问题，而是 AI 决策树不知道 Pawn 已死亡。

### 16.1 添加 Blackboard Key

在 Blackboard 中新增：

```text
IsDead：Bool
```

### 16.2 在行为树增加 Decorator

在主要战斗分支上添加 Blackboard Decorator：

```text
条件：IsDead == false
Observer Aborts：Both
```

`Observer Aborts = Both` 的目的：当 `IsDead` 从 false 变成 true 时，不必等当前 MoveTo/Attack Task 自然结束，而是立即终止当前分支及相关低优先级分支。

```text
IsDead = false
  -> 允许索敌、移动和攻击

IsDead = true
  -> Decorator 条件失败
  -> Abort 当前行为
  -> 不再激活攻击 Ability
```

### 16.3 C++ 死亡时写入 Blackboard

在敌人的服务器死亡逻辑中：

```cpp
if (AuraAIController && AuraAIController->GetBlackboardComponent())
{
    AuraAIController->GetBlackboardComponent()
        ->SetValueAsBool(FName("IsDead"), true);
}
```

核心原则是：

- 死亡由服务器权威判断；
- 服务器更新 AI Blackboard；
- Behavior Tree 立即停止战斗逻辑；
- 多播死亡表现负责各端动画、物理和溶解，但不代替服务器 AI 状态。

硬编码 Key 名称容易拼写错误，后续可以集中为常量或用 Blackboard Key Selector。

## 17. 多人测试发现的 SpecHandle 空指针问题

本章使用：

```text
Net Mode：Play As Listen Server
Players：2
```

客户端释放火球时出现访问冲突。调用栈显示在访问：

```cpp
DamageEffectSpecHandle.Data.Get()
```

但 `Data` 无效。

### 17.1 逻辑错误一：有效性判断写反

正确语义应当是：

```cpp
if (!DamageEffectSpecHandle.Data.IsValid())
{
    return;
}
```

不是“有效时返回”。

### 17.2 逻辑错误二：应使用 OR 而不是 AND

如果存在两个独立的提前返回条件：

```text
SpecHandle 无效
或者
目标不应受到这次伤害
```

应使用：

```cpp
if (!DamageEffectSpecHandle.Data.IsValid() || ShouldIgnoreTarget)
{
    return;
}
```

如果误用 `&&`：

```cpp
if (!IsValid && ShouldIgnoreTarget)
```

只有两个条件同时成立才返回。当 Spec 无效但第二个条件为 false 时，代码仍继续解引用空指针。

### 17.3 为什么单人测试可能没发现

多人环境具有不同执行端和复制时序：

- 客户端可能只拥有表现对象；
- 权威 Damage Spec 只在服务器构造；
- Overlap 可能在多个端发生；
- Projectile、Owner 和 Causer 的复制到达时间不同。

因此必须在任何解引用前验证：

```cpp
SpecHandle.IsValid()
SpecHandle.Data.IsValid()
TargetASC 是否有效
是否处于 Authority
目标是否为敌对对象
```

同时通过 Visual Studio Call Stack 找到第一个项目函数，而不是只停留在 `SharedPointer.h`。智能指针内部崩溃通常只是症状，真正原因是上层传入了无效 Handle。

## 18. 为萨满和法杖制作溶解材质

萨满死亡后没有溶解，是因为 Mesh 和 Weapon 没有配置兼容 Enemy Base 溶解时间线的材质实例。

### 18.1 修改萨满身体材质

1. 打开萨满基础材质；
2. 从已有可溶解敌人材质复制 Dissolve 节点组；
3. 设置 Material Domain 为 Surface；
4. 设置 Blend Mode 为 Masked；
5. Shading Model 保持 Default Lit；
6. 将溶解颜色/边缘结果连接到 Emissive Color；
7. 将遮罩结果连接到 Opacity Mask；
8. 设置安全的默认 Dissolve 值，例如 `-2`，避免编辑器中默认消失；
9. 点击 Apply；
10. 创建 Material Instance，例如 `MI_Shaman_Dissolve`。

### 18.2 修改法杖材质

对 Staff 材质执行相同流程：

```text
复制 Dissolve 节点
  -> Blend Mode = Masked
  -> 连接 Emissive / Opacity Mask
  -> 设置默认 Dissolve 参数
  -> Apply
  -> 创建 MI_ShamanStaff_Dissolve
```

### 18.3 在 BP_Shaman 中设置材质实例

在 Class Defaults 的 Dissolve Material 配置中分别设置：

```text
Character Dissolve Material：MI_Shaman_Dissolve
Weapon Dissolve Material：MI_ShamanStaff_Dissolve
```

运行时 Enemy Base 通常会：

```text
死亡
  -> 创建 Dynamic Material Instance
  -> 替换 Mesh / Weapon 材质
  -> 播放 Dissolve Timeline
  -> 持续更新标量参数 Dissolve
  -> 身体和武器逐渐消失
```

### 18.4 为什么创建材质实例后看不到参数

如果基础材质新增参数后没有点击 **Apply/Save**，材质实例可能还看不到新参数。正确顺序：

```text
修改 Parent Material
  -> Apply
  -> Save
  -> 打开/刷新 Material Instance
  -> 参数出现
```

身体材质和武器材质都要独立 Apply。

## 22. 本章架构总结

萨满的创建流程可以压缩为：

```text
Enemy Base 提供通用角色能力
  ↓
BP_Shaman 配置 Mesh、Weapon、职业和移动参数
  ↓
ABP_Shaman + Blend Space 提供移动表现
  ↓
Attack Montage 提供施法时序
  ↓
Motion Warping 使萨满面向目标
  ↓
Gameplay Event 决定火球发射帧
  ↓
Weapon Tip Socket 决定火球生成位置
  ↓
GA_Enemy_FireBolt 复用通用远程攻击流程
  ↓
CharacterClassInfo 在服务器授予能力
  ↓
Behavior Tree 激活 Abilities.Attack
  ↓
Projectile + GAS 完成权威伤害
  ↓
Blackboard IsDead 终止死亡后的 AI
  ↓
动态材质完成身体与武器溶解
```

这一章最值得掌握的不是每一次鼠标点击，而是蓝图资产之间的协议：

- 父类决定可复用的结构；
- Skeleton Socket 决定附件与发射点；
- AnimBP 决定持续动画；
- Montage Notify 决定一次攻击的关键时间点；
- GameplayTag 连接动画、Ability 和 Combat Socket；
- DataAsset 决定职业属性和授予能力；
- Behavior Tree 负责决定何时攻击；
- GAS 和服务器负责决定攻击是否生效；
- 材质实例负责死亡后的视觉表现。

只要这些接口约定保持一致，后续创建冰霜法师、治疗祭司或闪电萨满时，都可以沿用同一套流程，主要替换动画、投射物、伤害类型、职业能力和表现资产，而不必重新设计整个敌人系统。
