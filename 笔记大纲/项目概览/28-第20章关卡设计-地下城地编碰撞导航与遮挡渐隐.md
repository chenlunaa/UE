## 1. 为什么现在要做关卡

平面测试地图无法暴露大型几何体挡住相机和鼠标、点击移动与 NavMesh、楼梯高差、投射物碰撞、纹理预算等真实问题。

本章建立了三条系统链：

~~~text
关卡几何体
  -> Collision Channel
  -> Cursor Trace / Projectile / Camera
  -> Navigation Mesh

灯光与环境
  -> Directional Light / Sky Light
  -> Post Process Volume
  -> Niagara / 动态火光

相机遮挡
  -> 角色与相机之间的 Box Overlap
  -> Blueprint Interface
  -> Fade Actor
  -> Dynamic Material Instance
~~~

<a id="section-2"></a>
## 2. 创建地下城地图

### 2.1 新建并保存

1. 选择 File > New Level；
2. 使用带基础光照的模板；
3. 保存到 Maps 目录，命名为 Dungeon；
4. 在 Project Settings > Maps & Modes 设置 Editor Startup Map 和 Game Default Map。

### 2.2 整理 World Outliner

~~~text
Lighting
├── DirectionalLight
├── SkyLight
├── SkyAtmosphere
├── VolumetricCloud
└── PostProcessVolume

DungeonMeshes
├── Floor / Walls / Stairs
└── Railings / Decorations

FadeActors
PlayerStart
NavMeshBoundsVolume
~~~

文件夹便于批量选择。例如需要让所有大型网格忽略 Camera 时，可以直接选择整个文件夹。

<a id="section-3"></a>
## 3. 模块化地下城搭建

模块化资产通常按固定尺寸制作，应使用 Translation/Rotation Snap：

~~~text
第一个地砖放在世界原点
  -> 开启网格吸附
  -> Alt 拖动复制
  -> 旋转 90° 制造变化
  -> 混用破损变体减少重复感
~~~

关闭吸附后大量复制容易产生地砖缝隙、Z-Fighting、墙体拼接错误和平台高度不一致。

推荐顺序：

1. 地板和主要通道；
2. 墙体、封闭区域和高度变化；
3. 楼梯、栏杆和柱子；
4. PlayerStart 和 NavMesh；
5. 碰撞验证；
6. 光照、火焰和装饰；
7. 后处理和性能调优。

先做可玩的灰盒，再做装饰，避免做好美术后才发现角色或 AI 无法通过。

<a id="section-4"></a>
## 4. 光照与后处理

默认白天模板过亮，会削弱火焰和 Niagara。地下城光照可以采用：

~~~text
低强度环境光
+ 冷色全局基调
+ 暖色火焰局部光
+ 适度后处理对比度
~~~

### Post Process Volume

1. 放入 Post Process Volume；
2. 勾选 Infinite Extent (Unbound)；
3. 在 Post Process Materials 数组加入项目高亮材质；
4. 调整 Exposure、Color Grading、Saturation、Contrast、Shadows；
5. 用实际角色、血效、火球和火焰进行对照。

不能只看环境调色，还要确认角色没有偏色、Custom Depth 高亮清晰、火焰不过曝、暗部可辨认路径、Niagara 没被压成单色。

编辑器性能不足时可降低 Engine Scalability 预览，但这不等于解决纹理和粒子预算。

<a id="section-5"></a>
## 5. 静态网格碰撞 Bug

### 5.1 角色穿地或穿墙

**现象：**角色掉出地图、穿墙或投射物穿柱。

**原因：**网格没有 Simple Collision，或自动碰撞形状不合适。

**定位：**

1. 打开 Static Mesh；
2. 开启 Show > Simple Collision；
3. 检查绿色碰撞体；
4. 查看 Collision Complexity 和 Presets。

**修复：**添加 Box/Sphere/Capsule Simple Collision；删除错误自动碰撞后重建。原型阶段可临时使用 Complex Collision as Simple，但大量高模正式发布不建议这样做。

### 5.2 栏杆堵住整个开口

自动凸包可能把视觉空隙包成一面碰撞墙。应删除自动碰撞，用多个简单 Box 只覆盖立柱和横杆。碰撞表达玩法边界，不必完全复制视觉模型。

<a id="section-6"></a>
## 6. Collision Channel 分工

| 通道 | 使用者 | 需求 |
|---|---|---|
| Visibility | CursorTrace、点击地面 | 找到可点击位置或目标 |
| Projectile | 火球、石块 | 被墙体和障碍阻挡 |
| Camera | Spring Arm | 是否缩短相机距离 |

装饰柱可设置：

~~~text
Projectile：Block
Visibility：Ignore
Camera：Ignore
~~~

楼梯可能需要 Block Visibility，因为点击楼梯表面要获得有效 Hit Location。

Projectile 使用 Overlap 回调时，还必须启用 Generate Overlap Events，并保证 Collision Enabled 至少为 Query。只改通道响应但关闭 Overlap，不会触发 BeginOverlap。

<a id="section-7"></a>
## 7. 点击移动与 NavMesh

~~~text
CursorTrace by Visibility
  -> 地面 Hit Location
  -> NavigationSystem 查找路径
  -> Spline 保存路径点
  -> AutoRun 沿路径移动
~~~

需要同时满足：Visibility 命中合理表面、目标位于 NavMesh、障碍碰撞影响导航、NavMeshBoundsVolume 覆盖对应高度。

### 7.1 点击后不移动

可能原因：

- 未放置或未覆盖 NavMeshBoundsVolume；
- 装饰物抢先 Block Visibility；
- 地板 Ignore Visibility；
- 碰撞体把通路封死。

按 P 显示 NavMesh，查看点击位置是否为绿色，并检查 CursorTrace 的 Hit Actor。

### 7.2 点击楼梯却跑到下面

原因是楼梯下方仍被认为可通行，视觉网格与导航阻挡不一致。

修复：

- 在楼梯下方加 Box Collision 封住空洞；
- 增大 NavMeshBoundsVolume 的 Z 高度；
- 重建导航并按 P 检查上下层区域。

### 7.3 点击栏杆无法寻路

栏杆 Block Visibility 时，Hit Location 可能落在不可导航位置。让栏杆 Ignore Visibility、Block Projectile；让楼梯和地板负责接收点击。

<a id="section-8"></a>
## 8. Texture Streaming Pool Over Budget

环境中大量 4K/8K 纹理会造成纹理流送池超预算，出现模糊、Mip 频繁切换和显存压力。

### 8.1 优先降低纹理尺寸

单个纹理在 Compression/Advanced 中设置 Max Texture Size。批量处理：

1. Content Browser 过滤 Texture；
2. 按 Dungeon、Tile、Stair 等筛选；
3. 多选；
4. Asset Actions > Bulk Edit via Property Matrix；
5. 批量设置 Max Texture Size。

| 资产 | 建议起点 |
|---|---:|
| 大量重复地砖、远景 | 512 |
| 楼梯、墙面等中景 | 1024 |
| 关键近景装饰 | 2048 |
| UI、角色脸部 | 不要与环境批量处理 |

压缩后短暂模糊可能是缓存尚未刷新，保存并重启后再评估。

### 8.2 增加 Pool 不是第一选择

目标硬件显存足够时，可在 DefaultEngine.ini 中设置：

~~~ini
[/Script/Engine.RendererSettings]
r.TextureStreaming=True
r.Streaming.PoolSize=1000
~~~

正确顺序是先降低不必要的分辨率，再评估目标显存，最后合理增加 Pool。单纯调大 Pool 只是在高显存机器上推迟问题。

<a id="section-9"></a>
## 9. BP_FirePillar 动态火焰柱

### 9.1 组件结构

~~~text
BP_FirePillar
└── Pillar：StaticMesh
    └── Flame：NiagaraComponent
        └── FireLight：PointLightComponent
~~~

灯光要在运行时改变强度，不能是 Static。位置固定但强度变化时使用 Stationary；需要移动才用 Movable。

### 9.2 随机时间线避免同步闪烁

所有实例同时播放同一曲线会同步闪烁。创建两条长度和曲线不同的 Timeline：

~~~text
BeginPlay
  -> SelectTimeline
  -> Random Integer 0/1
  -> Switch on Int
      0 -> Start Timeline 1
      1 -> Start Timeline 2

Timeline Update
  -> SetIntensity(BaseIntensity * CurveValue)

Timeline Finished
  -> SelectTimeline
~~~

将重复运算折叠为 ScaleFireIntensity 函数。每次完成后随机选择下一条，多实例就不会显得同步。

火焰柱推荐 Block Projectile、Ignore Visibility、Ignore Camera。

<a id="section-10"></a>
## 10. 为什么需要遮挡渐隐

Spring Arm 遇到墙会收缩，导致俯视镜头突然拉近。本章选择：

1. 大型几何体 Ignore Camera，保持相机距离；
2. 几何体位于角色与相机之间时渐隐；
3. 保留对 Projectile 和必要 Visibility 的响应。

<a id="section-11"></a>
## 11. Fade Material 与 DitherTemporalAA

Translucent 成本较高且有排序问题。本章复制原材质，创建 Masked 渐隐版本：

~~~text
Scalar Parameter "Fade"（默认 1）
  -> DitherTemporalAA
  -> Opacity Mask

Blend Mode = Masked
~~~

Fade 为 1 时可见，为 0 时消失，中间值通过时间抖动渐隐。

资产层级：

~~~text
原始 Material：Opaque
  -> 原始 Material Instance

Fade Material 副本：Masked + Fade
  -> Fade Material Instance
  -> 运行时 Dynamic Material Instance
~~~

动态修改参数必须使用 MID。复制材质而不直接改原材质，是为了避免所有环境资产长期承担 Masked 成本。

<a id="section-12"></a>
## 12. BP_FadeActor 数据结构

| 变量 | 类型 | 作用 |
|---|---|---|
| OriginalMaterials | MaterialInterface Array | 保存原始材质 |
| FadeMaterialInstances | MaterialInstance Array | 编辑器配置的渐隐材质 |
| DynamicMaterialInstances | MaterialInstanceDynamic Array | 运行时修改 Fade |
| BlockVisibility | Bool | 淡入后是否阻挡 Visibility |

### 12.1 Construction Script

~~~text
Get Materials(Mesh)
  -> Set OriginalMaterials

Clear DynamicMaterialInstances
  -> For Each FadeMaterialInstances
  -> Create Dynamic Material Instance
  -> Add 到 DynamicMaterialInstances
~~~

Construction Script 可能在编辑器反复执行，所以先 Clear，避免重复追加。

### 12.2 切换和恢复材质

SetMaterialsToDynamicInstances：

~~~text
For Each DynamicMaterialInstances
  -> Mesh.SetMaterial(ArrayIndex, ArrayElement)
~~~

ResetMaterials：

~~~text
For Each OriginalMaterials
  -> Mesh.SetMaterial(ArrayIndex, ArrayElement)
~~~

淡入结束恢复 Opaque 原材质，避免不渐隐时持续承担 Masked 成本。

<a id="section-13"></a>
## 13. Fade Timeline

创建 0.4～1 秒 Float Timeline：

~~~text
Time 0   -> Fade 1
Time End -> Fade 0
~~~

~~~text
FadeOut
  -> SetMaterialsToDynamicInstances
  -> Timeline Play

FadeIn
  -> Timeline Reverse

Timeline Update
  -> 每个 MID Set Scalar Parameter "Fade"
~~~

Finished 时，Fade >= 1 代表淡入完成并 ResetMaterials；Fade <= 0 代表淡出完成。不要使用浮点精确等于比较。

<a id="section-14"></a>
## 14. Bug：MID 有元素但不渐隐

**现象：**数组长度正确，Set Scalar Parameter 也执行，网格仍不透明。

**根因：**MID 基于原始 Opaque 材质创建，原材质没有 Fade 参数和 Opacity Mask。

**错误流程：**

~~~text
OriginalMaterials -> Create MID -> Set Fade
~~~

**正确流程：**

~~~text
FadeMaterialInstances -> Create MID
  -> Mesh.SetMaterial -> Set Fade
~~~

OriginalMaterials 只用于最终恢复。

<a id="section-15"></a>
## 15. Bug：多材质网格只部分渐隐或材质错位

原因包括：

- FadeMaterialInstances 少于 Material Slots；
- 数组顺序与 Slot Index 不一致；
- 某个父材质没有 Fade 版本；
- 误选 Material 而不是 Material Instance。

修复步骤：

1. 在 Static Mesh 中记录 Slot 0～N；
2. 为每个父材质制作 Masked Fade 副本；
3. 创建对应实例；
4. 按 Slot Index 顺序填入数组；
5. 确认动态数组长度一致；
6. 逐槽测试。

材质数组按位置匹配，不会按名字自动匹配。

<a id="section-16"></a>
## 16. Blueprint Interface 解耦

创建 BPI_FadeInterface：

~~~text
FadeOut
FadeIn
~~~

BP_FadeActor 实现接口，用接口 Event 替换同名 Custom Event。

Aura Character 只知道“这个 Actor 能淡出”，无需 Cast 到具体 FadeActor，也不依赖墙、楼梯或栏杆子类。

<a id="section-17"></a>
## 17. 角色与相机之间的 Box Collision

在 Aura Character 蓝图中：

1. 选择 Spring Arm；
2. 添加 Box Collision 子组件；
3. 放在相机与角色之间；
4. 宽度略窄于角色胶囊；
5. Collision Enabled = Query Only；
6. Ignore All，仅 Overlap WorldStatic；
7. 开启 Generate Overlap Events。

事件图：

~~~text
Box BeginOverlap(OtherActor)
  -> Does Implement Interface
  -> True：Execute FadeOut

Box EndOverlap(OtherActor)
  -> Does Implement Interface
  -> True：Execute FadeIn
~~~

盒体挂在 Spring Arm 下，会随相机方向保持在角色和相机之间。

盒体太大会提前淡出，太小会延迟，太宽会在贴墙时误触发，需要在运行中调整。

<a id="section-18"></a>
## 18. Bug：渐隐 Actor 阻止移动

视觉消失不等于物理碰撞消失。Fade 只控制材质。

应分开决定：

- Pawn/WorldStatic：是否允许角色通过；
- Visibility：是否挡住点击和选敌；
- Projectile：是否挡火球；
- Camera：是否让 Spring Arm 收缩。

不要用 NoCollision 一刀切，否则墙可能不能挡角色和火球。

<a id="section-19"></a>
## 19. Bug：墙已消失但鼠标仍被挡

材质 Fade 不会修改 Collision Response，墙仍 Block Visibility。

淡出完成：

~~~text
Visibility = Ignore
~~~

淡入完成根据 BlockVisibility：

~~~text
BlockVisibility = true  -> Visibility = Block
BlockVisibility = false -> 保持 Ignore
~~~

楼梯需要点击可设 true；纯装饰柱和顶墙可设 false。

<a id="section-20"></a>
## 20. Bug：渐隐阴影闪烁

Masked Dither 与动态阴影可能产生颗粒和残影。本章对 Fade Mesh 关闭 Cast Shadow，保证稳定表现。关键物体必须投影时，需要专用材质和阴影方案。

<a id="section-21"></a>
## 21. Fade Actor 子类化

~~~text
BP_FadeActor
├── FA_Tile_3x3x2
├── FA_Stairs
├── FA_RailingCorner
└── FA_Wall
~~~

子类只配置 Static Mesh、Fade Material Instances、BlockVisibility、碰撞和 Cast Shadow。

替换旧网格：

1. Copy Transform；
2. 删除旧 Actor；
3. 拖入 Fade 子类；
4. Paste Transform；
5. 验证碰撞和材质槽；
6. 移入 FadeActors 文件夹。

<a id="section-22"></a>
## 22. Bug 总表

| Bug | 根因 | 解决 |
|---|---|---|
| 穿地/穿墙 | 无 Simple Collision | 添加简单碰撞 |
| 栏杆堵开口 | 自动凸包过大 | 多个 Box 覆盖实体部分 |
| 火球穿柱 | Projectile 响应/Overlap 错误 | 配置通道并启用 Query |
| 点击装饰物不移动 | 装饰物 Block Visibility | Ignore Visibility |
| 点击楼梯跑到下面 | 下方仍可导航 | 下方加碰撞并重建 NavMesh |
| 上层无 NavMesh | Bounds 高度不足 | 增大 Z 范围 |
| Streaming Pool 超预算 | 高分辨率纹理过多 | 批量限尺寸，再调 Pool |
| 火焰同步闪烁 | 同一 Timeline 同时开始 | 多曲线随机循环 |
| MID 不渐隐 | 基于原 Opaque 材质 | 从 Fade 实例创建 MID |
| 部分材质不渐隐 | 槽数量/顺序错误 | 按 Slot Index 配齐 |
| 淡出后仍挡鼠标 | 碰撞未变化 | Ignore Visibility |
| 淡入后楼梯不能点击 | 未恢复 Block | BlockVisibility 条件恢复 |
| 阴影闪烁 | Dither 与阴影冲突 | 关闭 Cast Shadow |
| 墙消失但仍不能通过 | 物理碰撞仍存在 | 分开配置 Pawn/查询通道 |

<a id="section-24"></a>
## 24. 本章总结

~~~text
模块化网格决定空间
  -> Simple Collision 决定物理边界
  -> Visibility 决定点击与选敌
  -> Projectile 决定弹道阻挡
  -> Camera 决定镜头是否收缩
  -> NavMesh 决定角色和 AI 能否到达
  -> Fade Interface 解决俯视遮挡
  -> Texture/Niagara/Light 预算决定性能
~~~

同一块墙在视觉、物理、鼠标、投射物、相机和导航系统中扮演不同角色。排错时应依次问：

1. 哪个组件参与？
2. Object Type 是什么？
3. 查询哪个 Channel？
4. 应该 Block、Overlap 还是 Ignore？
5. 是否需要 Generate Overlap Events？
6. NavMesh 是否重新构建？
7. 是否把材质变化误认为碰撞变化？

用这套问题，就能分层定位穿模、点击失效、投射物穿墙、相机拉近和遮挡渐隐问题。
