## 1. 本章完成的系统

```text
敌人死亡
  → 根据敌人职业和等级计算 XPReward
  → 发送 Attribute.Meta.IncomingXP 游戏事件给攻击者
  → IncomingXP 元属性接收并清零
  → PlayerInterface::AddToXP
  → AAuraPlayerState::AddToXP
  → OnXPChangedDelegate.Broadcast(XP)
  → OverlayWidgetController::OnXPChanged
  → LevelUpInfo 查找当前等级
  → 计算当前等级区间百分比
  → OnXPPercentChangedDelegate.Broadcast(Percent)
  → WBP_XPBar.ProgressBar_XP.SetPercent
```

新增的关键代码资产：

- `ULevelUpInfo` / `FAuraLevelUpInfo`：等级需求和奖励的数据资产；
- `IncomingXP`：属性集中的元属性；
- `IPlayerInterface`：属性集向玩家角色传递 XP、升级命令的解耦接口；
- `AAuraPlayerState::XP`：服务器权威、复制到客户端的累计经验；
- `OnXPPercentChangedDelegate`：Overlay 到 XPBar 的 UI 委托；
- `GetXPRewardForClassAndLevel`：按敌人职业和等级读取经验奖励；
- `GetCharacterClass`、`GetPlayerLevel`：统一改为 `BlueprintNativeEvent` 的接口查询。

## 2. 累计 XP 的数学模型

本项目把 XP 定义为**从游戏开始到现在的累计总经验**，而不是“当前等级内的经验”。例如：

| 等级 | 达到该等级所需累计 XP | 本级新增所需 XP |
|---:|---:|---:|
| 1 | 0（占位） | - |
| 2 | 300 | 300 |
| 3 | 900 | 600 |
| 4 | 2700 | 1800 |

这样做的好处是升级判断直接比较累计值，而且可以自然处理一次奖励导致的多级升级。例如角色有 180 XP，一次获得 1000 XP 后变为 1180 XP，已经超过 900，因此应从 1 级连续提升到 3 级。

升级需求可以用公式（如 `100 × Level³`），也可以手工配置。课程选择 DataAsset，是因为手工表可以自由调整曲线，并且能和属性点、法术点等奖励放在同一条等级记录中。

## 3. `ULevelUpInfo` 数据资产

### 3.1 结构体

```cpp
USTRUCT(BlueprintType)
struct FAuraLevelUpInfo
{
    GENERATED_BODY()

    UPROPERTY(EditDefaultsOnly)
    int32 LevelUpRequirement = 0;

    UPROPERTY(EditDefaultsOnly)
    int32 AttributePointAward = 1;

    UPROPERTY(EditDefaultsOnly)
    int32 SpellPointAward = 1;
};
```

每个数组元素对应一个等级。`AttributePointAward` 和 `SpellPointAward` 目前只是为后续升级奖励预留的数据，尚未在本章消费。

### 3.2 数组索引约定

课程采用：

```text
Index 0：无效/占位
Index 1：1 级数据
Index 2：2 级数据
...
```

因此 `LevelUpInformation[Level]` 才能直接读取该等级信息。创建 DataAsset 后，必须至少保留索引 0，并在蓝图中填充后续各级的 `LevelUpRequirement`。

### 3.3 按 XP 查找等级

```cpp
int32 ULevelUpInfo::FindLevelForXP(int32 XP) const
{
    int32 Level = 1;
    bool bSearching = true;

    while (bSearching)
    {
        if (LevelUpInformation.Num() - 1 <= Level)
        {
            return Level;
        }

        if (XP >= LevelUpInformation[Level].LevelUpRequirement)
        {
            ++Level;
        }
        else
        {
            bSearching = false;
        }
    }
    return Level;
}
```

算法从 1 级开始：只要 XP 已达到当前等级门槛就继续加级，直到 XP 不足以下一级门槛。它天然支持双倍、三倍甚至多级升级。

边界注意：

- 数组为空或只有占位元素时返回 1；
- XP 超过最高已配置等级时返回数组支持的最高等级；
- 生产版本可额外检查负 XP、数组索引和最高等级定义，避免数据资产配置错误导致越界。

## 4. PlayerState：保存并复制 XP

### 4.1 为什么 XP 放 PlayerState 而不是 AttributeSet

Attribute 更适合参与战斗计算、Modifier、MMC 和属性变化通知。XP 是玩家进度标记，通常不参与伤害或防御公式，因此放在 `AAuraPlayerState` 更清晰。

```cpp
UPROPERTY(VisibleAnywhere, ReplicatedUsing=OnRep_XP)
int32 XP = 1;
```

服务器负责修改 XP，客户端通过复制获得结果。等级 `Level` 也采用同样模式。

### 4.2 修改函数和委托

```cpp
DECLARE_MULTICAST_DELEGATE_OneParam(
    FOnPlayerStateChanged, int32 /*StateValue*/);

void AddToXP(int32 InXP)
{
    XP += InXP;
    OnXPChangedDelegate.Broadcast(XP);
}

void SetXP(int32 InXP)
{
    XP = InXP;
    OnXPChangedDelegate.Broadcast(XP);
}
```

等级也补充 `AddToLevel`、`SetLevel` 和 `OnLevelChangedDelegate`，形成一致的状态更新模式。

### 4.3 复制注册和 RepNotify

```cpp
void AAuraPlayerState::GetLifetimeReplicatedProps(
    TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);
    DOREPLIFETIME(AAuraPlayerState, Level);
    DOREPLIFETIME(AAuraPlayerState, XP);
}

void AAuraPlayerState::OnRep_XP(int32 OldXP)
{
    OnXPChangedDelegate.Broadcast(XP);
}
```

服务器调用 `AddToXP` 时立即广播本地委托；远程客户端收到复制后调用 `OnRep_XP` 再广播一次本地委托。这样服务器和每个客户端的 HUD 都能刷新，而不是依赖服务器的 C++ 委托跨网络传播。

### 4.4 LevelUpInfo 放在哪里

`LevelUpInfo` 作为 `AAuraPlayerState` 的 `TObjectPtr<ULevelUpInfo>` 配置：

```cpp
UPROPERTY(EditDefaultsOnly)
TObjectPtr<ULevelUpInfo> LevelUpInfo;
```

原因：WidgetController 在客户端也需要它，而客户端没有 GameMode。GameMode 中的 `CharacterClassInfo` 适合服务器游戏规则；玩家自己的升级表需要放到客户端可访问的 PlayerState 或其他可复制/可加载对象中。蓝图中必须实际把 `DA_LevelUpInfo` 指定给 PlayerState，否则 Controller 的 `checkf` 会失败。

## 5. 从敌人死亡到 XP 奖励

### 5.1 为敌人配置 XPReward

`FCharacterClassDefaultInfo` 增加：

```cpp
UPROPERTY(EditDefaultsOnly, Category="Class Defaults")
FScalableFloat XPReward = FScalableFloat();
```

每种职业可以在 `DA_CharacterClassInfo` 中配置独立曲线：

```text
Elementalist / Warrior / Ranger
    └─ XPReward Curve：按敌人 Level 返回经验
```

辅助函数：

```cpp
int32 UAuraAbilitySystemLibrary::GetXPRewardForClassAndLevel(
    const UObject* WorldContextObject,
    ECharacterClass CharacterClass,
    int32 Level);
```

它读取 CharacterClassInfo，按职业取 `FScalableFloat`，再用敌人等级求值。当前实现把 `float` 转成 `int32`；如果游戏需要小数 XP，应把整个链路改成浮点数。

### 5.2 `SendXPEvent`

致命伤害在 `UAuraAttributeSet::PostGameplayEffectExecute` 中确认：

```cpp
if (LocalIncomingDamage > 0.f)
{
    if (CombatInterface->IsDead())
    {
        CombatInterface->Die();
        SendXPEvent(Props);
    }
}
```

`SendXPEvent` 的步骤：

1. 从 `Props.TargetCharacter` 取得敌人的 `GetPlayerLevel()` 和 `GetCharacterClass()`；
2. 调用 `GetXPRewardForClassAndLevel` 得到 XPReward；
3. 创建 `FGameplayEventData`；
4. 将 `EventMagnitude` 设为 XPReward；
5. 把事件标签设为 `Attribute.Meta.IncomingXP`；
6. 用 `SendGameplayEventToActor` 发给 `Props.SourceCharacter`（攻击者）。

经验来自被击杀目标，但接收者是造成致命伤害的玩家。

## 6. IncomingXP：通过 GAS 元属性接收

### 6.1 为什么仍然使用元属性

虽然 XP 最终不存 AttributeSet，但元属性可以复用现有 GAS 事件/效果管线：伤害计算、事件标签、SetByCaller 和 PostGameplayEffectExecute 都能沿用。

```cpp
UPROPERTY(BlueprintReadOnly, Category="Meta Attributes")
FGameplayAttributeData IncomingXP;
ATTRIBUTE_ACCESSORS(UAuraAttributeSet, IncomingXP);
```

新增原生标签：

```cpp
Attribute.Meta.IncomingXP
```

### 6.2 事件转 GE

监听 IncomingXP 的 GameplayAbility 使用 `WaitGameplayEvent`。事件携带 `EventMagnitude`，蓝图将其用于 `SetByCaller`，再应用一个 Instant GE：

```text
Wait Gameplay Event(Attribute.Meta.IncomingXP)
  → Make Effect Spec（GE_IncomingXP）
  → Set By Caller Magnitude
  → Apply Gameplay Effect
```

`GE_IncomingXP` 的 Modifier 加法修改 `IncomingXP`，值由调用者设置，而不是写死在 GE 中。

### 6.3 在 PostGameplayEffectExecute 中消费

```cpp
if (Data.EvaluatedData.Attribute == GetIncomingXPAttribute())
{
    const int32 LocalIncomingXP = GetIncomingXP();
    SetIncomingXP(0.f);

    if (Props.SourceCharacter &&
        Props.SourceCharacter->Implements<UPlayerInterface>())
    {
        IPlayerInterface::Execute_AddToXP(
            Props.SourceCharacter, LocalIncomingXP);
    }
}
```

元属性是“一次性事件缓存”：先读出、再清零，避免同一 XP 被下一次 GE 重复消费。真正持久保存的是 PlayerState 的 XP。

## 7. PlayerInterface：解除 AttributeSet 与 PlayerState 的耦合

### 7.1 接口定义

```cpp
UINTERFACE(MinimalAPI)
class UPlayerInterface : public UInterface
{
    GENERATED_BODY()
};

class IPlayerInterface
{
    GENERATED_BODY()

public:
    UFUNCTION(BlueprintNativeEvent)
    void AddToXP(int32 InXP);

    UFUNCTION(BlueprintNativeEvent)
    void LevelUp();
};
```

`UAuraAttributeSet` 只知道“源角色是否支持增加 XP”，不需要包含或依赖 `AAuraPlayerState`。`AAuraCharacter` 实现接口，再由角色访问自己的 PlayerState：

```cpp
void AAuraCharacter::AddToXP_Implementation(int32 InXP)
{
    AAuraPlayerState* PS = GetPlayerState<AAuraPlayerState>();
    check(PS);
    PS->AddToXP(InXP);
}
```

这样避免属性集和 PlayerState 之间的紧耦合及潜在循环依赖。

### 7.2 蓝图原生事件的调用规则

对于 `BlueprintNativeEvent`：

- C++ 实现函数名是 `FunctionName_Implementation`；
- 通过接口静态调用时使用 `IPlayerInterface::Execute_AddToXP(Object, Value)`；
- 判断对象是否实现接口时使用 `Object->Implements<UPlayerInterface>()`。

不要把 `UPlayerInterface` 和 `IPlayerInterface` 混用：前者是反射/类型判断的 UObject 接口类，后者是 C++ 调用包装接口。

## 8. OverlayWidgetController 计算 XP 百分比

PlayerState 广播的是累计 XP，不是百分比。Controller 在 `OnXPChanged` 中把它转换为当前等级内进度：

```cpp
const int32 Level = LevelUpInfo->FindLevelForXP(NewXP);
const int32 LevelUpRequirement =
    LevelUpInfo->LevelUpInformation[Level].LevelUpRequirement;
const int32 PreviousRequirement =
    LevelUpInfo->LevelUpInformation[Level - 1].LevelUpRequirement;

const int32 Delta = LevelUpRequirement - PreviousRequirement;
const int32 CurrentXP = NewXP - PreviousRequirement;
const float Percent = static_cast<float>(CurrentXP)
    / static_cast<float>(Delta);

OnXPPercentChangedDelegate.Broadcast(Percent);
```

公式：

```text
本级进度 = (累计 XP - 当前等级起点 XP)
         / (下一级门槛 XP - 当前等级起点 XP)
```

例如累计 XP 为 500，当前等级区间是 300～900：

```text
(500 - 300) / (900 - 300) = 33.3%
```

这就是为什么不能直接用 `XP / MaxXP`：MaxXP 必须随当前等级变化。

边界处理建议：

- `LevelUpInfo` 为空时提前返回或明确报错；
- `Delta <= 0` 时避免除零；
- `Percent` 最终可 `Clamp(0, 1)`；
- 最高等级没有下一等级门槛时，应显示 1 或采用“满级”分支。

## 9. 蓝图连接 XPBar

### 9.1 Overlay 设置控制器

在 `WBP_Overlay`：

1. 将 `WBP_XPBar` 勾选 **Is Variable**；
2. 在 `WidgetControllerSet` 中调用 XPBar 的 `SetWidgetController`；
3. XPBar 中 Cast 为 `BP_OverlayWidgetController`；
4. 将 Controller 保存为变量；
5. Assign `OnXPPercentChangedDelegate`。

### 9.2 经验条响应

```text
OnXPPercentChanged(NewPercent)
  → ProgressBar_XP
  → Set Percent(NewPercent)
```

设计器默认把 ProgressBar Percent 设为 0，让经验条从空状态开始。不要让 XPBar 自己查询 PlayerState；数据由 Controller 委托推送。

### 9.3 初始化时机

Overlay、PlayerState、LevelUpInfo 和委托绑定必须全部有效。若玩家一进入游戏经验条没有初始值，可以在 `BroadcastInitialValues` 中额外广播当前 XP，或在绑定完成后主动调用一次 `OnXPChanged(CurrentXP)`。

## 10. 本章重构：GetPlayerLevel 改为 BlueprintNativeEvent

原先项目大量使用 C++ 虚函数或直接 Cast 到 `ICombatInterface`。本章将 `GetPlayerLevel` 改为：

```cpp
UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
int32 GetPlayerLevel();
```

同时新增/统一：

```cpp
UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
ECharacterClass GetCharacterClass();
```

### 10.1 为什么重构

- C++ 和蓝图都能实现/调用；
- 调用方不需要强制转换成 `ICombatInterface*`；
- 对效果演员、环境伤害等“不一定实现接口”的对象更容易安全处理；
- `Execute_GetPlayerLevel(Object)` 形式在整个项目中一致。

### 10.2 正确调用方式

```cpp
int32 PlayerLevel = 1;
if (SourceObject && SourceObject->Implements<UCombatInterface>())
{
    PlayerLevel = ICombatInterface::Execute_GetPlayerLevel(SourceObject);
}
```

注意：

- `Implements<UCombatInterface>()` 用 `U` 接口类型；
- `Execute_GetPlayerLevel` 用 `ICombatInterface`；
- 传入被调用的 UObject；
- 不要在 C++ 中继续保留旧的同名函数定义，否则 UHT 生成的 NativeEvent 包装会造成重复定义链接错误。

### 10.3 MMC 和 ExecCalc 中的影响

`MMC_MaxMana`、`MMC_MaxHealth`、`ExecCalc_Damage` 等地方不再盲目 Cast 接口：

```text
默认 playerLevel = 1
→ 源对象 Implements<UCombatInterface>()？
   ├─ 是：Execute_GetPlayerLevel(SourceObject)
   └─ 否：保留默认等级
```

这样火焰区域、效果演员等非角色来源不会因为空接口指针导致崩溃。`ExecCalc_Damage` 还可以先缓存 `SourcePlayerLevel`、`TargetPlayerLevel`，再把它们传给后续曲线计算，避免多次查询。

## 11. 典型问题与修复

| 问题 | 原因 | 修复 |
|---|---|---|
| XP 条不动 | XPBar 未设置 WidgetController 或未绑定委托 | Overlay 中传递 Controller，并 Assign XP 委托 |
| Controller 崩溃 | PlayerState 没有设置 `DA_LevelUpInfo` | 在 PlayerState 蓝图默认值中指定数据资产 |
| XP 一直为 0 | IncomingXP 没有通过事件应用 GE | 检查事件标签、WaitGameplayEvent、SetByCaller 和 Modifier |
| 杀敌没有 XP | 只有致命伤害才调用 `SendXPEvent` | 检查死亡判断和 SourceCharacter |
| 客户端 XP 不更新 | 只在服务器广播 C++ 委托 | XP 使用 RepNotify，在 `OnRep_XP` 中本地广播 |
| 经验百分比除零 | 相邻等级门槛相同或配置错误 | 检查 `DeltaLevelRequirement > 0` |
| 多级升级显示错误 | 把 XP 当成当前等级内值 | 使用累计 XP + `FindLevelForXP` 循环 |
| 重构后链接错误 | BlueprintNativeEvent 仍保留旧同名定义 | 删除旧定义，保留 `_Implementation` |
| 效果演员导致崩溃 | 对未实现 CombatInterface 的对象强制 Cast | `Implements<UCombatInterface>()` 后再 Execute |

## 12. 测试清单

### 数据资产

- `DA_LevelUpInfo` 有索引 0 占位和连续等级数据；
- 各级门槛递增；
- 属性点、法术点奖励字段已填充；
- PlayerState 正确引用该 DataAsset；
- 各职业 XPReward 曲线能按等级返回值。

### XP 流程

- 普通伤害不会给 XP；
- 致命伤害只奖励一次；
- 攻击者得到经验，被击杀者不会得到经验；
- `IncomingXP` 消费后清零；
- XP 通过 PlayerState 累加并广播；
- 客户端收到复制后 XPBar 同步。

### 等级与百分比

- 0～下一级门槛之间百分比从 0 增加到 1；
- 一次大奖励跨越多个门槛时等级查找正确；
- 最高已配置等级不会越界；
- XP 条不显示负数或超过 100%；
- Listen Server 和远程 Client 都能看到相同进度。

### 接口重构

- `GetPlayerLevel`、`GetCharacterClass` 的调用统一使用 Execute 版本；
- MMC、ExecCalc 面对无接口对象不会崩溃；
- C++ 实现只保留 `_Implementation`；
- 多人 PIE、专用服务器测试伤害和 XP 都正常。

## 13. 本章核心认识

本章建立了一个清晰的“事件—状态—表现”分层：

- **事件**：IncomingXP 元属性和 GameplayEvent，只表示一次经验奖励；
- **状态**：PlayerState 的累计 XP、Level，服务器修改并复制；
- **表现**：OverlayWidgetController 根据等级表计算百分比，XPBar 只负责显示。

敌人职业和等级决定奖励，GAS 负责传递事件，PlayerInterface 负责解耦玩家对象，PlayerState 负责持久状态，WidgetController 负责 UI 适配。下一步只需在 IncomingXP 处理处加入升级判断和奖励发放，就能把“经验条增长”扩展成完整的 RPG 升级循环。
