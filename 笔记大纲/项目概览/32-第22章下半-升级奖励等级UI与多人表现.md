## 1. 本章完成了什么

上一章已经能够把击杀奖励转换成累计 XP，但“XP 达到门槛”还没有真正改变玩家等级。本章补齐完整升级闭环：

```text
敌人死亡并发送 XP 事件
  → IncomingXP 接收奖励
  → 读取当前 XP 和当前等级
  → 用新 XP 查询目标等级
  → 计算本次提升的等级数
  → 更新 PlayerState.Level
  → 查询属性点 / 法术点奖励并调用预留接口
  → 恢复 Health / Mana
  → 添加累计 XP
  → PlayerState 委托与 RepNotify 广播
     ├─ XPBar 更新
     ├─ 等级球更新
     └─ 创建升级消息
  → NetMulticast 播放升级 Niagara
```

本章将升级拆成了三层：

- **规则层**：属性集判断是否升级并发放数值奖励；
- **状态层**：PlayerState 保存等级和 XP，点数状态留待后续补齐；
- **表现层**：Overlay、Niagara、声音和 Widget 动画展示结果。

表现层不决定玩家是否升级，它只响应服务器已经确认的状态变化。

<a id="section-2"></a>
## 2. 从获得 XP 到正式升级

升级判断发生在 `UAuraAttributeSet::PostGameplayEffectExecute` 消费 `IncomingXP` 的分支中。首先取得三个值：

```cpp
const int32 CurrentLevel =
    ICombatInterface::Execute_GetPlayerLevel(Props.SourceCharacter);

const int32 CurrentXP =
    IPlayerInterface::Execute_GetXP(Props.SourceCharacter);

const int32 NewLevel =
    IPlayerInterface::Execute_FindLevelForXP(
        Props.SourceCharacter,
        CurrentXP + LocalIncomingXP);
```

核心计算是：

```cpp
const int32 NumLevelUps = NewLevel - CurrentLevel;
```

结果分为两种：

```text
NumLevelUps <= 0
  → 只增加 XP，不升级

NumLevelUps > 0
  → 升级 NumLevelUps 次
  → 发放属性点和法术点
  → 恢复生命与法力
  → 播放升级表现
```

使用目标等级减当前等级，而不是简单写成“超过下一门槛就加 1”，是为了支持一次获得大量 XP 时连续提升多级。

例如：

```text
当前等级：1
当前 XP：180
新增 XP：1000
新总 XP：1180
FindLevelForXP(1180) → 3
NumLevelUps = 3 - 1 = 2
```

最终玩家应直接从 1 级升到 3 级。

<a id="section-3"></a>
## 3. 为什么通过 PlayerInterface 访问升级数据

`UAuraAttributeSet` 需要读取 XP、查询等级、发放点数，但这些数据实际保存在 `AAuraPlayerState` 和它引用的 `ULevelUpInfo` 中。

如果 AttributeSet 直接 Cast 到具体 PlayerState，会形成较强的类型依赖：

```text
AttributeSet
  → AuraCharacter
  → AuraPlayerState
  → LevelUpInfo
```

本章继续使用 `IPlayerInterface` 作为边界：

```text
AttributeSet
  → IPlayerInterface
  → AuraCharacter 实现接口
  → AuraCharacter 转发给 PlayerState
```

这样 AttributeSet 只表达“玩家需要完成什么操作”，不需要知道玩家状态具体存在哪里。

同时，只有实现玩家接口的源角色才执行升级。当前项目中的敌人不会升级，因此 `IncomingXP` 分支需要先确认：

```cpp
Props.SourceCharacter->Implements<UPlayerInterface>()
```

课程中还会使用 `ICombatInterface` 查询当前等级，因此也应保证源角色实现对应接口。

<a id="section-4"></a>
## 4. 新增的玩家接口函数

为了让属性集完成升级流程，`IPlayerInterface` 增加了一组查询和修改接口。

### 4.1 查询接口

```cpp
int32 GetXP() const;
int32 FindLevelForXP(int32 InXP) const;
int32 GetAttributePointsReward(int32 Level) const;
int32 GetSpellPointsReward(int32 Level) const;
```

职责分别是：

| 接口 | 数据来源 | 作用 |
|---|---|---|
| `GetXP` | PlayerState.XP | 读取当前累计 XP |
| `FindLevelForXP` | LevelUpInfo | 查询某个累计 XP 对应的等级 |
| `GetAttributePointsReward` | LevelUpInformation | 读取升级属性点奖励 |
| `GetSpellPointsReward` | LevelUpInformation | 读取升级法术点奖励 |

### 4.2 修改接口

```cpp
void AddToPlayerLevel(int32 InPlayerLevel);
void AddToAttributePoints(int32 InAttributePoints);
void AddToSpellPoints(int32 InSpellPoints);
void LevelUp();
```

`AAuraCharacter` 实现这些接口。等级修改已经转发给 `AAuraPlayerState`：

```text
AttributeSet
  → PlayerInterface::AddToPlayerLevel
  → AuraCharacter
  → AuraPlayerState::AddToLevel
```

接口应通过生成的 `Execute_函数名` 调用，尤其是 `BlueprintNativeEvent`：

```cpp
IPlayerInterface::Execute_AddToPlayerLevel(
    Props.SourceCharacter,
    NumLevelUps);
```

不要依赖直接调用 `_Implementation`，否则可能绕过蓝图重写和 UE 的接口派发机制。

本章结束时，`AddToAttributePoints` 和 `AddToSpellPoints` 仍是为后续功能保留的占位实现；调用链已经存在，但暂时不会真正把点数存入 PlayerState。

<a id="section-5"></a>
## 5. 属性集中的升级结算

当 `NumLevelUps > 0` 时，属性集执行升级相关操作：

```text
IncomingXP 分支
  → 计算 CurrentLevel / CurrentXP / NewLevel
  → NumLevelUps = NewLevel - CurrentLevel
  → NumLevelUps > 0
     ├─ 查询 AttributePointsReward
     ├─ 查询 SpellPointsReward
     ├─ AddToPlayerLevel(NumLevelUps)
     ├─ AddToAttributePoints(AttributePointsReward)（当前为占位）
     ├─ AddToSpellPoints(SpellPointsReward)（当前为占位）
     ├─ LevelUp()
     ├─ SetHealth(GetMaxHealth())
     └─ SetMana(GetMaxMana())
  → AddToXP(LocalIncomingXP)
```

需要注意操作顺序：XP 最终仍然要加入 PlayerState。升级判断只是根据“即将拥有的新总 XP”提前计算结果，不能因为发生升级就跳过 `AddToXP`。

### 多级升级奖励边界

`NumLevelUps` 可以大于 1，但如果只读取一次 `CurrentLevel` 对应的奖励，就可能漏掉跨越等级的奖励。更稳健的写法是逐级累计：

```cpp
int32 AttributePointsReward = 0;
int32 SpellPointsReward = 0;

for (int32 Level = CurrentLevel; Level < NewLevel; ++Level)
{
    AttributePointsReward +=
        IPlayerInterface::Execute_GetAttributePointsReward(
            Props.SourceCharacter, Level);

    SpellPointsReward +=
        IPlayerInterface::Execute_GetSpellPointsReward(
            Props.SourceCharacter, Level);
}
```

是否从 `CurrentLevel` 还是 `CurrentLevel + 1` 开始，取决于 DataAsset 的约定：奖励表示“离开当前等级时获得”，还是“达到目标等级时获得”。项目中必须固定一种索引语义并保持一致。

<a id="section-6"></a>
## 6. PlayerState 保存等级，点数暂留接口

`AAuraPlayerState` 继续作为玩家长期进度的权威状态拥有者。本章真正写入的是已有的 `Level` 和 `XP`；属性点与法术点尚未加入 PlayerState。

对应的修改函数采用统一模式：

```cpp
void AAuraPlayerState::AddToLevel(int32 InLevel)
{
    Level += InLevel;
    OnLevelChangedDelegate.Broadcast(Level);
}
```

后续加入属性点和法术点时，应延续 Level 和 XP 的模式：

1. 服务器修改权威值；
2. 属性注册网络复制；
3. `RepNotify` 在远程客户端广播本地委托；
4. WidgetController 订阅委托并转发给 UMG。

服务器上的 C++ Delegate 不会自动跨网络执行。真正跨网络的是复制变量，客户端收到变量后再通过 `OnRep` 启动本地 UI 通知。

<a id="section-7"></a>
## 7. 升级后恢复生命和法力

升级通常会完全恢复生命和法力。本章是在更新玩家等级和奖励之后直接设置：

```cpp
SetHealth(GetMaxHealth());
SetMana(GetMaxMana());
```

顺序很重要：应先修改 Level，让与等级相关的最大属性完成更新，再根据新的 `MaxHealth` 和 `MaxMana` 回满。

如果项目后续把最大属性的更新改为延迟执行或异步 GE，直接设置可能仍读到旧上限。届时可改用 `bTopOffHealth` / `bTopOffMana` 一次性标记，在最大属性真正变化后再回满；当前课程实现不需要先引入这层复杂度。

<a id="section-8"></a>
## 8. 等级变化如何到达 Overlay

PlayerState 已经拥有：

```text
OnLevelChangedDelegate.Broadcast(NewLevel)
```

`UOverlayWidgetController::BindCallbacksToDependencies` 增加订阅，并把值转发为蓝图可绑定的动态多播委托：

```text
AAuraPlayerState::OnLevelChangedDelegate
  → OverlayWidgetController
  → OnPlayerLevelChangedDelegate.Broadcast(NewLevel)
  → WBP_ValueGlobe / WBP_Overlay
```

和 XPBar 一样，等级显示还需要初始广播。否则 Widget 在等级没有发生变化时只能显示设计器默认值。

初始化与运行时更新应形成两条等价路径：

```text
BroadcastInitialValues → 广播当前 Level
OnLevelChangedDelegate → 广播新的 Level
```

这样无论 Widget 是首次创建，还是玩家随后升级，都能得到正确数据。

<a id="section-9"></a>
## 9. WBP_ValueGlobe：显示当前等级

本章复用 `WBP_SpellGlobe` 的外观，创建更简单的 `WBP_ValueGlobe`。它只显示一个整数，不需要技能图标、输入标签和冷却逻辑。

保留的主要组件：

```text
WBP_ValueGlobe
└─ SizeBox
   └─ Overlay
      ├─ Background Image
      ├─ Ring Image
      ├─ Glass Image
      └─ Text_Value
```

删除或停用：

- Spell Icon；
- AbilityInfo 委托绑定；
- InputTag 与 CooldownTag；
- 冷却计时器；
- 与技能状态相关的隐藏逻辑。

保留：

- Box 尺寸更新；
- Ring 和 Glass Brush；
- Background Brush；
- `PreConstruct` 中的设计期预览。

在 `WidgetControllerSet` 中：

```text
Cast to BP_OverlayWidgetController
  → Bind Event to OnPlayerLevelChangedDelegate
  → NewLevel 转换为 Text
  → Text_Value.SetText
```

然后把 `WBP_ValueGlobe` 放入 `WBP_Overlay`，并像其他子 Widget 一样传入同一个 OverlayWidgetController。

背景材质最好复制独立的材质实例，例如 `MI_LevelBackground`。这样可以单独调整颜色、暗度、边缘阴影和噪声速度，不影响技能球使用的背景材质。

<a id="section-10"></a>
## 10. WBP_PictureFrame：角色肖像

本章还创建了一个不参与数据通信的装饰 Widget：`WBP_PictureFrame`。

它复用球形 UI 的 Ring 和 Glass，并把中间内容替换为 Aura 的角色肖像：

```text
WBP_PictureFrame
└─ Overlay
   ├─ Portrait Image
   ├─ Ring Image
   └─ Glass Image
```

这个 Widget 不需要 WidgetController，也不监听任何委托。它只负责 HUD 构图。

这体现了两类 UMG 组件的区别：

- **数据 Widget**：例如等级球，需要 Controller 和委托；
- **装饰 Widget**：例如肖像框，只需要正确的 Brush、锚点和层级。

调整布局时应同时检查锚点、Alignment、Position 和组件宽度。仅复制另一个 Widget 的 Position X，可能因为二者尺寸和 Alignment 不同而无法真正对齐。

<a id="section-11"></a>
## 11. 升级 Niagara 与多人同步

为了让升级更明显，在 Aura Character 上增加 `UNiagaraComponent`：

```cpp
UPROPERTY(VisibleAnywhere)
TObjectPtr<UNiagaraComponent> LevelUpNiagaraComponent;
```

构造时创建组件、附加到角色并关闭自动激活：

```cpp
LevelUpNiagaraComponent =
    CreateDefaultSubobject<UNiagaraComponent>("LevelUpNiagaraComponent");

LevelUpNiagaraComponent->SetupAttachment(GetRootComponent());
LevelUpNiagaraComponent->bAutoActivate = false;
```

升级是在服务器权威流程中确定的。如果只在服务器的 `LevelUp_Implementation` 中激活 Niagara，远程客户端不一定看到表现，因此增加 NetMulticast RPC：

```cpp
UFUNCTION(NetMulticast, Reliable)
void MulticastLevelUpParticles() const;
```

调用链：

```text
服务器确认升级
  → AuraCharacter::LevelUp_Implementation
  → MulticastLevelUpParticles
  → 服务器和所有相关客户端
  → LevelUpNiagaraComponent.Activate(true)
```

`Activate(true)` 会重置系统后重新播放，适合短时间内再次升级。升级是低频且重要的反馈，课程使用 Reliable；如果项目中该效果频率较高，也可以评估 Unreliable，避免可靠 RPC 队列承载纯装饰事件。

<a id="section-12"></a>
## 12. 相机迁移到 C++ 与粒子朝向

升级特效最初会跟随角色方向，而不是稳定面向镜头。为了在 C++ 中取得相机位置，本章把原本只存在于角色蓝图的 Spring Arm 和 Camera 移到 C++：

```cpp
UPROPERTY(VisibleAnywhere)
TObjectPtr<USpringArmComponent> CameraBoom;

UPROPERTY(VisibleAnywhere)
TObjectPtr<UCameraComponent> TopDownCameraComponent;
```

主要配置：

```text
CameraBoom
  → 附加 RootComponent
  → 使用绝对旋转
  → bDoCollisionTest = false

TopDownCameraComponent
  → 附加到 CameraBoom 末端 Socket
  → bUsePawnControlRotation = false
```

迁移后要删除蓝图中旧的 Camera 和 Spring Arm，并把原本附加到旧 Spring Arm 的遮挡检测 Box 重新挂到新的 `CameraBoom`，否则会出现：

- 同时存在两套相机；
- 游戏仍使用旧相机；
- 遮挡 Box 位置或旋转错误；
- WASD 移动时渐隐检测异常。

激活粒子前计算从 Niagara 到相机的方向：

```cpp
const FVector CameraLocation =
    TopDownCameraComponent->GetComponentLocation();

const FVector NiagaraLocation =
    LevelUpNiagaraComponent->GetComponentLocation();

const FRotator ToCameraRotation =
    (CameraLocation - NiagaraLocation).Rotation();

LevelUpNiagaraComponent->SetWorldRotation(ToCameraRotation);
LevelUpNiagaraComponent->Activate(true);
```

方向必须是：

```text
CameraLocation - NiagaraLocation
```

如果减法顺序反了，特效会背对相机。

当前 Niagara 仍附加在角色上，所以播放期间可能继续跟随角色旋转。这是表现选择：如果希望激活瞬间固定在世界中，应改为在世界位置 Spawn System，而不是持续使用附加组件。

<a id="section-13"></a>
## 13. WBP_LevelUpMessage：升级提示

仅让等级球从 1 变成 2 不够醒目，因此本章创建一次性的升级消息 Widget。

建议结构：

```text
WBP_LevelUpMessage
└─ VerticalBox_Message
   ├─ Text：YOU HAVE REACHED
   └─ HorizontalBox
      ├─ Text：Level
      └─ Text_Level
```

`Text_Level` 勾选 `Is Variable`，创建 Widget 后由 Overlay 写入新等级。

Overlay 已经持有 `OverlayWidgetController`，因此可以直接订阅：

```text
OnPlayerLevelChangedDelegate(NewLevel)
  → 当前 LevelUpWidget 是否有效
     ├─ 有效：Remove From Parent
     └─ 无效：继续
  → Create Widget(WBP_LevelUpMessage)
  → Owning Player = WidgetController.PlayerController
  → 保存为 LevelUpWidget
  → Text_Level.SetText(NewLevel)
  → Add To Viewport
```

创建新提示前先移除旧提示，可以避免短时间连续升级时多个消息重叠。

Widget 自己管理生命周期：

```text
Event Construct
  ├─ Play Sound 2D（Level Up Sound）
  ├─ Play Animation（MessageAnimation）
  └─ Delay 3 秒
       → Remove From Parent
```

动画对 `VerticalBox_Message` 制作 Render Transform Scale：

```text
初始：Scale 0
稍后：Scale 1
```

可以在曲线中加入缓入或少量回弹，但不要让 Scale 下降到负数，否则 UI 会发生翻转。声音、Niagara 和 UI 动画应共同调节时间，使三种反馈的高潮尽量落在同一时刻。

这里的 `Play Animation` 播放的是 UMG Widget Animation，不是 Skeletal Mesh 的 `Play Animation`。它可以和声音在 Construct 中同时启动；若要连续播放两段 Widget 动画，应使用动画完成事件，而不是直接把两个播放节点串在一起。

<a id="section-14"></a>
## 14. 常见问题与实现边界

| 问题 | 原因 | 处理方式 |
|---|---|---|
| XP 增加但等级不变 | 只执行了 `AddToXP` | 用新总 XP 查询 NewLevel |
| 一次大量 XP 只升一级 | 使用单次 if 判断 | 使用 `NewLevel - CurrentLevel` |
| 多级升级点数设计不完整 | 只读取一个等级的奖励，且点数接口仍为空 | 后续加入 PlayerState 点数后，按跨越的每一级累计 |
| 升级后没有回满 | 恢复发生在 Level 和 Max 值更新前 | 先更新等级，再设置 Health/Mana 为当前最大值 |
| 主机有粒子，客户端没有 | 只在服务器激活组件 | 由服务器调用 NetMulticast |
| 粒子背对镜头 | 方向向量相减顺序错误 | 使用 Camera - Niagara |
| 粒子随角色旋转 | Niagara Component 附加在角色上 | 接受该表现，或改用世界空间 Spawn |
| 移动后遮挡渐隐异常 | Box 仍挂在被删除的旧 Spring Arm | 重新挂到 C++ CameraBoom 并重置变换 |
| 等级球初始值错误 | 只绑定变化委托 | 在 `BroadcastInitialValues` 广播 Level |
| 客户端等级球不更新 | Level 未复制或 OnRep 未广播 | 检查 DOREPLIFETIME 与 RepNotify |
| 升级消息重复堆叠 | 每次都 Create Widget | 创建前移除旧实例 |
| 消息永久留在屏幕 | Widget 不管理销毁 | Delay 后 `Remove From Parent` |
| Widget 动画发生翻转 | Scale 曲线进入负数 | 将最小 Scale 保持为 0 |

### 当前代码的职责边界

`PostGameplayEffectExecute` 中已经同时处理伤害、XP、升级和资源恢复，函数会逐渐变长。后续可以重构成：

```text
PostGameplayEffectExecute
  ├─ HandleIncomingDamage
  ├─ HandleIncomingXP
  └─ HandleLevelUp
```

这不会改变 GAS 执行时机，只是让每条结算链更容易测试和维护。

<a id="section-15"></a>
## 15. 测试清单

### 升级规则

- [ ] XP 未达到门槛时等级不变；
- [ ] 刚好达到门槛时正确升级；
- [ ] 一次大量 XP 可以连续提升多级；
- [ ] 累计 XP 不会因为升级被清零；
- [ ] 多级升级的目标等级计算正确；
- [ ] 敌人不会进入玩家升级流程。

## 16. 本章核心认识

升级不是简单执行一次 `Level++`，而是一笔由服务器确认的复合事务：

```text
输入：当前 XP + 新增 XP + LevelUpInfo
  → 计算目标等级和跨越等级数
  → 修改 Level / XP，并为 AttributePoints / SpellPoints 准备奖励接口
  → 重新计算派生属性并恢复资源
  → 通过复制和委托更新本地 UI
  → 通过 Multicast 展示共享世界特效
```

其中有三种不同的通信方式：

- **接口**负责在 C++ 系统间表达操作，减少具体类型耦合；
- **复制变量 + RepNotify**负责同步持久状态；
- **NetMulticast**负责广播一次性的世界表现。

等级球和升级消息只展示结果，Niagara 只强化反馈；真正决定等级、奖励和资源恢复的仍然是服务器上的 XP 与属性结算流程。
