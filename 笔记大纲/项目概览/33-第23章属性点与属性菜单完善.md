## 1. 本章完成的功能地图

```text
升级
  → PlayerState.AttributePoints 增加
  → OnAttributePointsChangedDelegate 广播
  → WidgetController 转发
  → AttributeMenu 显示点数并启用加号按钮

点击主要属性加号
  → AttributeMenuWidgetController 校验请求
  → AuraASC::ServerUpgradeAttribute(AttributeTag) RPC
  → 服务器创建 Upgrade Attribute GE
  → SetByCaller 写入要升级的属性 Tag
  → AttributeSet 应用 + 增加
  → PlayerState.AttributePoints 减 1
  → 委托刷新 UI
```

本章解决了两个边界：状态必须由服务器修改；UI 的按钮状态必须随属性点变化，而不是只在打开菜单时设置一次。

<a id="section-2"></a>
## 2. AttributePoints 的状态与委托

`AAuraPlayerState` 增加属性点成员，并使用复制和委托通知变化：

```cpp
UPROPERTY(ReplicatedUsing=OnRep_AttributePoints)
int32 AttributePoints = 0;

DECLARE_MULTICAST_DELEGATE_OneParam(
    FOnPlayerStatChanged, int32 /*Value*/);

FOnPlayerStatChanged OnAttributePointsChangedDelegate;
```

修改函数采用统一模式：

```cpp
void AddToAttributePoints(int32 InPoints)
{
    AttributePoints += InPoints;
    OnAttributePointsChangedDelegate.Broadcast(AttributePoints);
}
```

`OnRep_AttributePoints` 也要广播，确保远程客户端的菜单能够刷新。服务器上的委托不会跨网络传播，真正同步的是复制变量。

`SpellPoints` 使用相同结构，本章先把通信骨架建立好，后续法术菜单会消费它。

<a id="section-3"></a>
## 3. 从 PlayerState 到 AttributeMenu

WidgetController 订阅 PlayerState 的委托，再广播给蓝图：

```text
PlayerState.OnAttributePointsChangedDelegate
  → Overlay/AttributeMenuWidgetController
  → OnAttributePointsChangedDelegate.Broadcast(Value)
  → WBP_AttributeMenu
```

属性菜单每次打开时会重新构造并调用 `BroadcastInitialValues`，因此必须同时处理：

1. 初始广播：从 PlayerState 读取当前点数；
2. 运行时广播：玩家升级或花费点数时推送新值。

不要只在 `Construct` 中读取一次，否则菜单打开后升级不会更新；也不要只依赖运行时委托，否则首次打开可能显示默认值。

<a id="section-4"></a>
## 4. 属性点按钮的启用和禁用

每个 `WBP_TextValueButtonRow` 增加封装函数：

```text
SetButtonEnabled(bool Enabled)
  → 获取内部 Button
  → Button.SetIsEnabled(Enabled)
```

属性菜单收到点数变化时，对所有主要属性行调用：

```text
AttributePoints > 0
  → SetButtonEnabled(true)
AttributePoints == 0
  → SetButtonEnabled(false)
```

按钮的可用状态是表现层反馈，不是安全措施。即使客户端按钮被禁用，服务器仍必须检查玩家是否有足够点数以及属性 Tag 是否有效。

<a id="section-5"></a>
## 5. 服务器权威的属性升级流程

按钮点击后，WidgetController 不直接修改 AttributeSet，而是请求 ASC：

```cpp
UFUNCTION(Server, Reliable)
void ServerUpgradeAttribute(const FGameplayTag& AttributeTag);
```

服务器流程：

```text
ServerUpgradeAttribute(AttributeTag)
  → 检查 AttributeTag 是否属于允许升级的主要属性
  → 检查 PlayerState.AttributePoints > 0
  → 创建 Upgrade Attribute GameplayEffect
  → SetByCaller 设置目标属性 Tag
  → 应用 GE，使目标属性增加
  → PlayerState.AddToAttributePoints(-1)
```

客户端只发送“想升级哪个属性”的意图。属性值和点数扣除都由服务器完成，避免客户端直接写属性造成作弊或状态分歧。

### Tag 驱动的升级效果

同一个 GE 可以服务多个主要属性：

```text
Attribute.Primary.Strength
Attribute.Primary.Intelligence
Attribute.Primary.Resilience
Attribute.Primary.Vigor
```

服务器把被点击的属性 Tag 作为 SetByCaller 的 Key，GE Modifier 再根据该 Key 决定修改哪个属性。这样不需要为每个属性复制一份 GE。

<a id="section-6"></a>
## 6. 升级后回满生命和法力的修复

测试发现升级后生命球和法力球没有完全回满。原因通常不是 UI，而是升级时最大属性的重新计算顺序：如果在最大值更新前就设置当前值，使用的仍可能是旧上限。

本章的直接处理顺序是：

```text
先增加玩家等级
  → 重新计算 MaxHealth / MaxMana
  → SetHealth(GetMaxHealth())
  → SetMana(GetMaxMana())
```

如果未来最大值通过延迟 GE 或异步流程更新，再引入一次性 `bTopOffHealth` / `bTopOffMana` 标记，在最大属性真正变化后回满。当前课程实现保持简单，避免过早增加状态复杂度。

<a id="section-7"></a>
## 7. GameplayEffect SetByCaller 的稳定写法

属性升级使用 SetByCaller 时，必须明确所有可能的属性 Tag。常见错误是只给一个 Tag 分配值，其他 Tag 在 Spec 中不存在，导致执行阶段查询不到值并输出警告。

更稳定的模式是：

```text
创建 Spec
  → 遍历可升级属性 Tag 数组
  → 为目标 Tag 写入升级值
  → 其他 Tag 明确写 0
  → 应用 Spec
```

这样 `ExecCalc` 或 Modifier 查询任意合法 Tag 时都能得到确定值。缺失的 SetByCaller 如果语义上允许为 0，也应在读取端提供默认值；不要把正常的可选缺失全部当成错误。

<a id="section-8"></a>
## 8. 按钮交互反馈与视觉完善

本章最后完善属性菜单的使用感：

- 悬停时播放轻量 UI 音效；
- 点击时播放确认音效；
- 取消默认 Button 的重复点击音效，避免叠加；
- 调整背景、填充、文字和金色强调色；
- 根据点数是否足够显示灰色或高亮状态。

交互声音应放在按钮 Widget 内部，因为它与悬停、按下、取消悬停等控件事件绑定，不属于 GAS 规则层。

<a id="section-9"></a>
## 9. 常见问题与测试清单

| 现象 | 优先检查 |
|---|---|
| 升级后点数不变 | PlayerState 修改函数和 `OnRep` |
| 菜单首次打开显示 0 | `BroadcastInitialValues` 是否广播点数 |
| 升级后按钮不启用 | Controller 是否转发点数委托 |
| 客户端能改属性 | 是否绕过了 Server RPC |
| 点数可重复花费 | 服务器是否检查并扣除点数 |
| 属性升级无效果 | Attribute Tag、SetByCaller Key 和 GE Modifier |
| 出现 SetByCaller 警告 | 是否为合法 Tag 提供默认 0 |
| 升级后生命不满 | 最大值更新与回满顺序 |

- [ ] 无点数时所有加号按钮禁用；
- [ ] 获得点数后按钮立即启用；
- [ ] 每次点击只消耗 1 点；
- [ ] 客户端和服务器最终属性值一致；
- [ ] 重连或重新打开菜单后数值仍正确；
- [ ] Strength、Intelligence、Resilience、Vigor 均能升级；
- [ ] 升级后派生属性和生命法力正确刷新。

<a id="section-10"></a>
## 10. 本章核心认识

属性菜单不是直接操作属性的 UI 面板，而是一个网络请求入口：

```text
按钮表现
  → WidgetController
  → ASC Server RPC
  → GameplayEffect / AttributeSet
  → PlayerState 点数扣除
  → 委托复制回 UI
```

PlayerState 保存玩家进度，ASC 执行权威修改，GameplayTag 选择目标属性，WidgetController 负责通信适配，UMG 只负责显示和输入。
